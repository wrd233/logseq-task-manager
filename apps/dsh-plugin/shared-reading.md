# 共享读法：实现与验收

本轮在 `feature/shared-reading-views` 独立集成分支完成，按 Logseq 协议/状态、DSH 客户端/工具、联动验收三个阶段提交后整体合并 main。原有 DSH 工作台提交一并纳入；不加入外部文件窗口能力。

## 使用

Logseq 保留原有工作台、阅读器、“连续阅读／原结构／Agent 编排”菜单和行首标记语义，只增加当前读法“恢复上一版”。DSH 左侧用一个选择器切换相同读法，对照布局上下排列，Markdown 和行首标记解析复用 Logseq 实现。

两个端口的模式和选中读法属于工作；DSH 轮询当前可见工作的状态，约两秒跟随 Logseq 的选择。每个 DSH 会话绑定仍独立。滚动和折叠保留各端本地状态，文件列表和打开能力没有扩展。

Agent 用 `logseq_reading_list` 获取名称、planId、版本和完整当前布局，用 `logseq_reading_request` 获取新来源，再通过 `logseq_reading_submit` 提交。修改复用 planId，新建使用新 planId。旧请求被并行更新超越后不能覆盖新版本；请求归属仍检查，读取授权不变成正文写入。跨会话选择已有读法允许，因为选择是共享的呈现状态。

Agent 提交期间若用户切到其他读法，结果保存为新版本，返回 `saved`，不夺回选择。更多菜单可恢复上一版，恢复作为新的修订保留当前来源。每个工作保留最多八个读法和各一个上一版。

## 保存与来源变化

Logseq 的 localStorage 中按 Graph、root 和页面类型保存布局元数据及选择，不写 Graph 正文、工作文件或复制正文。当前插件/profile 重启可恢复；没有宣称跨机器或多个 Logseq profile 共享存储。

正文更新后按 sourceId 使用新原句；删除的来源从编排中移除；新增来源统一进入“新增 · 尚未归类”。不自动推断新段落的业务分组。重新核验失败的读法可留在列表，标明需重新整理，不展示旧内容。来源不可读、Graph 切换和材料不可用仍沿用原有处理。任意 HTML/JS 或全新组件不属于本次 Agent 编排能力。

- Logseq 完整测试：556/556，通过；包含原有菜单、101 原文节点、原生编辑/焦点、来源定位、材料、分页与既有写回功能。执行时限制测试文件并发为二，未增加产品防御层。
- 共享控制器 + 阅读 UI：23/23，通过；新覆盖工作持久化、重建、隔离、原句变更、新增/删除、同名更新、上一版恢复、用户导航与并行提交。
- DSH 服务测试：6/6，通过。
- 生产宿主证明：8 组通过；原生 Cordis/Tools/SystemPrompt/AgentLoop + 生产 HTTP companion，Logseq 是合成 SDK，本地脚本模型，不调用远端模型。覆盖两个会话共享选择、同名更新、不打断导航、版本恢复及正文零写入。
- 其余工作区测试：234/234，通过。类型检查、lint、完整构建、依赖边界（12/12）、sandbox（5/5）和 taste eval 通过。
- 原生 DSH 浏览器：已验证“讨论对照”布局、行首属性隐藏、Markdown、读法选择、基础模式及回读；本地工具选择后 DSH 跟随更新。测试使用隔离工作，不代表用户真实 Desktop Graph 已连接。
