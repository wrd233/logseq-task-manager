# 材料模块产品设计

2026-10-02。本轮实现的使用说明与边界；总体需求仍以[工作区协作设计](2026-10-02-workspace-usage-and-interaction-design.md)为准。底层契约见[材料模块架构](../architecture/materials-module-architecture.md)。

2026-10-04 增量：材料列表的“改文件名”已改为实际 basename 操作，默认名称与有证据的当前引用跟随文件名；不再仅改显示标题。拖入、复制、有限外部改名与恢复的当前规则见[增量设计](materials-drop-rename-design.md)。本页其他收纳与编辑边界继续有效。

## 目标与范围

让用户在 Logseq 的一份工作中收纳、找到和阅读材料，需要修改时继续在同一面板编辑，然后返回任务。任务正文留在 Graph；材料正文只有一个权威文件。材料模块独立于 Kernel 在线状态。

本轮包含轻量工作目录绑定、Markdown 收纳与原文件关联、已知目录定位、多个工作关联、阅读与授权编辑、外部冲突保护及原文恢复。PDF、图片等普通文件可关联和外部打开，内嵌界面不声称能读取正文或编辑。

不包含完整 Workspace 服务、任务层级或生命周期重构、原文镜像、阶段审阅与认可、问题聚焦、Git 编排、文件移动监听、全盘搜索、自动语义分类及外部 Agent 服务。主动行动建议保持取消。

## 日常操作路径

### 一份工作中的材料

从块打开工作视图，再点击该视图内的“材料”，进入当前工作的材料列表。列表默认只显示该块的记录关联及当前工作内容中已有的材料引用。“查找全部材料”用于查找当前 Graph 已登记目录中的材料；其他项目不会默认混入当前工作列表。

“目录与查找”中的“工作目录”接受已有目录的绝对路径，一次绑定即可持久使用。普通任务默认平铺；带明确项目标记的工作采用项目目录规则。绑定沿源块祖先就近继承，最多查找 32 层，不读取任务中心内部状态，也不等于正式任务归属。需要改变目录时重新绑定；“解除目录绑定”使之后的新收纳回到全局默认目录。已有材料继续使用原位置。

没有工作目录时使用设置中的 `materialsDirectory`。两者都没有时说明配置要求，保留输入。工作目录不可用时停止创建，不静默回退到全局目录。目录绑定与目录登记保存在插件本地存储；换电脑时需要显式重新登记原材料目录，备份必须包含隐藏的 `.longdoc`。

### 收纳、关联与补关联

- “收纳文本”接受提交的长文本，清洗 HTML 并转换为 Markdown，保存后尝试在工作块下插入引用。
- 命令“工作台：收纳当前块长文本”显式收纳已提交的块，保存后在来源内容仍吻合且没有块编辑时替换为引用。收纳时保留块原文和属性；恢复会恢复当时原块，而非后来编辑过的文件。
- 自动粘贴仍由原有 `materialsAutoCapture` 开关控制，默认关闭，原有阈值和开启状态不变。短文本、代码围栏内文本、Logseq 内部块和带文件的粘贴保留原生行为。引用和必要的原生来源 ID 在同一次原生插入中写入，外部文件不随 Undo 删除。
- “关联文件”可直接输入已有文件路径；“查看目录文件”显式刷新当前工作目录并选择文件，不要求命名、说明或分类。最多显示前 200 项，可通过路径入口指定其他文件。
- 材料“更多”中的“补关联”把同一材料连到当前工作，不复制正文。插入失败时记录关联仍保留，用户可重试；程序返回部分成功、材料身份及真实路径。

新收纳文件使用可读标题作文件名；同名追加短标识。旧 UUID 文件不改名，原文件不搬迁。当前改名入口修改实际 basename；无证据的旧引用文字保持，继续按材料 ID 定位和恢复。

### 阅读、编辑与返回

点击 `longdoc://` 引用先打开阅读页面。主要操作是材料库、外部打开、来源、编辑、返回工作与关闭；改文件名、复制链接、同步名称与引用、补关联、重新定位及恢复原文放在“更多”里。材料列表采用紧凑行，正文在独立阅读区域或已有 Vditor 中显示，不在任务面板默认展开全文。

界面显示标题、原文件或收纳来源、用途及文件位置；ID、hash、目录登记键和权限枚举留在程序结果中。普通阅读不加载编辑器。Markdown 提供“编辑”或“编辑原文件”，这一点击即表达用户编辑意图，不重复确认。编辑后自动保存，Cmd/Ctrl+S 可立即保存。“完成编辑”回到阅读。返回工作使用原工作视图入口，已有布局和来源状态由工作视图负责。

草稿存在时自动恢复到编辑状态；基础版本不符时显示紧凑冲突区域，不覆盖文件或当前草稿。打开别的材料或切换 Graph 时保留未保存草稿，保存操作始终绑定开始时的记录目录和 Graph。当前阅读位置不能改变已打开材料的保存目标。

## 默认用途与编辑边界

文件来源与用途分别表达。`capture` 是模块创建的文件，`reference` 是原文件关联；用途独立为参考、原始输入、工作稿或生成文档。修改显示标题、文件名或目录不会获得编辑授权。

| 场景 | 用户编辑 | Agent 编辑 |
| --- | --- | --- |
| 用户提供的参考文件、原始输入、普通用户收纳 | 默认只读；点击编辑可授权 | 默认不允许 |
| 新工作稿 | 可以编辑 | 需要明确授权 |
| Agent 通过收纳入口生成的文档 | 可以编辑 | 默认可编辑，仍核对版本 |
| 用户点击“允许 agent 编辑此工作稿” | 可以编辑 | 授权当前整个 Markdown 文件 |
| PDF、图片等文件 | 由外部工具处理 | 本接口不提供文件写回 |

目前 Agent 授权粒度是单个完整 Markdown 文件，尚无段落范围授权；Markdown 相对附件定位也未实机验收。按钮之外的存储和程序保存入口也会检查权限、预期正文及基础版本。正文中的 TODO、批注和引用不授予权限。旧 capture 保持此前用户可编辑的兼容行为；旧 reference 默认只读，旧记录均不自动取得 Agent 权限，也不批量补写元数据。

## 保存目录规则

普通 Task 在绑定根目录平铺。项目优先使用既有目录：参考和输入查找 `材料/materials/references`；工作稿查找 `工作记录/notes/work`；生成文档查找 `成果/outputs/output`。没有相应既有结构时，仅实际收纳时创建第一个默认目录。关联原文件的记录存于工作根，不为关联而创建用途目录。用户无需套模板，既有材料不自动迁移。

规则是本轮明确的机械默认值，不能识别任意用户目录的语义。用户可直接把合适的现有子目录绑定为平铺根；项目标记识别及真实多样目录命名仍需日常使用验证。普通任务不会因名称含“项目”就创建层次。

## 冲突、失联与恢复

| 情况 | 实际行为与入口 |
| --- | --- |
| 文件成功，引用失败或编辑位置变化 | 文件、独立记录和关联保留；返回部分成功，材料库可打开并补关联；不会重复创建 |
| 收纳文件或记录确认失败 | pending 独立记录保留原文及待写正文；重试原请求或“继续保存收纳”使用同一身份，不覆盖已有不同正文 |
| 外部修改遇到本地草稿 | 保留草稿和外部文件；另存草稿副本后继续或加载外部版本，副本留在原材料记录目录 |
| 文件丢失或移动 | 保留原关系、原文和历史；用户“重新定位”到明确路径，身份不变，不按同名或 hash 自动认领 |
| 独立记录目录不可读 | 显示不可用；登记原材料目录后按 exact ID 校验；不借当前项目目录替代旧位置 |
| Graph 在异步过程中变化 | 来源写入停止；已开始的文件写入仍向捕获的原目标完成，草稿按 Graph 隔离 |
| 恢复原文 | 按稳定 ID 查找唯一引用，恢复收纳当时原文；外部文件和后来编辑不删除；引用重复或原块已有新增正文时拒绝自动替换 |
| 未完成旧粘贴恢复记录 | 保留原恢复入口；无历史 Graph 字段的记录由用户显式选择恢复到当前目标，不能假称知道旧目录 |

文件历史、收纳原文和本地草稿是不同对象。历史保留每次编辑前的文件；原文恢复保留收纳语义；草稿是用户尚未提交的修改。UI 中“已保存”依赖文件读回，部分失败不会显示完整成功。

## 已实现、待验证与后续

已实现的行为由材料存储、服务与 Happy DOM 面板回归覆盖，连续场景包含 A 收纳、他处打开、编辑、B 切换、A 旧引用、外部冲突、草稿恢复和返回。实际 Desktop 验证及完整检查结果见[整合验证](../integration/VALIDATION.md)中的本轮记录。

待实机专项验证：中文输入法真实候选/提交、系统剪贴板与原生 Undo、真实双 Graph 切换、断电故障、长期使用、其他桌面与 Logseq 版本。本轮不把模拟事件当成这些场景的证明。

后续可接入完整工作区提供方、文件级授权的更细范围及阶段版本消费；材料模块只提供实际版本和修改结果，不自行扩展为阶段系统或任务平台。
