# 工作简报与情境化渲染

> 状态：产品方向草案，允许随着实际实现持续完善。

## 1. 背景与目标

希望进一步发展现有工作视图，使 Logseq 中自然、简洁的工作记录，能够转化为清晰、易读、可交互的前端展示。

核心思路是区分两种表达：

- **原始记录**：服务于正在工作的自己，尽量自然、简洁，不要求提前整理结构，不因为前端展示而增加记录负担。
- **工作简报**：服务于重新进入工作的自己，将原始记录、历史上下文和相关信息重新组织，让人能够快速理解之前发生了什么、当前处于什么状态，以及接下来需要关注什么。

两者使用同一份工作内容，但面向不同的使用场景。

目标不是美化 Markdown，而是降低持续工作和重新进入工作时的认知负担。

## 2. 工作简报

在 Logseq 工作区附近提供一个简报入口。用户主动点击后，出现独立的简报阅览窗口，不改变 Logseq 原有的页面和渲染方式。

简报的主要表现形式是一段**可读性很高的自然语言**：

- 连贯地交代工作背景、进展、困难和重要变化。
- 使用适量的加粗、颜色等方式突出不同语义的信息。
- 不强制使用多个标题和固定栏目，没有内容的部分直接不显示。
- 根据工作的复杂程度决定展示形式。简单工作保持一段话，复杂工作才逐渐增加必要的结构。
- 在需要时提供少量值得关注的事项和后续操作入口。

简报应当像一份简洁的工作说明，而不是传统的任务管理仪表盘。

阅览窗口支持左右切换其他工作简报，并能够查看原始记录、定位来源或恢复到对应工作。

## 3. 情境化渲染

同一份原始工作记录，可以根据用户当前的阅读目的，组织成不同的展示内容。

例如：

- **重新进入工作**：交代上次发生了什么、当前进展和中断位置。
- **了解当前状态**：突出最新变化、未解决问题和需要关注的事项。
- **理解历史问题**：组织相关记录、决策过程和处理经验。
- **准备开始执行**：呈现当前目标、必要材料和下一步建议。

这些是同一份工作内容的不同阅读视角，而不是需要用户分别维护的多份文档。

第一阶段优先做好工作恢复简报，其他情境可以随着实际使用逐步发展。

## 4. Agent 的职责

Agent 可以在用户不被打扰的情况下，持续理解和组织工作记录，并在适当的时候生成或更新简报。

主要职责包括：

- 结合工作区原始记录、历史信息和关联材料理解工作。
- 将零散记录组织成连贯、易读的工作描述。
- 识别重要进展、困难、决策和未解决事项。
- 根据不同阅读目的组织展示内容。
- 保留每项重要信息的原始来源，支持回溯。
- 对信息不足、存在冲突或尚未确认的内容保持谨慎。

需要明确区分用户确认的事实、AI 推断和 AI 建议，不能将推断直接表达为已确认事实。

Agent 可以组织展示内容，但不能因为生成简报而擅自修改 Logseq 原始记录。

## 5. 与 Logseq 和 DSH 的关系

保持现有产品的使用方式：

- **Logseq**：日常自然记录和原始内容编辑入口，尽量不增加额外写作规范。
- **工作简报**：独立的阅读与理解入口，不改变 Logseq 原有渲染。
- **DSH**：面向复杂工作，提供规划、Agent 协作、材料管理和更丰富的交互能力。

DSH 中嵌入的 Logseq 内容应当继续保持与原始 Graph 的联系。用户可以在 DSH 中直接编辑对应内容，并同步回 Logseq，而不是维护另一份独立副本。

工作简报属于阅读投影，不应成为新的权威数据源。

## 6. 设计原则

1. **低负担记录**：不要求用户为了获得好的展示效果而改变原有记录习惯。
2. **原文优先**：Logseq 和原始材料仍然是事实来源，展示内容可以重新组织，但不能替代原文。
3. **渐进式理解**：工作区可以从一句话开始，随着工作推进逐步完善，不要求提前填写完整背景和字段。
4. **简洁优先**：优先自然语言和少量视觉强调，避免过多卡片、标题和空白模块。
5. **按需呈现**：用户主动打开简报，系统不在正常工作过程中频繁打扰。
6. **来源可追溯**：简报中的重要信息能够定位到对应的原始记录。
7. **避免重复维护**：同一份工作内容不应在 Logseq、DSH 和简报之间形成多份需要人工同步的副本。

## 7. 第一阶段建议

先围绕现有工作视图和报告能力，完成一个小而完整的体验：

- 在 Logseq 中增加工作简报入口。
- 点击后打开独立的简报阅览窗口。
- 根据现有工作记录生成一段高质量的自然语言简报。
- 支持少量语义颜色、加粗和必要的后续关注事项。
- 支持简报左右切换。
- 支持查看来源、定位原始 Block 和恢复工作。
- 简报更新不影响 Logseq 原有内容和渲染。

暂时不需要实现完整的多情境系统、复杂关系图或庞大的结构化数据模型。

## 8. 后续演进

随着第一阶段的实际使用，可以逐步探索：

- Agent 静默增量理解和简报更新。
- 不同工作情境下的动态阅读视图。
- 简报与日终复盘、工作断点和工作上下文的结合。
- DSH 中更完整的原生内容编辑与双向同步。
- 更复杂工作中的阶段、材料和对象关系展示。

实现过程中应优先检查现有 Reader、工作视图、报告、来源身份和 DSH 集成能力，尽量在已有架构上演进，避免重复建设。

**本文件只定义产品方向和基本原则，不冻结技术架构、数据结构或具体 UI 细节。允许 Agent 在理解现有代码和实际使用场景后，持续完善本文档，并同步推进实现。**

## 9. 仓库核对与第一阶段收敛（2026-11-15）

基线：远端 `main`，`968ab0e0a5a649a5b53b643516ff6b206220529e`。在 `codex/contextual-work-briefing` 独立工作目录推进，不携带原目录未提交修改。

现有能力及本轮复用：

| 能力 | 当前实现 | 本轮决策 |
| --- | --- | --- |
| 工作识别与导航 | `host/reading-entry.ts`、`work-view/focus.mjs`、`agent-workspace/work-catalog.ts` | 沿用标题识别与已收录页面；不建第二套工作对象 |
| 原文及来源身份 | `workspace/source-protocol.ts`、`workspace.source` | 直接读同一 SourceSnapshot，不写 Graph |
| 全文与原生定位 | `work-view/report-*`、`host/native-source-set.ts` | 原有阅读入口保留；简报可回看原块、恢复工作 |
| Agent 阅读投影 | `ReadingPlanController`、`ReadingViewStore`、`reading.request/submit` | 给已有读法增加可选简报，不建新请求协议或存储服务 |
| DSH Reader | `reader-model.mjs`、`work-experience`、`service.sourceView` | 原文、引用和读法继续复用；简报不替代 Reader |
| DSH 协作 | 现有 `openWork` 与原生输入动作 | 沿用 Agent、会话与只读连接，不增加模型配置 |

首轮交付边界：独立宿主内阅览浮窗（不是新的 Electron 进程），自然语言正文优先，左右浏览当前 Graph 工作，逐段来源，全文回看和恢复入口。Agent 简报作为已有读法的可选字段；每段明确为原文事实、AI 推断或 AI 建议，可加少量进展／关注语义。没有生成结果时显示原文预览与生成入口，不用规则拼接冒充理解。原文变化后旧简报明确显示“原文已更新”，由用户请求 Agent 重写，不把旧摘要自动标成最新。

生成沿用现有 DSH 通道：从阅览器进入对应 DSH 工作，用户在原生输入框发起简报请求，Agent 使用已有 reading 工具提交。尚未接入静默生成、独立后台模型或自动发送。简报当前仅引用本工作原始块；跨工作历史和材料可以辅助理解，但关键结论必须落到可回看的原始记录，不能虚构外部来源。

个人项目按简洁实现推进，不新增防御性编程与自动测试；每轮保留类型／构建和实际阅览检查记录。

### 第一轮实现结果

已接通：工作标题和工具栏的“简报”入口、宿主内独立浮窗、左右工作浏览、自然语言段落和少量强调、逐段来源、当前原文回看、原块定位与恢复工作。无简报工作直接显示原文。生成使用 DSH 工作面板的“写工作简报”，把完整请求追加到原生草稿，用户发送后通过已有 Agent reading 工具返回；不另建模型调用服务。

已有 ReadingPlan 增加可选 `briefing`：来源基准版本、生成时间、自然语言段落与少量关注项。段落只需正文、来源和事实／推断／建议种类，可选进展／关注色彩；不增加工作对象字段。原读法的完整原文布局继续保留。`fact` 表示“有原文依据”，不是自动宣称“用户已确认”。来源变化时只更新原文布局，简报基准版本保持原值以提示过期。

验证：插件类型检查、Logseq 插件构建与 DSH 插件构建通过。浏览器使用真实阅览器、ReadingPlanController 与 ReadingViewStore，配合三件合成工作实际打开；提交简报、自然语言正文、来源展开、左右切换和未生成时原文预览均可用。没有接入日常 Graph 或真实模型，没有宣称远端生成质量已验收。首轮阅览发现：切换后需要保留键盘焦点，后台刷新不应收起用户正在看的来源；第二轮按这些实际结果收敛。
