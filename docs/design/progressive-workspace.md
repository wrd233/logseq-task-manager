# 渐进式工作台：找工作、读写、保持上下文

**2026-11-19 确认方向。** 日常默认进入 Logseq；DSH 既提供后台 Agent 运行能力，也负责复杂前台对话与工具协作。第一轮 [渐进式工作台](../implementation/logseq-progressive-workspace-validation.md) 已保留工作发现、来源版本、原生编辑、焦点恢复与预览构建。后续 `codex/logseq-agent-article-reading` 将读法进一步转成连贯文章与脚注式查证；具体实测范围见 [文章式阅读实施记录](../implementation/logseq-agent-article-reading-validation.md)。

## 三个工作场景

1. **找工作**：工作目录、搜索、手动收录旧笔记，沿用 Graph、页/块 UUID、项目标签和工作标记。恢复阅读现场及上次停点；不用把普通笔记转换为正式 TODO 或项目。
2. **阅读与写作**：原生正文、Journal 和编辑器是真实记录。右侧阅读工作内容，按需展开证据、引用页及材料；宽窗并排、窄窗/覆盖态在阅读与原生编辑间切换。原有未保存草稿、选择、键盘、组合输入由宿主拥有；覆盖态切回阅读前先结束原生输入，避免隐藏还在编辑的正文。
3. **工作上下文**：当前工作 A 不等于当前浏览页 B。打开临时参考页、关闭材料、回原文不自动切换 A；只有目录/搜索/明确进入另一工作选择 B。阅读方案、展开 key、阅读锚点、焦点和停点均按工作身份保存，调整布局或重新生成时尽量恢复。

## 阅读层次

| 用户动作 | 内容 | 实现规则 |
| --- | --- | --- |
| 进入工作 | 原文或上次选定的渐进简报 | 模型非必需，短事项可只有一句，复杂工作按实际需要组织 |
| 点文中有意义的词、短语 | 丰富的描述、判断、过程及条件 | 同篇文章的就近续读；独立展开、轻缩进和细侧线 |
| 点论述附近的脚注 | 原始语句/上下文、实际表与图、材料 | 单一浮窗，不改变文章布局；重要变化就近对照，关闭恢复焦点 |
| 查全部记录 | 当时的完整依据、当前及新记录 | 模型不负责删除未被概括的内容；原文入口始终可用 |

**先是一篇文章，才是可互动的读法。** 顶层只写主线与必要条件，细读不是另一个组件或重复摘要。AI 可选择段落、时间线、条件、方案对照和强调；不要求固定栏目、每段可点击或卡片。渲染器接收语义而非模型 HTML/样式，短语细虚线、正文重点字重、次级缩进表达层次，默认不展示“查看完整原句”“原始 Markdown”、技术 UUID 或哈希。脚注浮窗使用来源名称、真实记录文本与必要版本差异；技术细节或完整记录按需可达。数字、单位、列名来自真实来源表。数据本身若是文章论述主体，可随正文呈现；大表、复杂文件、超出有界摘录的内容通过现有材料服务打开。

## 依据与更新

`ReadingPlan` 保持实际 scope，附理清后的 `briefing`。邀请基于 `SourceSnapshot` 的 sourceId / block UUID、contentVersion、sourceSetVersion 和 structureVersion。生成时保存真实快照和相关材料版本、摘录，旧方案不是最新 sourceSet 的摘要。原文内容或结构变化后当前来源单独读取；受影响单元标示变化，展现当时与当前原文；新增内容另有入口。旧版摘要和历史判断不被隐式改写。

对已有文章，显式整理和获准的后台整理均先保存独立候选。用户主动开启某份工作的「后台准备修订」后，稳定的已保存来源变化触发查证，可关闭或取消；保持当前文章、展开、选区、排版和原生草稿不变。候选就绪只呈现一处更新入口，查看变化并选择采用或暂不采用。采用前再次核对版本及原方案修订，过时结果不覆盖。稳定且不受影响的语义单元尽量原样复用；旧版本及其依据保留为上一修订。每份工作使用现有有限存储，非无限历史归档。

## 轻量 AI 与协作流程

- 原文 → 当前工作或选中文字 → 提问/整理 → 本机 companion → DSH 原生 scoped Agent 读取真实邀请中的工作来源、获准关联笔记与材料 → 提交结构化文章或答案 → Logseq 保存成果或候选。复杂阅读由真正的 Agent 工具循环完成；有充分资料的短事和普通选块润色走轻量模型路径，用户无需另选模式。
- 后台阅读任务独立于用户 DSH 对话；限制工具为邀请索引、精确来源、关联资料及结果提交。来源内容是资料而非指令，不授权 shell、写文件或修改工作。只有生成和查证需要模型，开合、脚注和已保存证据均为本地阅读动作。
- AI 组织和问答不写源、不变更 TODO、工作识别、正式状态。结果允许复制；用户显式插入或确认替换某个仍为同一版本的普通块，原生输入期间不抢占编辑。模型不可用仍保留基础阅读和旧简报。
- 「在 DSH 继续」绑定工作/对应会话，携带真实 sourceId、请求、选段和依据版本。DSH 用户决定是否加入原生对话草稿及发送；复杂工具调用、跨会话、多轮协作沿用 DSH，不在 Logseq 重建聊天系统。
- DSH 也可以通过现有 reading request/submit 组织方案，按同一来源范围校验；简报投影共享、工具授权和模型发送权限分开。

## 验收重点

使用实际隔离 Logseq Graph 和 DSH 配置，保留普通旧笔记、一句话事项和长工作记录；真实读写、引用/材料返回、局部证据变化、重新整理、原生草稿、键盘/宽窄/主题均要独立观察。采用真实配置模型测试最短请求；演示数据不等于实际模型通路。前台日常实例、Graph 和端口不参与验收；在实施记录中注明未证实的平台、输入设备与其他边界。
