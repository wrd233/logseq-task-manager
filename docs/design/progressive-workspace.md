# 渐进式工作台：找工作、读写、保持上下文

**2026-11-19 确认方向。** 日常默认进入 Logseq；DSH 既提供后台 Agent 运行能力，也负责复杂前台对话与工具协作。第一轮 [渐进式工作台](../implementation/logseq-progressive-workspace-validation.md) 已保留工作发现、来源版本、原生编辑、焦点恢复与预览构建。后续 `codex/logseq-agent-article-reading` 将读法进一步转成连贯文章与脚注式查证；具体实测范围见 [文章式阅读实施记录](../implementation/logseq-agent-article-reading-validation.md)。

## 三个工作场景

1. **找工作**：工具栏只有「工作台」，打开后能直接搜索当前笔记库的工作标记、普通页面（包括 Journal）、最近工作及继续上次阅读；收录当前页、调整发现首页偏好在搜索选项。不把普通笔记转换为正式 TODO 或项目。
2. **当前工作**：标题确定工作身份，默认「文章」，「写作」往返原生 Logseq。没有已有文章时直接显示实际原文；没有模型也能读写。宽窗并排、窄窗/覆盖态在阅读与原生编辑间切换；覆盖态切回前先结束原生输入。AI 助手是一个轻量工作面，「在 DSH 继续」是复杂协作主入口。当前工作 A 不等于当前浏览页 B，只有明确选择其他工作才换身份。
3. **阅读与使用材料**：从文章脚注打开原文、真实表、关联笔记或材料；当前工作「材料」优先展示明确关联项，可搜索、加入文件、查看文件的完整预览。返回文章保留展开、锚点和焦点；全部材料从全局「其他」查找，不切换工作。目录管理、重命名/修复等集中到相应选项。

2026-11-20 产品化：不提供「连续阅读／原结构」独立模式，也不提供另一个设计读法对话。旧阅读成果与版本、底层阅读接口保留；非文章的历史编排需要时从「阅读成果与版本」访问。完整当前原文从文章的「查看原文」直接打开；原生块结构仍由 Logseq 呈现，复杂编排、结构分析和历史回顾由 DSH 承担。阶段记录、成果认可、正式任务和写回冲突不等同于文章版本，按需进入，原有行为不删除。

## 阅读层次

| 用户动作 | 内容 | 实现规则 |
| --- | --- | --- |
| 进入工作 | 原文或上次选定的简报 | 数秒内恢复工作所需的最少信息；短事一句、普通一两句、复杂工作少量极短段落 |
| 点文中有意义的词、短语 | 丰富的描述、判断、过程及条件 | 同篇文章的就近续读；独立展开、轻缩进和细侧线 |
| 点论述附近的脚注 | 原始语句/上下文、实际表与图、材料 | 单一浮窗，不改变文章布局；重要变化就近对照，关闭恢复焦点 |
| 查全部记录 | 当时的完整依据、当前及新记录 | 模型不负责删除未被概括的内容；原文入口始终可用 |

**顶层不是全文摘要，而是数秒内恢复工作所需的最少信息。** 不设置固定栏目、强制字数或规定每份普通笔记必须有下一步。只有立即影响理解和当前行动的信息才留在顶层；能下沉且不妨碍初读的内容就放入细读。比如「机房交接还剩 3 台待核验设备。下一步是确认北侧标签差异，再决定交接方式。」历史判断、过程、计数明细、联系人、方案和限制在对应词句展开后阅读。

**文章在细读中生长。** 展开后的内容才是有丰富思路与依据的连贯文章，可以有数百字，并按需组织段落、时间线、方案对照及强调；不重复论述，不为可能误读反复自证。重要事实、限制和未决事项如实表述一次，不用连续的否定、标签解释或提示文字证明文章可靠。渲染器接收语义而非模型 HTML/样式，短语细虚线、正文重点字重、次级缩进表达层次，默认不展示“查看完整原句”“原始 Markdown”、技术 UUID 或哈希。脚注浮窗使用来源名称、真实记录文本与必要版本差异；技术细节或完整记录按需可达。数字、单位、列名来自真实来源表。大表、复杂文件、超出有界摘录的内容通过现有材料服务打开。

## 依据与更新

`ReadingPlan` 保持实际 scope，附理清后的 `briefing`。邀请基于 `SourceSnapshot` 的 sourceId / block UUID、contentVersion、sourceSetVersion 和 structureVersion。生成时保存真实快照和相关材料版本、摘录，旧方案不是最新 sourceSet 的摘要。原文内容或结构变化后当前来源单独读取；受影响单元标示变化，展现当时与当前原文；新增内容另有入口。旧版摘要和历史判断不被隐式改写。

对已有文章，显式整理和获准的后台整理均先保存独立候选。用户主动开启某份工作的「后台准备修订」后，稳定的已保存来源变化触发查证，可关闭或取消；保持当前文章、展开、选区、排版和原生草稿不变。候选就绪只呈现一处更新入口，查看变化并选择采用或暂不采用。采用前再次核对版本及原方案修订，过时结果不覆盖。后台局部修订原样复用不受影响的语义单元；AI 助手内「更新文章／按要求整理」允许按当前编辑策略重新组织文章、将旧版过长顶层下沉，尽量沿用仍适用的语义键，不因版本保留将已收起的旧段落强行并回顶层。旧版本及其依据保留为上一修订。每份工作使用现有有限存储，非无限历史归档。

## 轻量 AI 与协作流程

- 原文 → 打开「AI 助手」，可直接整理文章、输入要求后提问/按要求整理或选普通原块改写 → 本机 companion → DSH 原生 scoped Agent 读取真实邀请中的工作来源、获准关联笔记与材料 → 提交结构化文章或答案 → Logseq 保存成果或候选。复杂阅读由真正的 Agent 工具循环完成；短事和普通选块润色走轻量模型路径，用户无需另选模式。
- 后台阅读任务独立于用户 DSH 对话；限制工具为邀请索引、精确来源、关联资料及结果提交。来源内容是资料而非指令，不授权 shell、写文件或修改工作。只有生成和查证需要模型，开合、脚注和已保存证据均为本地阅读动作。
- AI 组织和问答不写源、不变更 TODO、工作识别、正式状态。结果允许复制；用户显式插入或确认替换某个仍为同一版本的普通块，原生输入期间不抢占编辑。模型不可用仍保留基础阅读和旧简报。
- 「在 DSH 继续」绑定工作/对应会话，携带真实 sourceId、请求、选段和依据版本。DSH 用户决定是否加入原生对话草稿及发送；复杂工具调用、跨会话、多轮协作沿用 DSH，不在 Logseq 重建聊天系统。
- DSH 也可以通过现有 reading request/submit 组织方案，按同一来源范围校验；简报投影共享、工具授权和模型发送权限分开。
- 工作目录、共同指导与项目差异、独立许可、修复入口在工作选项的分组；正常阅读不常驻权限、连接或技术状态。正式任务只在「其他」按需进入；块工作的「阶段记录与确认」保留阶段开始、记录、认可及历史，与「文章版本」分开。

视觉规格：纸张背景、文本/辅助色/单一强调色，标题、正文、注释三个层级；导航及标签明确但不重复，选择态下划线；低频按钮悬停或键盘焦点出现，触屏保留可见入口。菜单、证据浮窗、AI 修订和材料预览共用阅读色板，深色模式跟随真实宿主。详见 [本轮架构](../architecture/logseq-workbench-productization.md) 及 [实机验收](../implementation/logseq-workbench-productization-validation.md)。

## 验收重点

使用实际隔离 Logseq Graph 和 DSH 配置，保留普通旧笔记、一句话事项和长工作记录；真实读写、引用/材料返回、局部证据变化、重新整理、原生草稿、键盘/宽窄/主题均要独立观察。采用真实配置模型测试最短请求；演示数据不等于实际模型通路。前台日常实例、Graph 和端口不参与验收；在实施记录中注明未证实的平台、输入设备与其他边界。
