# 渐进式工作台：找工作、读写、保持上下文

**2026-11-19 确认方向。** 日常默认进入 Logseq，DSH 负责复杂 Agent 对话与工具协作。继承 `codex/logseq-sidebar-reading` 的发现、原生编辑、焦点恢复、主题和构建；选择性继承 `codex/contextual-work-briefing` 的简报与来源逻辑。本文为产品方向及本阶段方案；具体已验收能力以 [实施记录](../implementation/logseq-progressive-workspace-validation.md) 为准。

## 三个工作场景

1. **找工作**：工作目录、搜索、手动收录旧笔记，沿用 Graph、页/块 UUID、项目标签和工作标记。恢复阅读现场及上次停点；不用把普通笔记转换为正式 TODO 或项目。
2. **阅读与写作**：原生正文、Journal 和编辑器是真实记录。右侧阅读工作内容，按需展开证据、引用页及材料；宽窗并排、窄窗/覆盖态在阅读与原生编辑间切换。原有未保存草稿、选择、键盘、组合输入由宿主拥有。
3. **工作上下文**：当前工作 A 不等于当前浏览页 B。打开临时参考页、关闭材料、回原文不自动切换 A；只有目录/搜索/明确进入另一工作选择 B。阅读方案、展开 key、阅读锚点、焦点和停点均按工作身份保存，调整布局或重新生成时尽量恢复。

## 阅读层次

| 用户动作 | 内容 | 实现规则 |
| --- | --- | --- |
| 进入工作 | 原文或上次选定的渐进简报 | 模型非必需，短事项可只有一句，复杂工作按实际需要组织 |
| 点击顶层语句 | 丰富的描述、判断、过程及条件 | 独立展开，允许多个并存；保留事实、推断、建议及关联来源 |
| 点击描述 | 原始语句/上下文、实际表与图、材料 | 来源版本和不确定性可辨；小型证据就近嵌入，完整材料按需打开 |
| 查全部记录 | 当时的完整依据、当前及新记录 | 模型不负责删除未被概括的内容；原文入口始终可用 |

AI 可以组织段落、时间线、条件、方案对照和强调。不要要求每次输出固定项目卡、状态栏或固定栏目。渲染器约束可呈现语义，不接受模型生成 HTML/样式；文字为主，点击提示用低饱和色、下划线和可聚焦按钮，细线、字号和缩进形成层次。数字、单位、列名来自真实来源表而非模型重新填值。材料摘录有界，原文件通过现有材料服务打开；本阶段不构建通用表格或文件解析器，不承诺可回放所有大文件原字节。

## 依据与更新

`ReadingPlan` 保持实际 scope，附理清后的 `briefing`。邀请基于 `SourceSnapshot` 的 sourceId / block UUID、contentVersion、sourceSetVersion 和 structureVersion。生成时保存真实快照和相关材料版本、摘录，旧方案不是最新 sourceSet 的摘要。原文内容或结构变化后当前来源单独读取；受影响单元标示变化，展现当时与当前原文；新增内容另有入口。旧版摘要和历史判断不被隐式改写。

同名方案更新保留上一修订及其快照，语义 key 尽可能不变，展开和阅读锚点据此复用。删除或分拆单元时退回仍可定位的阅读位置。第一阶段使用现有每工作阅读视图存储（有限方案、上一修订），不是无限历史归档；跨设备同步、更久的版本和大文件快照可后续演进。

## 轻量 AI 与协作流程

- 原文 → 正文/选中文字 → 「提问」或「AI 整理」→ 读取工作已保存来源与相关材料 → 本机 companion 调用 DSH 所配置默认模型 → Logseq 呈现答案/提交阅读方案。
- AI 组织和问答不写源、不变更 TODO、工作识别、正式状态。结果允许复制；用户显式插入或确认替换某个仍为同一版本的普通块，原生输入期间不抢占编辑。模型不可用仍保留基础阅读和旧简报。
- 「在 DSH 继续」绑定工作/对应会话，携带真实 sourceId、请求、选段和依据版本。DSH 用户决定是否加入原生对话草稿及发送；复杂工具调用、跨会话、多轮协作沿用 DSH，不在 Logseq 重建聊天系统。
- DSH 也可以通过现有 reading request/submit 组织方案，按同一来源范围校验；简报投影共享、工具授权和模型发送权限分开。

## 验收重点

使用实际隔离 Logseq Graph 和 DSH 配置，保留普通旧笔记、一句话事项和长工作记录；真实读写、引用/材料返回、局部证据变化、重新整理、原生草稿、键盘/宽窄/主题均要独立观察。采用真实配置模型测试最短请求；演示数据不等于实际模型通路。前台日常实例、Graph 和端口不参与验收；在实施记录中注明未证实的平台、输入设备与其他边界。
