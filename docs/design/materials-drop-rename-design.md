# 材料拖入与文件改名

2026-10-04。基于已发布 `e666e7be1367e97dabf5f787c7dcb944ac70e815` 的增量实现，现已[整合最新 main](../integration/materials-drop-rename-main-2026-10-04.md)的报告与正文整理能力。既有收纳、阅读、编辑与恢复见[材料模块设计](materials-module-design.md)；本页的实现、验证与剩余接入见[架构](../architecture/materials-drop-rename-architecture.md)和[交接](../implementation/materials-drop-rename-handoff.md)。

## 目标与范围

用户把已有资料带入当前工作，获得能打开的稳定引用；在材料列表改文件名，或在外部改名后再次打开，都继续使用同一份文件和同一个材料身份。文件正文仍是唯一权威，Logseq 保留用户自然书写的原文。

本轮提供列表拖入、可靠报告块下的引用插入、已有材料拖出、实际剪贴板复制及失败时的可选文本、真正 basename 改名、有限外部改名识别和逐项恢复。没有新增材料数据库、正文编辑器、转换器、全目录监听、全 Graph 引用扫描、Kernel 实体或 agent 改名权限。精确报告段落与原生跨面板拖放留给来源导航端口整合；主动行动建议仍取消。

## 连续操作

1. 从当前工作的“材料”进入列表，直接把已保存文件拖入结果区域。材料立即按原文件关联，名称来自实际文件名的名称部分；不搬动文件、不更改其内容，也不插入 Graph 引用。
2. 一行材料显示名称、来源、用途和简短正文。点击名称阅读 Markdown；其他格式沿用“外部打开”。行末“⋯”提供“复制链接”和“改文件名”，不占用长文阅读区域。
3. 把文件或列表中的已有材料拖到报告的真实正文行。本分支适配 main 的块级映射，落点是**该原文块的子块**，不是鼠标所指的精确字位。只在已授权、来源字节和结构版本匹配、没有原生草稿的当前工作写入。报告小标题、历史、失联行不作为来源。
4. 写入成功后可以点击 `longdoc://` 阅读同一材料，再“返回工作”。读写与草稿保留仍由原材料编辑器和工作视图管理；不会为拖入另建导航。
5. 若文件登记成功而引用未写入，文件和关联留在列表。原行就近出现“复制材料链接”“定位原块继续”“重新核验并补插子块”；不会重复导入文件。未知写入先查询 Journal；已证明未写入的操作才能在新的明确落点重试。

列表拖入只接管列表区域；报告拖入只接管已有正文行。其他原生文件拖动及普通粘贴保持 Logseq 的行为。宿主没有真实 `File.path` 时，列表提供绝对路径关联入口；报告说明先关联或复制链接，不推断路径或静默复制文件。

## 名称与正文分别授权

“改文件名”明确操作真实文件 basename。输入名称时自动保留原扩展名；文件格式、字节、材料 ID、编辑权限和恢复原文保持。遇到已存在名称、非法路径、文件权限问题或未核验的上次文件操作时停止。仅大小写改名受实际宿主目录事实校验。

新收纳／关联的默认名称跟随实际文件名，扩展名在列表及默认引用中省略。重名收纳的短标识属于真实文件名，也进入默认名称。旧 UUID 文件和旧显示标题不批量改写；只有用户明确改名时更改旧文件名。

系统生成且读回验证的引用登记为“跟随文件名”；手写概述、显式修改过的标签以及没有证据的旧引用保留。不能因为文字等于旧文件名就认为可以更新。系统维护只处理已登记、位于当前可信正文范围的引用，不扩大工作授权。历史／阶段快照不追溯改写。

文件改名不授予正文修改权限。原参考和输入材料仍默认只读；用户主动“编辑原文件”沿用已有意图表达。agent 的公开材料入口继续按原权限读取、收纳、关联和保存，不增加改名方法，drag payload 不能携带权限。

## 外部改名与失联

列表刷新或读取材料时，模块核对已关联文件。宿主确实提供设备、inode 与创建时间时，仅在原父目录的直接普通文件中查找相同物理身份；目录超过 200 项、证据不全、多重硬链接、跨目录移动或格式变化，都保留失联关系并提供“重新定位”。相同内容的两个独立文件不会互认。

识别成功更新路径与默认名称，已登记引用在当前可信正文范围内尝试同步。范围之外的旧文字仍凭稳定 ID 打开新位置。没有承诺全面自动跟随任意移动。旧记录没有物理身份时不靠正文 hash 补认；可以显式重新定位建立后续身份事实。

## 部分失败、草稿与恢复

文件、材料 JSON、Graph 引用不是一个事务。操作先保存改名意图，再改文件、读回核验、更新记录，最后同步各处引用。分别展示“文件已改名，部分引用待同步”等结果。实际文件已确认改名时，待同步引用不阻止后续新改名；尚不确定文件结果时先恢复。

重载后通过“更多 → 同步名称与引用”核对旧／新路径和原请求，已完成的文件操作不重放。缺乏物理身份的中断不会认领同内容文件，需明确重新定位。文件已保存而记录更新失败，准备事实仍保留在原独立记录中。

材料编辑、保存、组合输入或未保存草稿会暂停对应文件改名和外部发现。报告来源变化、Graph／工作切换以及晚到导入不写入新的工作。用户改变引用标签后保留别名；复杂位置变化宁可停止管理，不猜测并覆盖正文。

## 已实现与验证边界

- 自动化覆盖真正文件改名／读回、相同内容文件、硬链接歧义、权限和元数据失败、已登记范围批量更新、标签改动、回复丢失、来源保护、重复调用与异步工作切换。
- 隔离 macOS Logseq 0.10.9 已验证 Chromium 文件拖入产生真实路径、列表只关联、报告子块写入及持久 Journal、真实剪贴板复制、真实 basename 改名及稳定 ID 打开。完整结果以交接的最终记录为准。
- 最新 main 的自然 MiniProject 子树识别已通过组合回归：生成引用跟随文件名，已认可阶段历史不变。正式对象、managed 子树、TODO 或当前输入保护仍可能阻止名称同步；此时文件可改名，旧链接仍可打开并显示待同步。整合构建未重新做 Desktop 验收。
- Finder 原生系统 drag、原生任意字位落点、中文 IME、跨 OS 和完整原生 Undo 不标为通过。复制后的原生粘贴只有在两分钟内、同一工作、唯一生成链接且已提交内容读回一致时才登记跟随证据；未证明时保留普通链接。报告块级端口已整合，实际系统粘贴、精确字位与原生跨面板消费仍待验证或接入。
