# 事务／任务与 MiniProject 书写兼容

2026-10-04。共同基线 `e666e7be1367e97dabf5f787c7dcb944ac70e815`。

用户可以继续自然书写：

```text
TODO **[事务]** 核对引用资料
TODO **[任务]** 核对引用资料
**[MiniProject]** 整理一份调研材料 #MiniProject
```

`[事务]` 与 `[任务]` 都是既有 TASK 的书写方式，不增加对象 kind。新建且没有来源写法的 Task 沿用 `[任务]` 默认；有来源的明确正式化、标题／状态操作及规范化保留该根的标签。旧 prefix-first 写法仍可读取，明确规范化时输出 marker-first，保持 Logseq 原生任务识别。

标签识别提供导航标题及保守保护线索。它不创建正式对象、不写 `id::`、不执行 TODO、不授予正文维护或状态权限。只有既有正式化命令、Kernel 身份与受管理 UUID 决定正式身份。普通内部 TODO 和同名嵌套根不随父对象自动纳入。

根的首行承担标题／状态表达，其后的自然正文、属性、链接和局部 TODO 必须保留。用户继续交错写 `[注]`、`[想法]`、`[目标]` 和无标记条件，不需要小标题或固定正文顺序。报告分组由展示模块负责，本分支不生成报告标题或整理原块。

事务／任务和 MiniProject 是块对象，Project、Area 是独立页面。保持既有 Project 绑定与页面导航；不新增 Area Kernel 实体或改变页面组织。

离线不能证明字段归属时沿用保守保护。增加 `[事务]` 语法兼容不扩大正文写回权限，也不放开正式根、受管理子树或普通 TODO。

实机观察：Logseq 0.10.9 的 `updateBlock` 会把属性行移到首行后。本实现传入完整正文，保留自然正文顺序、属性值和 UUID；不承诺该宿主保持属性行原位置。不会为追求字节相同另建文件写入路径。
