# 来源、状态与决策记录规则

## 来源等级

| 标签 | 含义 | 使用规则 |
|---|---|---|
| A — 用户直接表达 | 用户原话、明确修正、原型评语 | 优先级最高；尽量保留原意，不替用户补充没说过的承诺 |
| B — 当前倾向 | 用户在 Grill Me 中选了方案或写了自定义答案，但状态仍为 leaning | 可以作为原型和文档默认，不可标为最终定稿 |
| C — 代码基线 | 前序仓库检查与现有正式文档 | 只能说明固定版本的已知事实；开工时需核对当前代码 |
| D — 设计建议 | 本文档作者提出的交互、数据与实现方案 | 可以被实现团队采用为可逆默认；若改变正式语义或授权边界，需明确确认 |
| U — 未决 | 用户未回答、回答未覆盖的行为、真实宿主尚未验证的能力 | 不得用沉默推断同意；可以通过隔离接口、可逆默认和测试继续推进 |

## 不要把下列状态混用

- **捕获已保存**：记录已可靠写入某个持久位置；不等于同步完成，也不等于形成正式 Task。
- **Inbox 已处理**：这条记录不再需要作为待决定项留在 Inbox；不等于对应工作已完成。
- **已安排投入**：用户计划在某个语义时段做这件事；不等于已投入或已完成。
- **观察到变化**：文件、Git 或 Logseq 来源有变化；不等于变化符合目标。
- **据用户描述已验证**：用户报告做过验证；不等于系统独立观察到验证证据。
- **正式变更已接受**：Kernel 接受并记录正式事实；Graph 投影可能仍待完成。
- **投影完成**：目标 Graph 反映正式事实；不反向决定 Kernel 是否已接受。
- **领航结束**：本次 Agent 连续推进停止；不等于 Project 或 Task 被标记完成。
- **历史恢复草案**：从旧版本挑选出的变更候选；不等于回滚或自动覆盖当前结构。

## 来源冲突时的处理顺序

1. 当前用户明确指令与最新用户原话。
2. 当前仓库源码、正式 API/ADR 与可复现测试。
3. 用户反馈文件中的当前倾向与自定义原型评语。
4. 既有助手总结、早期原型和外部参考。

如果来源不能直接比较，保留冲突并说明原因；不静默折中。

## 本次文档基线的适用范围

独立模块文档是产品需求的维护入口；总览、跨模块设计与待决登记共同约束它们。未逐段标注来源的实现细节视为 D 类设计建议，不能从陈述语气或验收列表推断已被用户接受；明确方向和倾向以待决登记的分类为准，原始依据不可用时保留不确定性。

本轮仅核查 Git 基线、文档输入及文档一致性，不对现有功能做业务验收。C 类描述均是前序研究记录，不能当作本轮证明的当前能力。未来开发须检查相应源码、正式文档和真实宿主；当前用户指令优先于文档里的未来任务安排。

原始输入不随仓库分发，来源类别、摘要校验值与历史版本定位见[来源记录](sources/README.md)。只获得本仓库的 Agent 可依据独立文档理解设计；需要引用用户原话或解决来源争议时，应请用户提供对应本地证据，不得补写结论。
