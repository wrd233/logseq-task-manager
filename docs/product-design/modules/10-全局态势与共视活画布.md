# 模块需求：全局态势与共视活画布

> 状态：产品设计草案（2026-11-21 方向对齐），非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未逐段标定来源的实现细节按 D 类设计建议理解，倾向与未决项均不构成最终定稿。返回[文档导航](../INDEX.md)。

## 1. 目标与定位

在已有「单工作现场（Logseq 阅读写作 + 单工作强边界协作）」之上，补齐**“抬头看路（Zoom-Out）”的全局态势层**：

- 做完一项具体任务后，能够从当前节点**平滑拉远镜头**，直观感知各个长期责任领域（Area）和下属 Mini Projects 的近期动静与潜在可行动点。
- 在同一视野内顺手扫视 Inbox，让零散想法与领域版图产生即时共振，快速决定归属或衍生后续动作。
- 将这一上层态势通过**Agent 无关的协议**共享给任意外部 Agent（Codex / Antigravity / Claude Code / DSH），使人与 Agent 在同一张活画布上**共视、共编、边演进边讲解**，而不是退回纯文本复述背景或维护静态看板。

核心分工原则（A/B 类已确认方向）：**人做导演，Agent 做舞美与参谋**——人在画布上只保留极简高频动作（点击变焦、选中指代、轻拖定方位/安放 Inbox、拍板留删）；结构梳理、冷启动建模、衍生拆解、归类维护与日常更新优先交由接入的 Agent 承担。

## 2. 载体形态：悬浮活舞台（三态呼吸）

独立于单个聊天客户端的**轻量悬浮窗**（A/B 类方向：支持悬浮摆放在 Codex 终端、Antigravity 或 Logseq 旁），避免大面积常驻遮挡：

1. **静默边缘胶囊（Peek）**：收拢于屏幕边缘，仅显示当前锚定的领域/工作名称与极克制的脉搏色点（仅在高匹配 Inbox 或 Agent 刚发出标注时轻提示）。
2. **悬浮伴随画布（Co-Pilot Stage，日常主力态）**：一键呼出或从 Logseq 当前任务“拉远”展开，支持置顶（Always-on-Top）与贴边停靠，与外部 Agent 对话框并排共视。
3. **全景鸟瞰（Full Map）**：阶段复盘或冷启动整理时一键铺开全局，完成后按 `Esc` 收回或平滑落回选中的工作现场。

## 3. 四档语义变焦（Semantic Zoom）与空间记忆

画布采用**语义变焦**而非几何缩放：不同镜头层级呈现不同颗粒度的语义，不做把全部节点与连线一次画满的“毛线球”。

| 镜头层级 | 屏幕主要呈现 | 刻意隐藏 / 弱化 | 核心动作 |
| :--- | :--- | :--- | :--- |
| **L0 全局星区** | 近期活跃的 **Areas** 领地 + 其下带脉搏或可行动色光的核心 **Projects** 缩影；一侧常驻 **Inbox 浮带** | 长期静默且无动静的 Area 退为边缘低饱和“休眠岛”；底层零碎 TODO 隐藏 | 任务收尾后抬头看路；悬停 Inbox 照亮归属；点击任一 Area 推近 |
| **L1 领域切面** | 当前 Area 下属的 **Mini Projects**（含近期变化摘要、等待/卡点状态）；邻近 Area 柔和虚化为边缘坐标 | 无关领域的子项隐藏；右侧 Inbox 浮带自动把本领域共振条目上浮置顶 | 观察领域近期推进与停滞；就近收编相关 Inbox 线索 |
| **L2 事务结构** | 当前 Project / MiniProject 的下属任务树、关键依赖、阶段目标与近期变化 | 其他项目收束为顶栏路径/边缘幽灵锚点 | **人机共编黄金层**：就当前画面提问，观看 Agent 生长虚态衍生分支并拍板 |
| **L3 执行入口** | 单项工作停点与简报摘要 + 显式出口：「回到 Logseq 原文现场」/「带此单工作深入协作」 | 不在悬浮画布内重造富文本大纲或文档编辑器 | 选定下一步后无缝回到 Logseq 安静笔记本或单工作协作流 |

**空间记忆规则（D 类设计建议）**：
- L0 全局星图中，各 Area 拥有稳定的默认方位，支持用户手工拖拽一次定下“老家坐标”，避免每次重排导致地图感丢失。
- L1/L2 展开后的下属结构由确定性防重叠布局自动排布；新增或调整节点时周边节点通过平滑位移动画（FLIP）让位，不依赖大模型计算原始像素坐标。

## 4. Inbox 双向共振浮带

用户倾向采用**常驻侧边浮带（场景 A）**与画布实时共振：

- **正向共振（点/悬停 Inbox → 照亮画布）**：在浮带中悬停或点击某条 Inbox 记录时，画布上最可能相关的 1–2 个 Area / Project 即时亮起暖琥珀光并出现淡预览弧线。用户可直接把该条 Inbox 拖入亮起的节点，或保持选中态向旁边的 Agent 提问“这条放哪合适 / 要不要拆任务”。
- **反向共振（聚焦 Area → 浮带上浮匹配项）**：镜头推近到某个 Area（L1）或 Project（L2）时，浮带自动将与之相关的 Inbox 条目上浮置顶并微亮提示，其余条目降对比度保留可滚动。
- **0 延迟与隐私护栏（对齐 D-41 / D-42）**：悬停/点击触发的瞬时亮灯必须由本机 Companion 基于轻量本地索引/特征匹配完成（目标 `< 30ms`，不触发云端大模型调用）；仅在用户主动与外部 Agent 对话深度研判时才进入模型推理。

## 5. 冷启动初始星图与「防乱护栏」

用户希望初始 Area 版图由 **Agent 读取现有项目与近期笔记后在画布上以虚态生成**，同时明确要求**“不要太乱”**（A/B 类方向）。为此设立硬约束：

1. **顶层数量封顶**：初始建议严格控制在 **4–7 个核心 Area**，按长期责任域划分，禁止为单次任务或细碎标签建 Area。
2. **先聚骨架、散沙不硬塞**：优先依据现有正式 `Project / MiniProject`、高频活跃页面与工作目录聚合骨架；零散一次性笔记统一留在边缘的「未归类 / 暂放」池中，宁缺毋滥。
3. **可核查的虚态初稿**：冷启动结果先全部落于虚态层，每块虚态 Area 直接展示最具代表性的 2–3 个下属项目/页面名称，便于用户在数十秒内判断划分是否合理。
4. **低摩擦微调后凝固**：支持在画布上拖拽合并相似 Area、点掉多余块，或在对话中口头指令调整；确认后一键“由虚化实”凝固为稳定骨架。

## 6. 视觉语言与「可行动色光」编码

延续 [09-视觉与主题.md](09-视觉与主题.md) 与 D-35 的安静笔记本美学，颜色必须低饱和、克制，且配极简语义标记（不单一依赖颜色）：

- **暖琥珀（Inbox 共振）**：Inbox 中存在与该领域/项目高度匹配的待归位线索。
- **清透青绿（可顺手推进 / 卡点松动）**：等待条件有新动静、前置任务刚完成或存在低启动成本的下一步。
- **低饱和冷灰（静默待决策）**：仍处于开启状态但超过阈值无真实进展，且未被用户标记为主动搁置。
- **微光虚线蓝（Agent 现场推演态）**：当前对话中 Agent 正在画布上展示的候选分支、归属预览或见解便签。

禁止在画布上显示虚构的“项目健康分数”“完成率百分比”或强制排优先级红点。

## 7. 人机共编协议、三层权限与动画礼仪

吸收社区在共享画布与视口控制上的实践教训，并与既有治理原则（[01-产品总览.md](../01-产品总览.md) 原则三、原则五、原则七）严格对齐，将画布操作划分为**三层互不混用的边界**：

### 7.1 三层操作边界

1. **共视与提示层（Presence / Gaze —— 只读与瞬态）**
   - 画布实时将 `ViewportState`（当前镜头层级、聚焦节点、可见邻域、选中节点、选中 Inbox 条目）同步至本机 Companion。
   - Agent 可读取当前视口，在聚焦节点旁呈现极克制的存在感微标（如 `Codex 正在看这里`），或对视野内节点做短暂高亮与贴折叠便签。
   - **不抢方向盘原则**：目标在当前视野之外时，禁止 Agent 粗暴拉走用户镜头，而是于画布边缘浮出方向雷达提示（如 `↗ 某领域 · 2 条线索`），由用户点击滑过去（用户明确要求“拉远看全局”除外）。
   - 本层操作不脏数据、不进入业务撤销栈。

2. **虚态推演层（Ghost / Staging —— 沙盘共编）**
   - 当用户在对话中提问（如“最近这个东西能不能衍生出一些任务？”），Agent 通过舞台原语在对应节点旁**错峰播放生长动画**，长出半透明虚线态（Ghost）分支、归属预览弧线或初始星图，并在对话框中同步讲解理由。
   - 所有虚态对象仅驻留在 Companion 的轻量会话推演缓冲中，**绝不冒充正式任务或写入 Logseq 原文**。
   - 悬浮窗底边安静浮现**「本轮变更胶囊」**（汇总本轮 Agent 提议项，支持悬停联动高亮、一键全部留下 / 逐个审 / 全部散去）。

3. **正式落盘层（Committed —— 虚实转换）**
   - 用户在画布上点选 `✓ 留下 / × 散去`，或在对话框中明确拍板（如“前两条留下，第三条去掉”）。
   - 被认可的虚态对象播放短促的**“由虚化实”凝固动画**后落盘：
     - **轻量运营态**（Area 语义映射、固定坐标、主动搁置标记、Inbox 队列状态）写入 Companion 本地轻量存储，提供单步 Undo；
     - **正式结构变更**（新建/重命名/改归属正式 `Project / MiniProject / Task`）走既有 Formal Kernel 唯一权威通道；
     - **Logseq 正文修改**继续走 D-45 / D-46 既有原文整理/写回提案通道。

### 7.2 与现有 Companion MCP 的并行对齐（D 类协议草案）

现有 `apps/task-copilot-cli/src/mcp-handler.ts` 已提供 6 个单工作强边界工具（`workbench_*`），负责单工作正文/材料读取与阅读/写回提案提交。全局活舞台在**不放松单工作强边界**的前提下，由同一本机 Companion 并行暴露一组极窄的 `stage_*` 原语：

| 分层 | 建议原语名称 | 语义说明 | 影响范围 |
| :--- | :--- | :--- | :--- |
| 共视 | `stage_get_view` | 读取当前镜头层级、聚焦对象、视野邻域、选中节点与选中 Inbox | 只读（宽而浅，不吐项目私有文件全文） |
| 共视 | `stage_get_pulse` | 拉取各 Area/Project 活跃脉搏、静默时长、可行动线索与 Inbox 列表 | 只读 |
| 提示 | `stage_highlight` | 点亮视野内目标并附短理由；视野外目标自动降级为边缘方向雷达 | 瞬态 UI |
| 提示 | `stage_annotate` | 在节点旁附加可折叠的 Agent 见解便签 | 瞬态 UI |
| 推演 | `stage_propose_areas` | 冷启动或重构时在画布生成受控（4–7 块）虚态 Area 星图 | 虚态缓冲 |
| 推演 | `stage_sprout_branches` | 在父节点下带生长动画衍生若干虚态子任务/阶段分支（可带 Inbox 来源线） | 虚态缓冲 |
| 推演 | `stage_propose_move` | 以虚线弧预览某项目或 Inbox 的目标归属迁移 | 虚态缓冲 |
| 落盘 | `stage_resolve_proposals` | 依据用户确认结果提交或放弃指定虚态提案，触发凝固或淡出动画 | 受控落盘（区分运营态与正式 Kernel 通道） |

## 8. 最小数据边界与不混用的状态

- **不新建平行正式任务库**：Formal Kernel 继续仅维护 `Project / MiniProject / Task` 基线，不因引入 Area 强行膨胀 Kernel schema；`Area` 作为 Companion 维护的轻量语义映射层引用 `WorkRef` 与普通 Logseq 页面。
- **脉搏自然冒泡，拒绝手工填报**：活跃度与近期进展由底层真实事件（任务完成、Logseq 页面更新、Inbox 新增、已有证据记录）自动聚合，辅以用户显式标记的“主动搁置”意图，避免把主动暂停误判为遗忘。
- **严格区分的状态**：
  - `虚态衍生分支` ≠ `已创建正式任务`；
  - `Area 轻量归属映射` ≠ `Formal Kernel 正式父子关系`；
  - `Inbox 已归入领域` ≠ `对应工作已完成`；
  - `Agent 视野内高亮/批注` ≠ `文档已被修改`。

## 9. 验收标准（目标基线）

1. 用户可从当前任务平滑拉远到 L0 全局星区，仅展示活跃 Area/Project 与可行动色光，点击任意节点丝滑聚焦至 L1/L2，按 `Esc` 或返回键无损回退。
2. 悬浮窗支持胶囊态 / 悬浮伴随态 / 全景态切换，置顶并排于 Codex 或 Antigravity 旁时不阻塞主操作。
3. 悬停或选中侧边 Inbox 浮带条目时，画布相关 Area/Project 在本地即时亮灯（不触发云端模型调用），支持拖拽安放或直接口头交由 Agent 处理；聚焦某 Area 时浮带自动上浮相关条目。
4. 冷启动由 Agent 虚态生成 4–7 个主 Area + 边缘暂放池，展示代表项目依据，允许合并/删改后一键凝固。
5. 任意接入 Companion MCP 的 Agent 可读取当前视口（共视），并在画布上以错峰动画长出虚态分支、贴批注或发边缘雷达；视野外不抢夺用户镜头。
6. 底部变更胶囊清晰汇总本轮 Agent 提议；用户画布点选或对话拍板后，虚态播放由虚化实动画并按既有权威通道落盘，取消或失败绝不播放成功凝固动画。
7. 系统减少动效设置生效时平滑降级；画布或悬浮壳不可用时可回退为紧凑文字目录与提案清单。

## 10. 待明确（U 类未决边界）

1. **脉搏与静默阈值**：默认以 7 天还是 14 天界定“近期活跃”与“悄悄变冷”；哪些底层信号（Logseq 编辑、Formal Commit、Git 改动）纳入默认冒泡权重。
2. **多 Agent 并发存在感与冲突**：当 Codex 与 Antigravity 同时连接同一 Companion Stage 时，各自虚态提案是否按 Agent 来源分色/分组显示，冲突归属以哪次用户确认优先。
3. **悬浮窗壳体首版选型**：Phase 1 先以本机 Companion 托管的无框浏览器/App 模式窗口验证，还是直接包一层极薄的 macOS 置顶壳（Tauri / Electron）以支持全局快捷键与多桌面跟随。
4. **与 D-05 / D-09 的协同**：当 Inbox 归入领域或虚态分支凝固为正式 `Task / MiniProject` 时，跨宿主（外部终端 Codex vs 可信 Logseq 插件渠道）的正式授权确认路径需与既有未决边界 #4 统一收口。
