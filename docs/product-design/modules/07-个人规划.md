# 模块需求：个人规划与语义时段

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 目标

帮助用户把工作放入熟悉的一天节奏，而不是建立精确计时系统。规划应在 DSH 对话中自然发生，用户能看见安排如何变化，并通过拖动进行简单调整。

## 基本单位

一次投入意向：某个 WorkRef 或工作意图，在某个语义时段中投入。它可以引用 Project，即使尚未拆成 Task；也可以重复、取消或只完成一部分。安排不等于正式任务，也不代表工作已经发生。

## 主要交互

- 默认展示今天与明天；整周视图按需展开。
- 语义时段由用户定义并排序，可有工作日/休息日不同模板。
- 与 DSH 交流安排时，旁边同步显示轻量日程；拖动优先，不用下拉框作为主要排程方式。
- 拖动时给出清楚的落点预览与轻动画；放手后可撤销。
- 未完成安排留在原处，并给“换个时段”入口；不自动挪到下一格。
- 部分完成时，本次投入可结束并留下继续入口；需要继续时再安排一次。
- 临时只有十分钟时，用户主动触发“现在只有一会儿”，系统在用户关注范围内找适合停下的小动作，不自动重新排列全部计划。
- 固定会议或硬截止由用户手动标记；第一版不自动写外部日历。

## 与 Inbox 的关系

当 Inbox 条目只是“决定何时投入”时，安排完成后可以从待处理队列移出，并提供去日程的链接。实际工作仍未完成；若安排取消，不自动把它标成未完成 Task，也不必机械地把条目重新塞回 Inbox。

## 与 Agent 领航的关系

计划是用户的投入意向；领航是用户在限定范围与停点内交给 Agent 的连续推进方式。领航可以参考日程，但不能因进入某时段就扩大工具权限或自动修改正式状态。

## 验收标准

1. 可以给 Project 直接安排“澄清范围”，无需创建占位 Task。
2. 今天/明天是默认视图，整周可按需打开。
3. 用户可以在 DSH 交流过程中看到计划变化并拖动调整。
4. 未完成项不自动移动；部分完成可留继续入口。
5. 工作日/休息日模板变化后，无法映射的安排进入“待安置”，由用户选择。
6. 固定会议和截止可以手动标注；没有外部日历写入。
7. 拖动只修改内部投入安排，不改变正式任务状态。
