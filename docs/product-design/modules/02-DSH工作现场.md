# 模块需求：DSH 工作现场与材料阅读

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 目标

让 DSH 原生对话继续成为中心，同时让用户能随时查看 Logseq 原文、相关文件和工作身份。插件应该补上 DSH 目前缺少的工作连续性，而不是重做聊天、终端或 IDE。

## 主要场景

### 进入一个工作

用户从工作目录选择某个项目的“继续工作”时，默认打开与该工作身份对应的最近有效会话。旁边提供可读的会话切换入口，允许选择另一段调查或实现会话。会话身份不能只靠 cwd 判断：同一个项目可能有多条 DSH session，同一 cwd 也可能对应不同工作。

### 阅读原文而不离开对话

- 短原文可使用覆盖层或右侧阅读层。
- 长时间对照时可以固定阅读层并拖动宽度；本次工作中记住宽度，关闭后恢复聊天空间。
- 阅读区可以展示 Logseq block、Markdown 文件和来源版本；短列表显示文件名、类型与变更线索，完整路径按需展开。
- 浏览另一个项目的原文只改变阅读区，不自动改变当前 DSH session、执行目录或模型权限。

### 工具结果与差异

Diff 的入口应贴近产生变化的工具结果，而不是每条聊天消息都插入大型提案卡。用户点开后，才进入独立、可读的差异审阅。一次改动很多文件时，先显示变化摘要和文件列表，再按需展开具体内容。

## 工作身份、会话与目录

以下概念必须分开：

- 当前浏览的 WorkRef。
- 当前 DSH session 与其关联的工作身份。
- 当前执行目录（cwd）。
- 当前授权的读取范围与写入范围。
- 当前被发送给模型的上下文材料。

用户可以在工作 A 的会话中阅读工作 B 的原文，但这不应该自动将 Agent 执行目录切换到 B。真正切换工作时，应明确显示工作身份和目录，并在不一致时提供受控修复。

## 数据与状态

`WorkSessionBinding` 是概念：将稳定工作身份关联到一个或多个 DSH 会话，并记录上次用途/有效性。`ReturnContext` 保存原会话、输入草稿、选中来源、滚动/折叠位置等最小返回状态。它们可以由现有 feature 结构演进而来，不应在没有核查的情况下重新造一套会话注册系统。

## 异常处理

- 会话失效：显示旧会话不可用，提供“用这些材料开新对话”，不装作继续了旧会话。
- Bridge 失联：保留标注时间/版本的阅读副本；不可将过期缓存显示为实时状态，也不可用它作为正式写入依据。
- cwd 不匹配：执行前提示具体工作路径；不默默 `cd` 到另一个目录。
- 插槽不可用或 SDK 升级：退回独立阅读视图或紧凑列表；不能为保住布局而破坏原生对话。

## 验收标准

1. DSH 原生对话仍是主界面，插件默认只增加极短工作入口。
2. 短阅读层和长对照布局都可用；关闭后恢复聊天布局。
3. 浏览 B 不会悄悄重绑 A 的会话或改变 cwd。
4. 当前工作身份、session 与 cwd 可被用户理解地核查。
5. 文件列表紧凑，路径/版本在需要时可查看。
6. 断连和过期材料有明确状态；离线阅读不冒充权威实时结果。
7. 宿主真实 API/slots、版本和焦点行为经 DSH 实际环境验证。
