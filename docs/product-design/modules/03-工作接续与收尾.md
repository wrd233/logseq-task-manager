# 模块需求：工作接续、暂停与收尾

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 目标

用户重新进入工作时，不必阅读一篇 AI 总结才能找回上下文；临时被打断时不被表单拦住；主动结束一轮工作时，可以看见真实成果、结构变化、遗留点和下次入口。

## 恢复体验

恢复入口默认以 DSH 对话顶部的一条轻入口出现。用户点开后进入短时专注层；不是每次打开项目就占满屏幕。

核心内容以共享结构图呈现：

- 上一步正在处理的节点高亮。
- 离开后相关结构发生的变化，以第二种低饱和颜色或局部动画标记。
- 可能的下一步以另一种视觉状态表示，但必须标明它是建议而不是已经安排的工作。
- 图旁提供简短可读说明、来源入口和“继续上次对话”。
- 不相关的 Git 变化不必全部展示；详细历史进入独立历史视图。

若停点已失效，不能继续显示一个看似有效的主按钮。应说明原位置为何不可用，并提供当前结构、可用来源和重新定位/开新会话入口。

## 暂停与结束的区别

### 暂停 / 中断

- 可以立即退出，不要求写停点说明。
- 自动保留可保存的草稿、当前工作身份、选中对象和来源位置。
- 可选地让用户补一句“我正在解决什么”。
- 结构图高亮当前工作位置，方便用户在全局中知道自己停在哪里。
- 暂停不等于结束，也不等于正式完成任何 Task。

### 结束本轮工作

- 展示本轮真实结构变化：节点新增/移动/修改、依赖变化、已有材料与结果。
- 列出仍未解决的事项与下次可打开的入口。
- 允许用户补一段评价或意图说明；不强制填写。
- 可选择是否把短记录与来源链接写入当天 Journal。
- 可以显示轻量的结构变化动画，但不能用动画代替实际证据和保存收据。
- 结束本轮 DSH 领航不自动把 Project/Task 标记为完成。

## Handoff 与来源变化

Handoff 不是每次关闭会话的必填报告。它可以在显著中断或用户明确收尾时生成，至少保留：当前意图（如果已知）、可打开的来源位置、未解决问题（如果有）以及来源版本/观察时间。界面不应出现“观察水位”等内部术语。

如果来源后来发生变化，旧 Handoff 仍可阅读，但应显示相关来源已变化、需要重新核对。不能静默改写旧内容，使历史看起来像当时就知道后来的事情。

## 验收标准

1. 恢复首屏先提供上次工作位置和继续入口，不先生成长摘要。
2. 同一结构图能高亮上一步工作与相关后续变化。
3. 暂停不要求用户填写内容，且保留可恢复现场。
4. 结束本轮展示真实结构变化、遗留点、下一次入口，并允许用户评价。
5. 失效会话/来源提供明确降级路线。
6. 不把暂停、结束领航和正式完成工作混为一个状态。
7. Journal 写入是明确的可选结果，且不复制完整工具日志。

## 待明确

- 恢复图上下一步提示是仅基于现有证据的候选，还是允许 Agent 结合当前对话生成。
- 收尾是否在第一版就写入结构化回顾，还是先保留轻量文字与引用。
