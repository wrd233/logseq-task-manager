# 模块需求：Attention Lens 与有限领航

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## A. Attention Lens

### 目标

让 AI 在用户正在使用的 DSH 对话中提供有依据的线索，而不是把用户带到一个独立的分析仪表盘。线索应“夹在”会话上下文里，标题自然可读，相关项目/对象名词用低饱和度加粗区分，其他结构保持克制。

### 触发与展示

- 用户提出问题或选择一个常用视角后分析。
- 少量明确的硬条件可轻提示；不做后台持续分析并不断插入建议。
- 默认保留当前列表/结构顺序，提供“只看命中”开关，而不是自动重排项目。
- 每条线索先显示一句可理解的描述、来源入口和已知/未覆盖条件；点开后才展示更多依据。
- 用户说“已解决”时先移除当前高亮，可选记下已收到答复；不要自动删除来源或改正式状态。
- 允许零条线索。分析失败不能显示成“没有问题”。
- 相同缺口可合并提醒身份，并允许用户停止此类重复提示；抑制提醒是可逆 UI 偏好，不改变正式事实。

### 与 DSH 的交互

当扫描发现材料不足时，Agent 应根据本次观察的具体缺口，在 DSH 中提出少量动态问题。问题不是固定问卷，也不应复制成一个独立下拉面板。例如，系统已看见代码与文档变化，但不知道改动动机时，可以问这次主要想解决什么；若用户只是中断，继续入口可能比问动机更重要。

### 验收

线索可追溯、可关闭、不会凭空打分、不会默认重排；用户可在 DSH 中继续讨论，不需离开对话。无证据或分析失败与“没有发现”严格区分。

## B. 有限领航

### 目标

用户可以明确交出一段工作范围和时间/停点，让 DSH 在范围内连续推进，但不扩大既有工具授权，也不无限期自治。

### 开始

- 用户选择本轮工作范围与最晚结束时间/停点。
- 复用同一结构图高亮本轮目标节点，轻动画说明本轮聚焦对象。
- 帮助准备正确的 DSH 会话、工作目录和必要来源；执行前核对工作身份与 cwd 一致。
- 不要求用户选择僵硬的“澄清/拆解/执行”模式；默认自由协作，需要专项工具时再打开。

### 运行

- 机器可执行且在范围内的小步骤可以连续进行。
- 需要人类判断的动作停下来，等用户点“继续”。
- 用户可以直接换下一项，不必解释理由；系统不自动把一次换项推断成永久偏好。
- 新想法先进入 Inbox，不自动插队改变当前领航顺序。
- 每阶段可以通过结构图局部高亮和轻动画表达开始/完成，但动画只对应真实状态。

### 暂停、恢复与结束

- 暂停立即停止后续派发，保留现场和草稿；隔天恢复时，先恢复现场并短确认新的范围/停点，再继续自动推进。
- “停一下”与“结束这次领航”不同；在途操作的结果仍要查询。
- 结束后展示本轮结构变化、成果、遗留点与下一次入口；用户可评价，并自行决定是否写 Journal 或改变正式状态。
- 领航结束不会自动完成 Project/Task。

### 验收

1. 开始前有明确范围和停点；不能靠聊天记忆推断当前项目。
2. 不扩大 DSH 原有文件/工具权限。
3. 人类决策点会停住，机器小步骤可以在授权范围内继续。
4. 新想法不自动打乱当前计划。
5. 暂停/结束/正式完成是不同语义。
6. 结束时结构图与记录基于真实变化；不能把建议当成已执行结果。
