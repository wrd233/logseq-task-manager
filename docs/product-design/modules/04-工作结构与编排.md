# 模块需求：工作结构与编排

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 目标

让用户在多个项目与任务之间保持清晰的工作结构，但不把日常体验变成仪表盘。默认是高信息密度、可搜索、可展开的文字目录；结构图在拆解、依赖分析、变更预览和历史回顾时按需打开。

## 默认工作目录

- 进入后优先恢复上次关注范围，并提供清楚的“全部工作”入口。
- 用户可以建立临时工作集，如“这周关注”“等待决定”；同一 WorkRef 可以出现在多个工作集中。
- 工作集、排序、展开状态和图上位置都是视图/运营状态，不改变正式父级。
- 一行优先显示：可读名称、明确已知的阻塞/新变化、可直接继续的入口。不要显示虚构的进度百分比、价值分或健康分数。
- 同名任务通过上级路径、来源短描述或上下文区分，不把内部编码暴露在日常界面。

## 结构图

结构图主要表达正式父子关系和明确依赖。聊天提及、来源链接和其他关系可以作为可切换图层，不应全部默认画出。

- 选中列表中的对象后，切到图上聚焦同一个对象；反向亦然。
- 普通拖动只改变布局位置。
- 若用户要改变正式归属，可以把节点拖到新上级；松手后出现短确认/差异预览，说明原上级、新上级和受影响关系。
- 新拆解先作为候选草稿。用户只选择其中部分节点正式创建，未选中的仍留在候选区或被明确丢弃。
- 新对象、归属变化和正式依赖必须通过唯一正式写入路径，不因画布动作直接写 Kernel。

## Decision Routing

当 Inbox 记录需要修改结构时，不在 Inbox 内塞进完整画布。系统打开合适的结构视图，聚焦目标并保留原来源和返回点。完成后返回原 Inbox 条目；若变更冲突，条目仍保留待处理，候选与评论不丢失。

## 验收标准

1. 默认目录支持搜索、展开、恢复关注范围与查看全部工作。
2. 工作集不会复制正式对象或更改正式归属。
3. 列表和图共享稳定 WorkRef 与选中状态。
4. 布局拖动与正式归属修改明显不同。
5. 候选拆解可以部分接受，并在正式写入前检查必要的父子/依赖约束。
6. 图上节点名称可读；内部 ID 只在诊断详情出现。
7. 大图按需加载，只展示当前工作及邻域；图形不可用时可退回目录和差异清单。

## 待明确

- 对依赖变更，默认展示多大邻域；建议只显示直接相关对象，用户可展开一层。
- 正式父级变化是松手后短确认还是始终先打开完整 Diff；建议低风险单节点用短确认，多节点或有依赖影响时展开 Diff。
