# 模块需求：视觉系统、聚焦与可插拔主题

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 目标

界面阅读式、克制、信息密度高但不拥挤；当前行动自然突出，其他内容低对比。轻像素主题值得尝试，但应是可插拔的视觉外观，而不是让产品初期先承担游戏地图或 RPG 任务组件的实现成本。

## 共同视觉规则

- 使用少量稳定文字层级：正文、辅助说明、当前焦点；避免每个模块使用不同字号与重复大标题。
- 用留白和轻分组建立关系，减少高对比卡片边框、鲜艳状态色和装饰性标签。
- 日常界面只显示可读名称。内部 ID、哈希、协议值放入诊断详情或复制信息。
- 对象名词可以用低饱和度颜色加粗，但颜色不能是唯一的语义编码。
- 每个界面在第一眼应能回答“我正在看什么、现在可以做什么”。
- 聚焦不是所有场景都盖一层遮罩：普通阅读时淡化周边；输入或重要审阅时才进入覆盖式专注层。
- 需要教程时优先就地一条提示；完整手册按需查看。

## 主题可插拔

第一版建立 CSS tokens/语义化样式类，主题只改变：颜色、字体风格、边框、阴影和轻动效。不要让主题改动信息结构、正式状态或交互语义。轻像素作为一个独立主题；切换主题后同一任务和操作仍保持相同含义。

## 结构动画

同一结构图 renderer 支持：
- 捕获成功后的短暂状态转移（仅持久化成功后发生）。
- 恢复时高亮上次工作节点与相关变化。
- 开始领航时高亮目标节点。
- 阶段/本轮结束时显示真实完成的结构变化。

动画应短、可关闭或尊重系统减少动态效果设置。动画不能把未执行的建议画成已完成的事实。

## 回退方案

当宿主插槽、图形布局或主题样式不稳定时，回退到清楚的文字目录和差异清单，保留原数据、来源和定位。不能为了保住漂亮图形而隐藏关键事实。

## 验收标准

1. 默认阅读式主题可长时间阅读。
2. 轻像素主题可切换，且不改变信息布局、正式语义或键盘行为。
3. 对象名词、来源和状态可读，内部编码不占据日常视图。
4. 当前焦点突出，次要信息弱化；没有大量重复字号和按钮。
5. 动画只表达已发生状态；失败时不播放成功动效。
6. 减少动态效果时功能仍完整。
7. 图形失效时退回文字目录/差异清单。
