# 模块需求：Capture 与 Inbox

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 这个模块解决什么问题

想法常常在做别的事情时突然出现。用户不想停下来选择项目、填写标题、挑标签或阅读说明；他只想把一句话留下，然后马上回到 DSH 当前工作。之后才决定它是一个想法、一个 TODO、需要和 Agent 讨论的问题，还是应该成为正式工作对象。

用户对旧 Inbox 原型的反馈也明确：文字太大、按钮太显眼；右侧正文应可双击直接编辑；左侧选择应支持全选和“今天”；不能让 Inbox 变成一直施加压力的操作面板。

## 用户故事

- 当我在 DSH 工作时，我可以通过明确按钮或快捷键打开空白捕获窗，直接输入并保存。
- 当我钉住捕获窗时，我可以连续写多条；保存后正文清空、光标回到输入区。
- 当我关闭或被打断时，未保存的草稿不会无声丢失。
- 我可以在一个地方找到以前保存的记录，并继续编辑它们。
- 我可以在 Inbox 里按自然时间浏览、全文搜索、选择今天或全选多条记录，并把它们带入 DSH 对话。
- 我可以把条目转成 `[想法]`、TODO、正式工作对象或 Journal 记录；不同结果不混成一个“完成”状态。

## 主要交互

### A. 快速捕获

1. 从 DSH 工作入口呼出浮窗，输入焦点立即落在正文。
2. 默认只出现输入区、保存动作和必要的轻状态；不显示项目选择、标签、优先级或 AI 摘要。
3. 默认保存后收起；用户显式钉住后，保存会清空正文并准备下一条。
4. 关闭时保留未保存草稿；保存请求失败时保留文本并给出短说明。
5. 捕获时可保存来源引用，例如来自哪段 DSH 对话或选中的文字；来源信息不需要占据输入主区。

### B. Inbox 回看

- 默认按日期分组的紧凑文字列表；只有当前聚焦条目展开。
- 主要操作保持低调，可在右下角或上下文工具区出现；不要在每条记录旁放一排高对比按钮。
- 双击正文进入编辑；编辑期间有清晰但克制的保存/取消状态。
- 多选支持“选择今天”“全选当前结果”“清除选择”。
- 基础操作：保留/继续考虑、现在处理、归档。正式化、关联、写 Journal、安排投入等放到“现在处理”之后按需出现。
- 归档表示离开待处理队列，但仍可搜索；永久删除需要独立且清晰的动作。

### C. 带去 DSH

1. 用户选中一条或多条记录，选择“带去 DSH 讨论”。
2. 系统打开原生 DSH 会话或创建一份带有原文和来源引用的草稿，默认不自动发送。
3. 用户可以直接说“先帮我梳理这些，不修改”。此时 Agent 应按明确指令分析，不能因带入 Inbox 就自行创建任务或归档记录。
4. 如果用户明确要求合并、写 Journal 或建立正式对象，按对应操作边界执行，并保留来源关系。

### D. Inbox 与 Journal 的演变

当前工作基线：记录可以先被可靠保存；成熟为 TODO 或正式事务后，应从 Inbox 待处理列表移出；仍处于考虑中的 `[想法]` 可以继续留在 Inbox；归档不等于删除。

用户倾向把捕获记录写到 Logseq 当天 Journal，并在每日整理时决定最终形式。这里需要在实现前明确：Inbox 与 Journal 是同一记录的两个视图/引用，还是两个独立文本。优先避免复制两份长期不一致的正文。第一版可以先做清楚的“记到今天”入口和可追溯来源，不必自动分类。

## 最小数据概念

- `CaptureRecord`：原始正文、捕获时间、可选来源、轻量处理状态、编辑版本。
- `SourceRef`：可选的 DSH 会话/消息、Logseq block 或文件位置。
- `InboxDisposition`：当前是否仍待处理、已归档、已关联/正式化等队列状态。它不等于正式任务生命周期。
- `JournalLink`：若写入 Journal，记录目标位置和来源链接；不要复制完整 DSH 工具日志。

这些名称是概念草案，不要求全部成为独立表或正式 WorkObject。

## 异常与恢复

- 同一次保存请求重试必须幂等，避免回执丢失后创建重复条目；用户故意再写一条相同文字仍应允许。
- 若本地已保存但同步未完成，显示“已保存在此设备”与“已同步”的区别，不显示虚假的统一成功。
- 若 DSH 同时修改条目而用户正在编辑，优先保留用户未保存输入，提供查看 Agent 修改的入口。
- 若来源失效，记录正文仍可用；来源链接应显示无法定位或提供重新定位，不得伪造来源。
- 若用户把条目正式化后撤销捕获，应撤销的是 Inbox 队列状态，不自动回滚已接受的正式操作。

## 验收标准

1. 第一次使用者不读说明也能呼出、输入、保存并回到原工作。
2. 捕获首屏没有强制项目、标签、标题或 AI 处理步骤。
3. 保存成功前不播放“已保存”动画；失败时正文仍在。
4. 钉住后可连续写；默认保存后收起。
5. 历史记录可找到、双击编辑、搜索、归档和恢复。
6. 多选“今天/全选”可用，带去 DSH 的引用内容完整且默认不自动发送。
7. 形成 TODO/正式事务后可从待处理队列移出；仍在考虑的想法可保留；归档仍可搜索。
8. 日常界面使用可读名称，不暴露内部 ID。

## 待明确

- 空白捕获是否显示当前项目作为弱提示，默认不强制归属。
- Journal 默认写入策略与每日整理的确切关系。
- 捕获窗关闭时点击背景与 Escape 是否同样保留草稿。
- 本地持久化与跨设备同步的首版范围。
