# 模块需求：Capture 与 Inbox

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 这个模块解决什么问题

想法常常在做别的事情时突然出现。用户不想停下来选择项目、填写标题、挑标签或阅读说明；他只想把一句话留下，然后马上回到当前工作。之后才决定它是一个想法、一个 TODO、需要和 Agent 讨论的问题，还是应该成为正式工作对象。2026-11-19 起日常自然记述以 Logseq 原生页面和 Journal 为主；下文 DSH 捕获入口针对正在进行 Agent 协作的现场，不是另一个日常主工作台。

用户对旧 Inbox 原型的反馈也明确：文字太大、按钮太显眼；右侧正文应可双击直接编辑；左侧选择应支持全选和“今天”；不能让 Inbox 变成一直施加压力的操作面板。

## 用户故事

- 当我在 DSH 工作时，我可以通过明确按钮或快捷键打开空白捕获窗，直接输入并保存。
- 当我钉住捕获窗时，我可以连续写多条；保存后正文清空、光标回到输入区。
- 当我关闭或被打断时，未保存的草稿不会无声丢失。
- 我可以在一个地方找到以前保存的记录，并继续编辑它们。
- 我可以在 Inbox 里按自然时间浏览、全文搜索、选择今天或全选多条记录，并把它们带入 DSH 对话。
- 我可以把条目转成 `[想法]`、TODO、正式工作对象或 Journal 记录；不同结果不混成一个“完成”状态。

## 主要交互

### A. 快速捕获

1. 从 DSH 工作入口呼出浮窗，输入焦点立即落在正文。
2. 默认只出现输入区、保存动作和必要的轻状态；不显示项目选择、标签、优先级或 AI 摘要。
3. 默认保存后收起；用户显式钉住后，保存会清空正文并准备下一条。
4. 关闭时保留未保存草稿；保存请求失败时保留文本并给出短说明。
5. 捕获时可保存来源引用，例如来自哪段 DSH 对话或选中的文字；来源信息不需要占据输入主区。

### B. Inbox 回看

- 默认按日期分组的紧凑文字列表；只有当前聚焦条目展开。
- 主要操作保持低调，可在右下角或上下文工具区出现；不要在每条记录旁放一排高对比按钮。
- 双击正文进入编辑；编辑期间有清晰但克制的保存/取消状态。
- 多选支持“选择今天”“全选当前结果”“清除选择”。
- 基础操作：保留/继续考虑、现在处理、归档。正式化、关联、写 Journal、安排投入等放到“现在处理”之后按需出现。
- 归档表示离开待处理队列，但仍可搜索；永久删除需要独立且清晰的动作。

### C. 带去 DSH

1. 用户选中一条或多条记录，选择“带去 DSH 讨论”。
2. 系统打开原生 DSH 会话或创建一份带有原文和来源引用的草稿，默认不自动发送。
3. 用户可以直接说“先帮我梳理这些，不修改”。此时 Agent 应按明确指令分析，不能因带入 Inbox 就自行创建任务或归档记录。
4. 如果用户明确要求合并、写 Journal 或建立正式对象，按对应操作边界执行，并保留来源关系。

### D. Inbox 与 Journal 的演变

当前工作基线：记录可以先被可靠保存；成熟为 TODO 或正式事务后，应从 Inbox 待处理列表移出；仍处于考虑中的 `[想法]` 可以继续留在 Inbox；归档不等于删除。

用户倾向把捕获记录写到 Logseq 当天 Journal，并在每日整理时决定最终形式。这里需要在实现前明确：Inbox 与 Journal 是同一记录的两个视图/引用，还是两个独立文本。优先避免复制两份长期不一致的正文。第一版可以先做清楚的“记到今天”入口和可追溯来源，不必自动分类。

## 最小数据概念

- `CaptureRecord`：原始正文、捕获时间、可选来源、轻量处理状态、编辑版本。
- `SourceRef`：可选的 DSH 会话/消息、Logseq block 或文件位置。
- `InboxDisposition`：当前是否仍待处理、已归档、已关联/正式化等队列状态。它不等于正式任务生命周期。
- `JournalLink`：若写入 Journal，记录目标位置和来源链接；不要复制完整 DSH 工具日志。

这些名称是概念草案，不要求全部成为独立表或正式 WorkObject。

## 异常与恢复

- 同一次保存请求重试必须幂等，避免回执丢失后创建重复条目；用户故意再写一条相同文字仍应允许。
- 若本地已保存但同步未完成，显示“已保存在此设备”与“已同步”的区别，不显示虚假的统一成功。
- 若 DSH 同时修改条目而用户正在编辑，优先保留用户未保存输入，提供查看 Agent 修改的入口。
- 若来源失效，记录正文仍可用；来源链接应显示无法定位或提供重新定位，不得伪造来源。
- 若用户把条目正式化后撤销捕获，应撤销的是 Inbox 队列状态，不自动回滚已接受的正式操作。

## 验收标准

1. 第一次使用者不读说明也能呼出、输入、保存并回到原工作。
2. 捕获首屏没有强制项目、标签、标题或 AI 处理步骤。
3. 保存成功前不播放“已保存”动画；失败时正文仍在。
4. 钉住后可连续写；默认保存后收起。
5. 历史记录可找到、双击编辑、搜索、归档和恢复。
6. 多选“今天/全选”可用，带去 DSH 的引用内容完整且默认不自动发送。
7. 形成 TODO/正式事务后可从待处理队列移出；仍在考虑的想法可保留；归档仍可搜索。
8. 日常界面使用可读名称，不暴露内部 ID。

## 待明确

- 空白捕获是否显示当前项目作为弱提示，默认不强制归属。
- 捕获窗关闭时点击背景与 Escape 是否同样保留草稿。
- 本地持久化与跨设备同步的首版范围。

## D-63 演进基线：多入口三轨分治哲学、防失效机制与极简三口袋体验（2026-11-24 已确认待实施）

> 适用分支：`feat/personal-time-stage-v1`，正式闭环 [DECISION-REGISTER.md](../DECISION-REGISTER.md) 中的 `D-05` / 未决边界 #2。核心定位：**水面下三轨严谨分治，水面上极简三口袋人话交互（冰山结构）**。

### 1. 五条底层处理哲学

1. **可信卸载契约优先于“催办完成”**
   - 消耗工作记忆（RAM）的根因是蔡格尼克效应与对外部系统的不信任：弹窗提醒会打断深度专注，而全量塞进黑洞列表一旦漏掉承诺，大脑就会重新自己硬扛杂事。
   - 系统的核心契约是：**不该出现的时刻绝对静音，该出现的时刻绝对准时、绝不丢包**。
2. **按「失约代价 × 完整度」分治，而非按来源或目录分治**
   - 真实随手记的动机高度多样，绝不只是“未来要转成 TODO 的草稿”：包含临时中断、模糊承诺与责任、项目半成品补充、独立待发育种子、观察判断与情绪卸压。
   - **高失约代价（临时中断 / 承诺责任）**必须遵守「零静默丢失」；**低失约代价（想法 / 慢思考）**必须遵守「自然衰减与零道德债」。两者绝不可共用同一套冷却规则。
   - **30% 完整度的模糊记录**缺的不是排期或标签，而是「澄清与发育」；硬给模糊事项建 TODO 只会制造拖延与内耗。
3. **准时延迟发育（Just-in-Time Clarification）**
   - 捕获当下保持零分类决策；对于指向某个已有项目的半成品想法，不在通勤或周复盘时脱离上下文硬拆，而是先投递到该项目的**「待发育口袋」**，等下次真正进入该项目现场（Logseq 页面 + DSH 专属工作区）时，结合完整上下文与 Agent 聊透成型。
4. **拉取制（Pull）时间主权，而非推送制（Push）打扰**
   - 外部信息流无限（Open List），每日深潜容量有限（Closed List）。白天工作期间杂事默认关在门外，由用户在大块工作间隙主动微注入、在下午下班前固定「清扫时刻」集中泄洪、在看图与进项目时被动共振拉起。
5. **AI 帮半成品长肉与照镜子，绝不替人背虚假债务**
   - 禁止 AI 静默把随手记自动批量转成 TODO 或塞进日程；AI 聚焦于洗口语、多意图拆条、3 分钟澄清边界、跨来源重复涌现提示，以及提供合法的放弃/延期/拒绝沟通出口，最终拍板权始终留给用户。

### 2. 水面上的极简心智（面向新手 30 秒上手）

为避免过度工程化与术语劝退，日常界面严禁直接堆砌架构术语，对外呈现为 **3 句话说明书 + 3 个大白话口袋**：

- **3 句话说明书**：
  1. 平时脑子冒出任何事，别自己记，顺手扔进兜里（不用分类、不用选项目）；
  2. 每天只守两个短时刻：早上 1 分钟选上午最重要的 1 件事；下班前 15 分钟「清扫时刻」清掉今天的小尾巴、把怕忘的大事点一下「盯住别忘」、想法直接不管；
  3. 周末花 10 分钟找 AI 聊一次，对着 AI 摊平的三叠牌点头拍板即可。
- **架构机制 -> 界面人话映射**：

| 底层机制（藏在 Companion 与 Agent 中） | 界面呈现的大白话口袋 / 动作 | 物理规律 |
| :--- | :--- | :--- |
| 轨道 1 · 快清兜底轨（Quick Sweep） | **今日小尾巴**（下班前顺手清） | 全天静音不弹窗；大块缝隙可主动微注入；下班前清扫时刻唯一亮起；做完即焚不污染星图 |
| 轨道 2 · 承诺与责任轨（Commitments） | **别忘 / 已答应**（不会自己消失） | **硬编码免疫 14 天自然挥发**；支持「太模糊？让 AI 问 3 个问题理清楚」澄清边界 |
| 轨道 3 · 想法与养分轨（Sparks & Feed） | **随手想法**（不管也没事，两周自动收起） | 零道德债；允许 14 天自然收起；支持「放进 `[[某项目]]` 以后再聊」与同类想法重复发芽提醒 |

- **新手 3 档渐进启用**：首周只启用「早上选 1 件事 + 下班前 15 分钟清扫今日小尾巴」；第 2–3 周按需启用「别忘 / 已答应」与 3 分钟 AI 澄清；满月后全面协同全局星图、项目待发育口袋与周日复盘。全程零红字逾期、零打卡分数、断档 3 天也能无愧疚接回。

### 4. 五套防失效机制

1. **正文优先 + 保守兜底路由（Fail-Safe）**：录入不强制填表，也不迷信行首前缀；正文语义权重始终高于 `**[注]**` 等默认前缀。若自然语言初判拿不准一条未标记记录是“纯灵感”还是“忘了要办的急事/承诺”，宁可在当天「清扫时刻」露一次脸（1 秒可退回想法池），绝不误判进可挥发区导致失约。
2. **清扫时刻防堵机制**：下午下班前固定窗口（如 17:15，15–25 分钟）只处理 2–10 分钟可闭环小尾巴；一旦发现某条耗时超过 15 分钟或边界不清，提供一键「太大了 -> 转入别忘澄清 / 本周池」立刻移出泄洪道；连续 2–3 天留在清扫盘的跨天项自动触发点破拆因。
3. **承诺免疫挥发 + 3 分钟澄清协议**：轨道 2 条目硬编码免疫 14 天冷却；未澄清项超过 3–4 条时在事实镜直接点破超载；澄清对话聚焦“对谁承诺与真实死线 / 最小不掉链子标准 / 现实代价”，收敛为四选一落点：**起新 Project** / **写入 Area 每周维护底线** / **拆 1 个动作进本周** / **生成“预期对齐/延期/拒绝”沟通放进明日清扫**。
4. **项目待发育口袋 + 连发演化线程与重复涌现**：指向已有项目的半成品先停泊在目标项目「待发育口袋」（与项目正式正文隔离），等进入该项目现场再发育并通过 `D-45` 写回；未归属独立想法享受 14 天自然收起，但若短时连发 `>= 2` 条形成递进思考链或跨时间重复出现 `>= 2` 条高度相关碎片，自动聚为「正在发芽 / 演化线程」并重置冷却。
5. **全局流转台账与三层数据洁癖**：原始真值层（Logseq / iCloud / Flomo 永远干净）→ Companion 轻运营态层（`stage-inbox-state.json`、`stage-pending-journal.json`、三口袋状态与可追溯/可撤销的「近 7 天流转台账 Flow Ledger」，不碰 Formal Kernel）→ 高纯度沉淀层（经拍板确认才写入 `D-62` 周复盘 `[[复盘/YYYY-Www]]` 反链或 `D-45` 项目正文）。

### 5. 分期落地与验收基线

- **Phase A（本地最小闭环，当前立刻推进）**：`icloud-inbox.ts` 加固 `.xxx.md.icloud` 云端占位符自动 `brctl download` 与 `evictedCount` 诊断 + `catalog-local.ts` 接入近 30 天 Journal `TODO`/`**[xx]**` 单真值投影（正文语义权重 > 前缀权重）+ MCP 新增 `stage_capture_inbox`（在线插件直写今日日记、离线 Spool 补写与 `captureId -> blockUuid` 去重）+ Companion 三口袋状态、近 7 天流转台账（Flow Ledger）与今日容器「下班清扫时刻」视图 + 非行动养分一键写入 `D-62` 周复盘页反链（并接入 DeepSeek `deepseek-flash` 做按节拍轻量语义辅助）。
