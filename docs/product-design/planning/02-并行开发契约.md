# Capture / Inbox × 工作结构历史：并行开发契约 v1

本轮只准备共同基线、最小接口和两条开发线，不启动功能实现，不冻结 Journal、敏感材料或历史恢复的产品决定。2026-10-21 再次 fetch / ls-remote 核实的输入为 `origin/main 669726965693595c860dbc235b85a5adc1d82900`；当前增补的提交进入远端 main 后，两条分支从该同一提交创建。此前[代码证据](00-代码基线核查-2026-10-21.md)保留其原检查时点；末节记录本次刷新。

产品语义以[独立模块](../INDEX.md)、[来源规则](../SOURCE-AND-STATUS.md)与[待决登记](../DECISION-REGISTER.md)为准。`codex/one-click-dsh-collaboration` 的三个独立提交本轮不合并；现有 main 的 DSH 绑定、引用与本地 Stage 能力足够作为开发起点。不得依赖该 feature 或另一条开发线的未合并文件。

## 0. 两条线的切片

- **A / `codex/capture-inbox-v1`**：快速捕获与 DSH 内悬浮窗、可靠保存、历史编辑与版本恢复、搜索/选择/归档和撤销归档、原文带入 DSH 草稿与返回。编辑版本恢复需生成新版本，不覆写旧证据；不做 AI 分类/相似分析、Journal 自动同步、正式化或大型面板。
- **B / `codex/work-structure-history-v1`**：基于已校验 Stage 快照的只读来源树、时间切换、稳定布局、真实差异与来源核查。父子/描述变化复用已有数据；正式依赖/状态没有对应历史证据就标为未覆盖，不从缩进或今天的文本推断。首轮不做结构编辑、历史回滚或通用工作流引擎。

## 1. 共享的最小集合

| 需求 | 共同约定 | 所有者 |
|---|---|---|
| 正式工作身份 | 仅引用现有 WorkObject.id / version；没有可靠映射就为 null，不从标题、cwd 或 sourceId 猜测 | 主代理 |
| 自然工作范围 | 复用 SourceScope、AgentWorkBinding、workspace manifest；比较完整 scope，含 kind/pageName，切换连接即失效旧异步结果 | 主代理 |
| 来源 | Logseq 复用 BlockSnapshot.target/sourceId/contentVersion；Kernel SourceRef 仅用于真实块引用；材料复用 materialId/version/reference；sessionId 单独保存 | 主代理 |
| 历史 | 直接读 StageHistory / StageStart / StageRevision.source / StageFile；派生布局与 Diff 不成为第二套历史 | 历史线只读消费 |
| 返回 | 原 sessionId、触发控件、所选来源和各模块的滚动/选择状态；原生草稿仍由宿主管，不复制/覆盖全文 | 主代理接宿主；模块保管自己的视图状态 |
| 请求与结果 | 复用已有 requestKey、content receipt、Stage problems；UI 只对自己的轻量保存定义 pending/saved/unknown/conflict，不能通用化为 Kernel 成功 | 各模块；跨宿主由主代理接线 |

产品草案中的 WorkRef、SourceRef、ReturnContext 是逻辑概念，不是要求创建三套新数据库/公共领域模型。仅新增不可避免的 Inbox 本地记录与 UI 参数类型；不引入统一操作引擎、通用 EvidenceRecord / GuidanceRun 或新的正式实体。

## 2. 接口形状与输入输出

签名的唯一源码为 [copilot-ui-port.ts](../../../apps/logseq-plugin/src/workspace/copilot-ui-port.ts)：`WorkUiContext`、`SourceSelection`、`SharedUiPort`、`StageHistoryPort`。初始共同基线只发布类型；后续主代理在同一文件提供 `sameWorkUiContext` 与 `createSharedUiPort` 的交互适配，独立于 A/B 模块，可注入原生 input actions 和可信来源 opener。它同步捕获原生 span，检查完整上下文，拒绝重复/过期插入，仅向原有效控件返回焦点；不注册宿主入口、不写存储、不授予权限。类型或适配器存在不等于真实宿主已接线。两条线从 main 获取同一版本；DSH 的 JSX 可用 JSDoc `import()` 引用类型，不复制声明。类型来源见[代码基线表](00-代码基线核查-2026-10-21.md)。

`context` 是调用时的身份快照，不是授权凭证。执行适配器每次核对 active session、scope、binding 和 generation；scope 与 binding.scope 不一致就拒绝。scope 可以在尚无目录绑定时存在；无项目 Capture 可传全空上下文，不能为了接口非空而新建 Project。StageHistoryPort 需要非空、现有已授权块范围；不隐式 authorize、refresh、begin、checkpoint 或扩展读权限。返回 history 先经 StageStore 既有校验；UI 不读原始磁盘绕过 provider。

`openSource` 依据 target 定位，hash 不再一致时显示“来源已变化”；打开当前来源与展示旧帧明确分开，不用当前正文补旧帧。主代理应在用户触发引用、任何异步工作**开始前**创建本次交互的 port，闭包持有原生 captureInsertion 的选区/修订，完成后以同一 span 调 insertText；不得到 insertDraft 完成前才捕获新选区。换 session、草稿改变或提交锁定时拒绝并保留待引用文本，绝不 setDraft 或自动 submit。`returnFocus` 只回 port 闭包保留的当前仍有效触发控件，不重绑会话或改 cwd；模块各自保管滚动/选择，不建立统一返回状态数据库。

| 开发线 | 输入 | 输出与副作用 |
|---|---|---|
| A Capture / Inbox | WorkUiContext（允许空）、SharedUiPort、主代理批准的模块本地 CaptureStore | 可靠保存/编辑的轻量记录、搜索与归档状态、明确的保存回执、由用户触发的原生草稿引用；不改 Journal / Kernel |
| B 结构历史 | WorkUiContext、StageHistoryPort、SharedUiPort.openSource / returnFocus | 从 start.source 和已记录 revision.source 派生只读帧、Diff、问题列表与定位请求；布局为 UI 状态，零正式/正文写入 |

CaptureStore 是 A 独有的本地接口，不由 B 导入；其记录最少为 id、原始/当前正文、时间、编辑版本、队列状态和可选真实来源。可复用材料正文与现有 requestKey/读回机制，但不把 MaterialRecord 的 ready 当作 Inbox 已归档；无绑定与离线持久化需过下列 G2，不能强制归属项目。两条线均不新增“所有格式通吃”的 SourceRef union。

## 3. 文件所有权

初始共同基线只新增共享类型；业务模块与宿主接线随各线的独立审查逐步整合。公共适配器也由主代理发布，两条线消费同一版本，不允许各自复制实现。

| 范围 | 唯一修改者 | 两条线规则 |
|---|---|---|
| `apps/logseq-plugin/src/workspace/copilot-ui-port.ts`、公共接口兼容性验证 | 共同基线主代理 | 只导入，不复制、不扩展字段；行为测试随真实适配器交付 |
| 新 `apps/dsh-plugin/src/capture-inbox/`、`apps/logseq-plugin/src/features/capture-inbox/`；各自 `capture-inbox.*test.*` | A 的 Codex 负责人；其中纯 UI 可交 DSH | 不写 B 文件；存储与宿主适配仍由 Codex 负责 |
| 新 `apps/logseq-plugin/src/features/structure-history/`、`apps/dsh-plugin/src/structure-history/`；各自 `structure-history.*test.*` | B 的 Codex 负责人；renderer 可交 DSH | 不写 A 文件，不修改 Stage 原始记录 |
| 现有 DSH client.jsx、index.mjs、service.mjs、styles.mjs、manifest/build；Logseq index.ts、agent-workspace/router/installer；CLI server | 共同基线主代理 | 入口、RPC、公共 CSS tokens 和远端历史枚举由主代理串行接线，模块 CSS 放各自目录 |
| workspace/source-protocol.ts、workspace-record.ts、registry.ts；Stage protocol/store/recorder/installer/diff；materials 核心；packages/contracts | 主代理 | 默认只读；提出变更单说明必要性、兼容性与测试，经主代理统一处理后再更新 pin |

“共同基线主代理”是负责 main 整合的唯一角色；A/B 电脑上的 Codex 负责各自模块，不能都以“主代理”名义修改共享核心。涉及共享文件时，在各自模块目录的 `INTEGRATION-REQUEST.md` 写出需求、最小签名/补丁建议、兼容性和验证方式，交回共同基线主代理串行处理；补丁不得作为本线未提交隐式依赖。共享改动先进入 main，再由两线普通 merge 获取，不 cherry-pick 各自变体，不 force-push。DSH Worker 与 Codex 不得同时修改同一文件。

G0 满足即允许后续获授权的 A/B Goal 在不同电脑并行开始。G1/G2/G3/G4 是真实集成与最终完成门槛，不阻塞独立的模块开发；模块内数据适配和持久化由本线 Codex 实现，跨模块接线仍由共同基线主代理串行完成。某个外部通道失败时应提供 Goal 中的独立前端子任务提示词，由 Codex 本地继续或交给可用 Worker；不得假称已委派、私自换 provider 或扩大目录授权。

两台电脑采用[两份 Goal](goals/01-Capture-Inbox-Goal.md)中的独立 clone / Node 20 / npm ci 方式启动；B 的入口见 [B Goal](goals/02-结构历史-Goal.md)。共同基线是准备提交发布后这两条分支的共同祖先，可用 `git merge-base origin/codex/capture-inbox-v1 origin/codex/work-structure-history-v1` 核查，不硬编码尚未生成的 SHA。既有 checkout 有未提交修改或分歧时保留原工作，另建干净 clone，不 reset/stash/覆盖。

## 5. 数据语义与待决事项

- Capture 已保存、Inbox 已处理、TODO 已完成、Kernel 已接受、Graph 投影完成分别表达；归档不删除原记录，撤销归档不反向撤销正式事实。
- StageStart 是第一帧，revision.parent 是版本关系；不按时间戳猜修订链。candidates/problems 不能静默塞进正式主链；Stage acceptance 仅为当地版本的用户认可，不等于正式 Task 完成。布局稳定性使用 sourceId，缺失 content 显示未知。
- 首轮 B 读取能证明的来源结构；正式对象树和代码模块图没有对应历史数据时标为未覆盖，不从 Logseq 缩进推出正式父级/依赖，不解析今天的 TODO 为过去的 Kernel 状态。
- 普通文件授权、敏感文件读取、模型上下文投递分别处理（D-07/08）；本次不新增扫描、自动投递或保留敏感快照。
- Inbox ↔ Journal 的正文权威、引用/投影、每日整理及同步仍待明确（D-05）；不接自动同步，界面不放假可用写入动作。
- 只读回放先行、历史变化恢复后置仍是建议顺序（D-16/17）；B 的只读任务不产生回滚能力，也不替用户冻结整体排期。
- 可信明确指令与 Agent 推断的正式权限桥接仍待核实（D-09/10/11）；现有 verified-local-connection 不升级为 Plugin USER capability。两线本阶段没有正式变更出口。
- 无绑定持久化/跨设备、Capture 背景点击/Escape 语义、系统级置顶、快照保留量和页面 Stage 支持仍未决；可逆 UI 默认必须在交付中单列，不写成用户最终决定。

## 6. 验收与交回

A 必测同键重试、部分/未知保存、编辑冲突、断连草稿、多选引用、会话切换与原生输入忙；B 必测真实 provider 读取、不可变旧帧、缺失正文、移动/增删/文字差异、分叉与损坏、页面不可用、零写入、稳定布局及文字回退。两线加上恶意来源文本不能变权限的检查。测试 fixture 必须有醒目标签，与真实 provider 数据分别记录。

公共回归命令、已通过范围与现有失败见[基线记录](00-代码基线核查-2026-10-21.md)。新实现至少跑各自行为测试、相关既有回归、受影响 workspace typecheck/build；由主代理整合后跑根 check（注意其中有文档生成步骤，核对生成差异），并完成真实 DSH/Logseq 验收。失败不可删检查或沿用旧报告算通过。

每次交回提供实际 diff、输入基线 SHA、检查命令/退出结果、fixture/真实宿主区分、未决/阻塞清单和恢复方法。DSH 自述测试不算验收，Codex 必须独立检查并运行测试。具体可执行目标：[A Goal](goals/01-Capture-Inbox-Goal.md)、[B Goal](goals/02-结构历史-Goal.md)。
