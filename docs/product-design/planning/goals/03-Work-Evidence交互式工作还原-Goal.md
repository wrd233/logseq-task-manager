# 下一阶段 Goal：Work Evidence 交互式工作还原

> 准备状态；本次文档同步不执行此 Goal。只有收到后续实施请求才开始开发。

以仓库[模块 06 产品需求](../../modules/06-工作证据与历史.md)和[交互架构](../../architecture/02-Work-Evidence交互式工作还原.md)为权威，实现：同步变化 → 文件条目 → Agent 逐条分析 → 按工作目的归组 → 关键澄清 → 局部重新分析 → 生成并保存交接记录 → 引用到 DSH 原生草稿。不得重新发明已确认的产品决策。

开工先直接刷新远端，核对最新 main、当前 Work Evidence 开发线及结构历史分支；在独立 Worktree 从当时最新开发线继续，保护其他 Goal。复用现有观察、不可变存储、意图修订和草稿边界，不合并 main、不覆盖其他工作区。遇到真实代码约束，记录准确源码位置、与设计的差异及最小必要调整，不静默缩减目标。

必须交付：

- 从上次同步到现在的新提交和当前未提交变化，明确初始范围、检查点异常和重复呈现语义。
- 文件级证据、可追溯 Agent 解释、工作目的归组；关联上下文限于获准的 Git、DSH 会话和 Logseq 工作结构。
- 每条目独立进度；只问影响结论的少量关键问题。支持回答、编辑和跳过，回答后仅更新受影响条目/工作组。
- 用户可提前交接；保留未知、未分析和失败项。交接保存到 Work Evidence 历史，可重开、修订并引用到原生草稿。
- 默认列表及可选结构视图，表达同一批条目。先检查真实通用组件，仅复用/提取模型、布局、渲染和交互边界，不依赖整个结构历史业务，不凭空规定 API。
- 区分观察事实、Agent 解释、用户澄清和交接产物。禁止自动发送、自动创建/完成正式任务、擅自写 Graph 或 Formal Kernel、自动 commit。
- 改善信息层级和局部反馈，减少重复按钮、无必要抽象与通用防御层；保留保护输入、不可变来源和越界写入限制所必需的可靠性。

在独立 profile 和合成 Git 的真实 DSH 中验证：首次与增量同步（含多个新提交及未提交变化）、文件 diff、逐条分析与归组、一个回答后的局部重分析、另一个跳过后仍保留未知、交接保存与重开、原生草稿引用且不自动发送、列表/结构切换，以及失败/重载后证据和输入恢复。运行对应自动化、类型检查、lint 和构建。模型替身与真实模型、模拟 UI 与真实宿主分别记录，未能执行的项目不得宣称通过。

最终交付实现与 UX 改动、共享工具复用方式、重要简化、测试/真实宿主结果、可复建启动方法、来源与剩余限制；仅提交并推送自己的开发分支，不自动整合 main。
