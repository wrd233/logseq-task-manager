# 跨模块设计：共享结构、来源、权限与工作接续

> 状态：产品设计工作基线，非已实现能力清单。下文方案与验收目标受[来源与状态](../SOURCE-AND-STATUS.md)及[待决登记](../DECISION-REGISTER.md)约束；未标定的实现细节按设计建议理解，倾向和未回答均不构成最终决定。返回[文档导航](../INDEX.md)。

## 1. 为什么需要一份跨模块设计

各模块表面上不同：Inbox 负责捕获，DSH 负责对话，结构图负责编排，Git 负责证据，Planner 负责投入，领航负责连续推进。但它们需要指向同一件工作、同一批来源和同一条操作结果。

本设计的目标不是建一套万能框架，而是让模块复用最少的稳定概念，避免出现多份正式任务数据、互相冲突的会话绑定或看起来成功但实际上未完成的写入。

## 2. 最小共享概念

这些是逻辑契约，不要求一一成为数据库表或独立领域实体。

### WorkRef — 工作身份引用

指向现有正式 Task / MiniProject / Project，或明确标记为尚未正式化的工作草案。它不复制正式对象的权威字段。所有目录、图、计划和 DSH 入口都引用同一身份。

### SourceRef — 来源引用

可以指向 Logseq block、文件路径与版本、Git commit/diff、DSH session/message 或测试结果。至少要说明来源类型、可定位信息、可用版本/时间以及当前是否还能访问。界面展示可读标题，内部 ID 放在诊断层。

### EvidenceRecord — 观察与解释

把机器观察（文件变化、测试输出、Git 状态）与用户/Agent 的解释分开。记录内容可以引用 WorkRef 和 SourceRef，但观察记录本身不自动成为正式任务状态。

### CaptureRecord / Inbox 状态

捕获正文与时间是原始记录；它可选地引用来源和工作身份。待处理、仍在考虑、已归档、已正式化等是 Inbox 队列语义，不等于正式 Task 生命周期。

### StructureSnapshot — 结构快照

用于历史回放、恢复、Diff、收尾与领航提示。包含同一时间点能够证明的节点身份、父子关系、依赖、名称/描述和正式状态，以及每部分来源。没有保存的字段应明确缺失。

### ChangeProposal / ChangeSet — 候选差异与正式操作

候选差异描述希望发生什么；正式操作由可信授权源在唯一写入路径上执行。布局位置、颜色、计划草稿和 Inbox 归档不需要全部变成 Kernel commit。正式变更被接受后，保存正式收据和后续投影状态。

### ScheduleAllocation — 一次投入安排

引用 WorkRef 或自由工作意图，包含语义时段、状态（计划/已结束/已取消）和可选停点。它不是正式 Task，也不等于工作已完成。

### ReturnContext — 返回现场

保留最少但足够恢复的信息：当前 WorkRef、原 DSH session、草稿、选中 SourceRef、焦点/滚动/折叠状态，以及触发跨尺度操作前的来源位置。不要冻结整棵 DOM 或全部临时状态。

### OperationReceipt — 操作结果

对异步/正式操作，至少能查明：请求身份、已接受/部分完成/冲突/未知/取消、正式结果和 Graph 投影状态。重复点击或网络重试要查询同一操作，而不是创建新的操作。

### GuidanceRun — 本轮领航

可先作为轻量的协调记录，引用工作范围、停点、开始/暂停/结束状态、已执行动作与结果。它不需要成为新的正式 WorkObject。

## 3. 三类状态存储，不建三套正式真相

### 正式事实

继续由 Kernel 负责正式对象、归属、生命周期和正式操作记录。新增功能应通过现有 API/commit 路径写入，不复制一份平行任务库。

### 自然材料

Logseq 和工作文件继续是自然语言正文与原始材料的来源。需要历史可核查时，通过 SourceRef、版本和有限快照关联，不强制把所有内容迁移到 Kernel。

### 轻量运营与视图状态

Capture/Inbox 处理、工作集、布局位置、选中对象、阅读宽度、计划草案和主题偏好属于轻量状态。它们可以持久化，但不必成为正式 WorkObject。第一版优先使用已有持久化基础；浏览器 localStorage 可以保存非关键偏好/草稿，但不能作为唯一的可靠 Inbox 持久化层，除非产品明确接受单设备限制。

## 4. DSH 原生内联交互

### 工作入口

在 DSH 中只保留一条紧凑入口，显示当前工作可读名称与必要的状态/来源线索。项目切换应从上层工作台或工作目录发起，不用一个不明所以的右侧下拉框承担整个工作导航。

### Lens 条目

线索插入相关对话位置，像一条短的上下文条目：

- 一句可读标题/描述。
- 相关对象以低饱和度加粗显示。
- 直接来源链接。
- 轻量动作，例如“展开依据”“继续讨论”“已解决”。

不要为每条线索制造一张大型卡片，也不默认排序整个工作目录。线索可以进入 DSH 讨论，由模型在上下文中追问真正缺失的信息。

### 证据追问

流程不是“扫描器发现差异 → 独立表单让用户填写固定字段”，而是：

1. 观察器展示可核查变化。
2. DSH 在用户回到工作或请求同步时阅读这些变化。
3. 若关键意图缺失，Agent 在对话里提出与当前情况相关的少量问题。
4. 用户回答后，保存为来源明确的解释/回顾记录；用户可以跳过。
5. 只有用户明确要求的正式状态变化才进入 Kernel。

## 5. 权限：把四件事分开

### 5.1 工作范围

当前任务/项目的授权边界是什么？跨项目阅读可能合理，但执行目录切换必须明确。

### 5.2 文件可访问范围

用户进入某项目后，普通项目材料是否一次授权、之后按需读取？这是未决设计项。建议减少普通文件的逐项审批，但不能默认为整个机器的所有路径都可读。

### 5.3 实际读取行为

Agent 可访问不意味着每次都要递归读取全部文件。默认应按任务检索、按需读取，并允许用户查看本次实际使用了哪些材料。文件界面“全选”是用户可以操作的入口，不自动意味着每份内容都被模型接收。

### 5.4 模型上下文投递

读取后的材料是否发送给模型，应由具体工作需要、授权和敏感内容规则决定。`.env`、凭据、私人日记等不能因为与项目目录相邻就默认进入模型上下文。具体敏感路径策略是未决项，必须在扩大读取能力前明确。

## 6. 正式操作与结果语义

推荐的操作分类：

- 轻量本地/运营操作：编辑 Capture、归档 Inbox、调整工作集、拖动日程、调整图布局。
- 自然材料操作：写入 Journal、编辑 Logseq block、修改文件；遵循 DSH/Logseq 现有授权。
- 正式 Kernel 操作：创建/重命名/改归属/变更生命周期等，走可信来源和现有 commit 路径。
- 高影响外部操作：不可恢复删除、扩大权限、对外发送、外部承诺等，需要更强确认。

可信用户明确指令可以免去重复审批，但必须由可信宿主/插件提供授权来源。Agent 自己写的 `USER_EXPLICIT` 等字符串不能构成信任根。实现时应检查当前 Kernel 的正式来源校验与 API，不另造一套绕过机制。

## 7. 正式提交、Graph 投影和异步恢复

已有 Kernel 设计将正式事实接受与 Logseq Graph 投影分开。界面至少区分：

- 操作尚未发送。
- 结果未知（请求可能成功但回执丢失）。
- 正式操作已接受。
- Graph 投影待完成。
- Graph 投影冲突/失败，需要重试或人工处理。
- 正式操作被拒绝/冲突。

同一个 `operationId` 应可查询和幂等重试。网络错误不等于失败，关闭 UI 不等于取消后端操作。对 Graph 的自动投影不能覆写用户后来编辑的来源。

## 8. 共享结构图：一套语义，多种用途

### 同一个节点身份

节点对应稳定 WorkRef 或有来源的自然材料引用。图上的节点名称是可读标题；内部 ID 仅用于诊断和链接。

### 同一 renderer 的四种用途

1. **编排**：父子关系、依赖和局部邻域。
2. **Diff**：旧结构与候选结构对照，突出增删移动和影响。
3. **历史**：同一张图随时间变化，保持位置稳定，缺失字段不补造。
4. **接续/领航/收尾**：高亮当前节点、上一步变化、已完成的本轮工作和遗留点。

这不意味着一个复杂万能图组件一次性实现所有编辑功能。先共享节点身份、来源和差异语义；首版历史可以只读，结构编辑后续接入。

### 动画规则

- 颜色/闪烁区分当前工作、真实变化、候选下一步；不要只靠颜色，需有文字标签或形状差异。
- 轻动画只在真实状态变化后播放。
- 历史滑动时稳定大部分节点，只移动受影响部分。
- 无法布局或数据不完整时，退回目录与差异清单。

## 9. Inbox 与 Journal

目前存在一个需要实现前明确的存储设计：用户希望捕获记录可以先写入当天 Journal，并每日整理；同时成熟为 TODO/事务后要从 Inbox 待处理队列消失，未成熟的 `[想法]` 可以继续保留。

建议把“记录本身”“Inbox 队列成员”和“Journal 引用/投影”概念分开：

- 原始捕获记录保留原句、时间和来源。
- Inbox 状态表示它是否仍需要用户考虑/处理。
- Journal 可以引用这条记录或生成用户认可的简短文字，但必须保留原始来源。
- 形成正式对象后，Inbox 队列成员可以关闭，正式对象引用原始记录；不要把“离开 Inbox”当删除，也不要把同一正文无意识复制成两份长期不同步的文本。

这套关系需要在第一版选定具体持久化方案后再冻结 schema。

## 10. 跨尺度返回契约

开始跨面板操作时，保存 `ReturnContext`。返回时恢复：

- 来源工作身份与原 DSH session。
- 原始草稿和未发送输入。
- 触发操作的 Inbox 记录/选中对象。
- 来源定位、滚动和折叠状态（若仍有效）。
- 操作结果状态和可继续的下一步入口。

如果源条目在别处已被归档或修改，不要硬恢复过期按钮；显示当前状态，并保留用户尚未保存的输入。

## 11. 主题与可访问性

主题只改外观 tokens，不改变数据、布局语义和正式行为。阅读式是默认；轻像素是可插拔主题。键盘操作、焦点恢复、减少动效、低饱和色彩和可读文字必须贯穿所有模块。

## 12. 主要架构风险

1. 为每个功能都创建新领域实体，造成模型膨胀。
2. 将浏览、读取、模型投递和执行授权混成一个权限开关。
3. 将 Agent 的推断写成正式事实。
4. 把 Kernel commit 与 Graph 投影视为同一原子操作。
5. 用今日文本伪造历史快照。
6. 让图形、主题或 DSH CSS hack 成为唯一界面路径。
7. 两个代理同时改共享协议，最后无法可靠合并。

对应策略：先做最小纵向链路；共享概念保持少量；正式写入复用 Kernel；保留来源和操作收据；所有高级图形都有文字回退；并行实现以接口先行、主代理集成为前提。
