# External CLI Agent Governance Golden Path

Automated acceptance uses a real loopback Kernel Service, the production broker/client/coordinator, and the independent Fake Graph Adapter worker. It proves:

1. bootstrap exposes two approved Skills and no secret;
2. bounded search/read writes ReadReceipts but not Evidence;
3. fresh Adapter material freezes as target-bound Evidence;
4. `EXTERNAL_CLI` current-focus output becomes the existing Proposal and a verified Commit;
5. the same executor enters and leaves WAITING through the existing Engagement Proposal;
6. `NO_PROPOSAL` creates no Proposal, Commit, or Graph mutation;
7. finish and apply retries return the original durable identities;
8. External result cannot select Skill, risk, actor, PARKED, Closure, generic create, or raw write.

The real Desktop matrix separately records current focus, both Engagement directions, and `NO_PROPOSAL` with zero Task Copilot Plugin UI clicks during the CLI flow. The protected real Graph was connected once through the Plugin's local bridge setup; after the click counter reset, every governance action ran through the built CLI while the Plugin remained only the background Graph Adapter. Local Graph names, content, screenshots, descriptors, runtime IDs, and database remain outside Git.

A fresh-session synthetic acceptance used only this repository's short Agent Guide and the built `task-copilot` binary. The first run exposed an incomplete Engagement result description and a broken build artifact; both were fixed. A clean rerun required no source-code reading or field guessing, committed one focus and one Waiting proposal, produced one durable `NO_PROPOSAL`, and ended with no failed runs or recovery rows. Runtime IDs and temporary descriptors remain local.
