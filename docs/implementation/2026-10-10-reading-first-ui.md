# 阅读优先界面

实现分支：`codex/reading-first-ui`。起点是当前试用分支的 `888142b`，不合入 main，也不替换正在试用的 Logseq 安装。

## 正文

默认继续使用完整正文的连续阅读。顶部读法菜单可切到原结构或 Agent 提交的自定义方案；选中范围后，“只读选中部分”变为“返回全文”。工作设置、协作与授权、高级维护归入“更多”，原生写作与审阅入口保留。

“让 Agent 设计读法”打开带阅读请求的真实协作准备表单，阅读偏好草稿与普通协作草稿分别保存。用户准备现场后，外部 Agent 通过既有 `reading request` / `reading submit` 协议提交方案。界面不自行启动模型，也不因选择读法授予正文、文件或 TODO 写权限。完整来源、版本、树结构依赖、材料可用性与过期方案保护保持原协议。

行首标记继续由 `report-body.ts` 解析。本次没有更改它；展示标签与真实原文保持分离。

## 材料

默认显示当前工作已收纳、已关联的材料，每份文件一行，名称与只读状态并列。概述保留为元数据及悬停信息；链接、改名等动作放在行末“更多”。即使尚未取得磁盘目录读取许可，已登记材料也不会因默认入口只显示目录浏览而消失。

保留文件和文件夹拖入，并增加文件选择入口。导入使用原有服务与队列，保存副本、保留原文件；材料列表中的导入不插入 Logseq 正文。目录管理保留默认目标选择。目录中的其他文件通过可收起的浏览入口读取；选择新目录后立即展开，日常收起时停止目录轮询。文件系统观察与已登记材料分别显示，无法读取目录不被当成文件删除。

## 文件阅读

Markdown 使用现有 marked 和安全清洗；DOCX 使用 Mammoth 连续正文；图片保留适配与缩放；PDF 使用随包 PDF.js。PDF 全部页面处于同一个滚动流，自动适配宽度，没有上一页、下一页或跳页按钮。附近最多四页持有画布，每页最多约六百万像素；退出、取消、改变尺寸或切换范围时释放或重绘画布。独立窗口在实际所属文档中建立视口观察器。

预览只保留一份文件标题与工具栏，复制链接、编辑、来源和位置移入“更多”，正文占据主要空间。独立窗口仍独立保留打开时的原始字节版本。

Excel、CSV 等表格保留文件、关联与外部打开，不再路由到内置表格预览。旧 `.doc` 外部阅读，另存 `.docx` 后可预览；不转换或覆盖原件。DOCX 是语义正文阅读，复杂版式、页眉页脚等仍沿用原有不完整提示。

## 验证

使用仓库要求的 Node 20.19.0。新增回归覆盖默认材料可见性、预览工具栏、动态读法切换、阅读请求草稿隔离、PDF 连续页面、尺寸变化、画布数量及取消释放；原有拖入、目录、改名、来源版本、原生输入与行首解析检查继续运行。

浏览器检查使用真实组件和合成材料：Chrome 中打开十八页 PDF，连续滚到最后一页、确认最多四个画布和自动适配；检查真实 DOCX、阅读菜单、密集文件列表，以及 360px 深色界面。此检查不替代 Logseq Desktop 的宿主验收，也没有更新用户正在试用的安装。

结果：完整 `npm run check` 通过，含 553 项插件测试；最后的文件选择范围保护与数量显示调整另经插件类型检查、全仓库 lint、37 项材料回归和全仓库构建通过。Chrome 检查同时验证真实 Markdown、PNG、DOCX 与十八页 PDF。
