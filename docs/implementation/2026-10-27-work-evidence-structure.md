# Work Evidence 结构快照接入

基线：`origin/main` `f35fa5efeb403e30a86b2c71b110ccef65b82047`；开发分支 `codex/work-evidence-ux-v1`，起点 `a7c69515eaf0acb6cba67eb849b5707f38e43d1a`。

同步仍由 Work Evidence 的 Git 检查点驱动。成功观察后，通过既有目录绑定的 `collaboration.read` 只读取得 Logseq 已保存协作场景，要求读取权限、绑定一致、来源版本一致，并通过原有 `validateSnapshot` 检查身份、结构、正文版本和范围。完整快照单独写入 Work Evidence 私有历史，与该观察关联；Git 观察失败、结构不可用或超出存储上限时不阻断文件工作流。这里保存结构和正文，Git Diff 仍不存档；不写 Graph、不发消息。保存场景的 `capturedAt` 是实际来源时间，并不保证等于同步时间；`sourceMatches` 表示协作宿主所核对的已保存工作区来源一致，不是同步瞬间对 Graph 的新采样。

前后快照必须来自同一 Graph 和完整工作范围。默认与 Git 上次成功检查点比较，也可选择其他较早的观察；首个快照仅为基线。快照缺失、范围改变或读取失败时不推断变化。基于 main 的 `structure-history/model.mjs` 确定性比较和 `layout.mjs` 树布局，沿用节点 ID、顺序、父子、正文和来源版本，计算祖先移动带来的后代深度变化。复用 main 的原文标记解析及 `sourceBody`；不引入 Structure History 的控制器、阶段存储或 Agent 结构。可选结构图展示前后位置、正文和来源；核对当前来源复用 `source.read`，检查工作绑定和来源身份，不改变历史快照。交接草稿包含快照时间和引用，但不将观察或分析视作验证通过。

该分支未移植 main 的 Stage 历史枚举服务，也不会将文件归组当成 Logseq 结构。它只能比较本改造启用后成功捕获的协作场景；历史场景、当前 Graph、同步提交不一定同一时点。没有已授权连接、已保存场景、完整来源，或快照大于存储上限时，界面明确显示无法比较。节点来源核对不提供跳转 Logseq 的操作。结构图目前没有 main 历史工作台的大图虚拟化，最多接收 5000 节点，较大结构可能不够流畅。

测试夹具是合成快照，不代表真实 Graph 验收。既有真实 Git / 隔离本机存储与回调测试验证文件、检查点、局部分析、交接及历史；新增测试覆盖祖先移动深度、增删、顺序、正文、范围变化、不可用、权限、快照重读及节点详情。尚未在真实 Logseq Desktop、真实用户 Graph、真实模型和 DSH 原生界面端到端验证，不应据此宣称可生产使用。
