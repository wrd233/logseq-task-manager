输入基线：远端实际分支 `codex/dsh-history-workbench`，`007b8e82232fd118b6ca2a62c1da8bdb059bc4eb`。远端没有不带 `codex/` 的 `dsh-history-workbench`。本轮在新建的独立 worktree 与对应分支完成；没有切换、覆盖或提交主工作区的 Capture 改动，没有合并其他开发线。单一 Codex 执行，无子代理或外部模型委派。

## 现在怎么用

打开会话头部「工作历史」，默认只浏览最新保存版本。顶部选择版本；点击「比较」才显示基准版本和简短变化数，可选择任意已加载的同投影版本；「更早版本」按原分页接口继续加载。浏览与比较均不写入历史。

主体是自上而下的结构树。实线为归属，带箭头虚线为依赖；新增标 `+`，变化标 `Δ`，移出标 `−`，旧节点及其连线用虚线。保留声明状态文字，颜色不是唯一信号。宽分支按可用宽度换行，无需逐层展开。大图按二维可见范围渲染节点；超过 80 节点时只显示所选节点相关依赖，避免依赖线遮蔽结构。目录视图共享节点选择。

选中节点才显示单一详情区：关系、前后字段和正文、来源核对、引用。宽屏并排，窄侧栏为可关闭的详情抽屉；Escape 关闭并返回节点焦点。搜索和「只看变化」保留淡化祖先作为上下文，变化选择器可直接定位删除节点。

删除常驻时间线、时间滑条、默认相邻比较、空详情占位、Agent 解释卡、活动列表、重复版本摘要和成组元数据折叠。Git patch 仍保留一个按需入口。Agent 解释与完整时间/来源事实仍可通过既有工具读取。

「更新结构」把整理指令插入原生草稿：先读取已有结构、核对材料、沿用节点 ID 和来源版本，再明确保存完整选定结构为新版本。节点、比较与来源引用同样只插入草稿，不发送。

## 数据与接口

- `work_history_list/read/compare/snapshot/explain` 的名称和参数保留。`list` 改为纯读取；删除 UI 刷新或工具查询触发的自动保存。Git / Logseq 检查点仍由既有工作重入与 Agent idle 生命周期采集，显式结构更新仍经 `snapshot` 追加不可变版本。
- 新增窄接口 `work_history_source({snapshotId,nodeId,sourceIndex?})`，直接复用 UI 的 `HistoryService.source`：在当前项目/Logseq 授权范围内返回保存的来源身份、版本、当前正文及核对结果。没有新增存储或授权系统。
- UI 与 DSH 继续共用确定性的 `compare`、同一历史存储和来源核对实现。新增 `layout.mjs` 仅计算布局和过滤，不成为历史事实。
- 部分结构引用未观察父级时，加入旧节点仅为展示；若会与当前移动关系构成伪循环，只在视图中断开旧归属，不修改原记录。当前 Logseq 来源缺失字段归一为 `null`，确保原生工具输出可序列化。
