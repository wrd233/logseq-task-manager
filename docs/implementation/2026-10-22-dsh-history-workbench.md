## 使用

1. 在已有工作目录中打开 DSH 会话，点击会话头部 **工作历史**。它是 DSH 原生右侧标签页，可展开到全屏。
2. 默认显示最近的 Agent 工作结构及上一条记录的比较；没有 Agent 结构时显示已连接的 Logseq 历史，再回退到 Git 观察。不同来源投影分别浏览，不能跨投影做增删比较。
3. 选择时间线记录或拖动时间条，另选任意已加载记录作为比较基准。相同标题或时间的记录用稳定记录编号区分。可继续加载更早记录，刷新会保留当前选择和比较基准。
4. 在结构图或目录点击节点，查看正文、归属、顺序、深度、声明状态、依赖及来源的前后变化。宽屏三栏，窄栏上下阅读；两种视图共享选择，画布只渲染可见区域，搜索后可定位节点。
5. 点来源可核对今天的文件或 Logseq 原文。版本一致、已变化、历史版本未知和已删除/移出授权范围分别说明；今天的内容不会补写到旧快照。
6. **带入草稿 / 引用节点 / 引用比较 / 引用来源与核对结果** 使用 DSH 原生输入接口，在当前插入位置追加带身份和版本的引用，保留原输入，不自动发送。切会话或读取未完成时不插入旧结果。

Git 记录无需 Logseq 连接。若要读 Logseq 历史：先在 Logseq 将工作入口关联目录，右键入口块选择 **工作台：只读连接此工作**，再在 DSH 的 **↗ Logseq** 关联该目录。这不会授予正文、结构、文件或 TODO 写入权限。也可使用已有命令面板的只读连接入口。运行 companion 和安装插件的步骤见 [DSH 插件说明](../../apps/dsh-plugin/README.md)。

## Agent 契约

| 工具 | 用途 |
| --- | --- |
| `work_history_list` | 查询项目历史；顺便刷新真实 Git / 已有 Logseq 修订，支持投影、分页 |
| `work_history_read` | 按记录 ID 读取保存内容，可指定节点或分页读取 |
| `work_history_compare` | 比较同投影任意两个有效快照，工具计算确定性变化 |
| `work_history_snapshot` | 保存 Agent 整理的完整选定结构，或明确标记的历史重建 |
| `work_history_explain` | 对已有记录追加具名归属的 Agent 解释，不改原记录 |

最小快照输入包含 `requestId`、`title` 和 `nodes:[{id,title}]`。节点可以附 `body`、`parentId`、同级 `order`、声明 `status`、`dependencies` 和 `sources:[{kind,ref,version,excerpt}]`。同一工作改名或移动时复用节点 ID；省略 order 时按同一上级下的输入顺序计算。未知正文标记 `availability: unavailable`；仅观察部分范围时标记 `coverage: partial`，未出现节点只记“未再观察”，不宣称删除。最多 5000 节点，单条记录最多 800 万 JSON 字符，正文保存完整；引用超过 12000 字符会明确标记节选。

重试使用同一 requestId 和相同内容；同 requestId 不同内容被拒绝。可用 expectedParent 避免并发覆盖预期。`origin` 为 agent 或 reconstructed；observed 留给真实来源适配。历史重建必须提供 occurredAt 及已有记录 ID 列表 reconstructedFrom，显示独立的重建时间。Agent 负责语义组织和解释，工具不猜测任务阶段，也不宣布正式完成。

记录区分事件时间 occurredAt、工具记录时间 recordedAt、来源原记录时间 sourceRecordedAt、重建时间 reconstructedAt。观察不能确定事件时间时保留未知，不把 Git 提交日期当作工作区所有变化的发生时间。顺序以已保存序列和 StageStore 校验后的因果链为准；不按时间戳拼造缺失状态。

## 实现边界与简化

- 新模块集中在 `apps/dsh-plugin/src/structure-history`。复用既有 Stage 历史链模型、声明状态/依赖提取、正文元数据过滤和行内比较；只增加 `stage.history` 只读 companion 命令，不另建记录器。id:: 的持久身份元数据不产生正文变化，完整来源和版本仍原样保存。
- DSH 原生 Tools、SystemPrompt、Connection、sidebarRight 和 inputActions 负责注册、会话、传输、面板和草稿。没有自建聊天框、任务系统、模型 provider 或通用事件引擎。
- 自动检查点在 Agent 回到 idle、下一轮上下文组装、历史查询/刷新时采集 Git 和已有 Logseq 修订；不自动给 Logseq 创建阶段或 checkpoint。Git 相同当前状态和已导入修订不重复记录；A→B→A 保留真正的三次观察。
- Git 仅记录选定目录内的路径状态、已有提交间 patch、工作区 patch 和内容指纹；不会猜测项目语义。新仓库替换原目录时开始新的观察，不伪造跨仓库提交范围。未跟踪文件只保留指纹，patch 超长明确节选；不记录常见凭据文件或私有工作目录。Git 路径列表本身是部分投影，干净时不补造完整文件树。
- 按真实工作目录归属私有不可变文件，带内容哈希校验；每个项目一个进程内追加队列。当前明确采用单 DSH 宿主写入，不提供多个进程同时写同一私有历史目录的锁。存储位于 DSH bindingStateDirectory 的 history 子目录，不在 Graph 中。
- 删除重复的正文过滤闭包，复用共享比较；精简工作目录绑定对原生编辑状态的过宽拦截，只阻止正在编辑目标入口块。保留来源完整性、授权范围、内容版本与异步会话竞态的检查。没有新增兼容平台、校验框架或运行时依赖。
