# 实施 prompt · 工作现场、共同写作与共享约定

请在现有外部 Agent 通道上完成实际协作流程：带当前工作去协作、共享指导、写材料和引用、组织有内聚性的记录、共同写作，以及维护获授权的普通 TODO。完成代码、必要测试、真实本机协作演练和交接，不停在提示词模板或未执行的 JSON 示例。

建议分支：`codex/agent-collaboration-workflow`。这是协作与自然写回支，消费目录、预览和阅读方案能力，不另建这些模块。

## 起点与共同要求

本 prompt 与共同约定位于仓库的 `docs/implementation/prompts/2026-10-07-agent-collaboration/`。若主工作树尚无这些文件，可从本地 `codex/workbench-visual-refresh` 分支读取同路径；不要为了取文档切换或重置用户主工作树。

先读适用 AGENTS.md、package.json、本目录 [shared-contract.md](shared-contract.md) 和整合分支固定的接口。独立工作树从共同 `BASE_SHA` 开始，包含视觉刷新 `eb07013d119584dbd3c68012541f1355118d2b0b`。记录实际起点 SHA，保留已有修改。

隔离 Graph、工作目录、材料、profile、私有通道状态、端口和进程；不使用生产笔记或用户体验 Lab。允许本范围实现、必要验证和本地提交；不自动联系其他聊天、抓取全量对话、推送或发布。外部 Agent 流程的演练使用明确的本次任务和当前工作许可。

## 核心使用习惯

用户最在意：保留我的语气、思考过程和不确定判断。

三种作用可以协同：仅编排阅读；按指导写文本材料/处理允许范围的文件；按指导真正补充、整理笔记和维护任务。每一步要能分清它作用于哪里，但日常界面不要求用户填写协议、UUID、权限矩阵或补丁 JSON。

三种主要流程都要成立：

1. 做工作时，阶段进展顺带记录到原有任务附近，TODO 有完成依据后才完成。记录有内聚性，不把每个工具动作变为笔记。
2. 项目开始时，讨论留下少量值得继续使用的想法、条件、注意点和权衡；相同问题续写/更新原落点，避免每轮自动总结制造杂乱。
3. 用户按原习惯随手记或改内容，Agent 可先只调整阅读，也可在用户希望时整理真实格式；含义尚未清楚时继续对话，保留用户声音。

## 必须实现：让现场可继续

1. 从当前工作形成可供外部 Agent 读取的协作入口。包含真实身份/范围、已保存原文及层级/版本、已有材料与相关文件、用户当前请求、必要的选定背景、阅读方案和此次能力范围。
2. 区分已保存原文、未保存输入、派生缓存和展示编排。未保存草稿不能悄悄当成正式原文；不会为了导出现场强制结束原生编辑。
3. 复用 WORKSPACE 入口、manifest 身份和来源发布。已有用户 `WORKSPACE.md` 不被覆盖；新增必要协作信息采用兼容、可核对的演进，不另造工作身份。
4. 用户能得到易用的“带当前工作去协作”入口：用已经存在的会话关联/读取入口、必要启动语或明确选择的已知会话链接继续。没有可靠会话链接时如实处理，不编造跳转、不自动创建或联系其他聊天。
5. 实时能力与缓存事实准确。重新绑定、切换工作/Graph、撤销和卸载使旧调用失效；外部调用不能自选 actor/root/授权。提交后的未知写入通过原 requestId 查询，不换 ID 盲目重写。

## 必须实现：一处共同指导

1. 建立一份可维护的共用协作约定来源：用户语气/不确定性、记录落点与粒度、阅读和写回边界、行首格式，以及少量用户风格正反例。项目工作区仅补充差异。
2. 各工作区入口引用同一来源，或由同一来源生成带版本的派生副本。导出指明这次读取的指导版本，不要求用户在多个文件夹手工复制同一段文本。
3. 共享文件修改后，新的读取/会话能够采用新版；已有现场能判断读到旧版并重新读取。不能声称任意 Agent 会自动加载一个普通文件或当前会话即时收到全局更新。
4. 针对实际支持的 Agent 入口提供短而可用的接入说明/模板。若涉及具体 Codex 或其他产品配置，核对其真实加载机制及官方资料；不要覆盖用户全局 AGENTS.md，也不未经要求写入 Codex 记忆。
5. 用户明确编辑共同指导时才改变其维护来源。一次局部建议或临时要求不自动升级为所有项目的长期规则。

## 必须实现：材料、引用与写回

1. Agent 可按当前任务在允许的工作目录生成实际文件。复用既有材料输出与文件系统能力边界；自然材料通道不变成任意全盘写接口。
2. 文件生成后，通过目录支的同一解析/关联入口获取真实材料 ID、当前文件名和完整 `reference`。已有关联复用，不重复复制/登记。
3. 写回“详见 + 材料文件名链接”时直接使用返回的稳定引用；不得用 `[[文件名]]`、猜测路径或伪造 UUID 代替。链接点击由预览支处理。Agent 不需要操作剪贴板才能取得机器可读引用。
4. 实际补充/整理调用现有受限 `content.read/apply/result/recover/retry` 和 Journal，保留版本与作者来源。明确定义目标落点、基础版本和操作范围；用户同时改内容时旧提议不能覆盖。
5. 对同一阶段/请求的可靠重试保持幂等。真正完成的阶段变化接到已有问题/任务下面；详细产物和检索内容放材料，不自动给每次聊天创建新的总结树。
6. “只编排好读”只调用阅读支；“规范格式/补充文字”才写回。用户明确要求改写时才进行相应改写，保留可回看的旧版本。原句里的限定、理由、思考变化和重复来源不被擅自消除。

## 必须实现：普通 TODO 维护

这部分是新的能力，不能通过放宽旧正文校验来假装已经具备。

1. 保留读取/正文写作/文件写作与 TODO 状态授权的区别。用户可明确允许 Agent 维护当前工作范围内的相关普通 TODO；授权来自真实本地操作/受信入口，外部 payload 不能自行声明授权。
2. 授权限定当前工作、目标范围、允许的操作与生命周期；切换 Graph、重新绑定或撤销后失效。在用户已经允许的范围内，不为每个小任务重复弹确认。
3. 通过实际执行/核验事实更新任务状态，保留简洁的完成依据或材料链接。一个子步骤完成不自动完成事务、项目、阶段；问题和想法不自动转成 TODO。
4. 普通 TODO 与注册的正式任务/事务分别处理。正式对象状态、受管字段、任务程序和阶段认可继续走其正式端口；自然文本替换不能改写这些字段，Agent 不代用户认可阶段。
5. 撤销、权限不足、范围外、版本冲突、部分成功、Journal 未确认和结果未知均有正确结果。不会在未可靠完成时提前标 DONE。

## 统一写作格式

所有新写作的语义行首标记用双星号，如：

```markdown
- **[想法]** 我目前偏向湖边，不过还要看天气。
  - **[注]** 如果同行的人很累，就别安排必须打卡的地方。
- **[记录]** 两处交通已比较，住宿取消条件还没核对。
- TODO 核对取消条款。
```

`TODO` / `DONE` 维持 Logseq 原生语法。只有已有正式对象锚点才采用 `TODO **[任务]** ...` 等正式写法，复用 `canonical-writing.ts`；不能给普通 TODO 新增 `[任务]` / `[事务]` 以达到加粗外观。旧裸标记兼容读取。用户明确要求格式整理时，提供受范围约束的真实差异，保留正文措辞、UUID、属性、父子关系和任务状态；正式锚点/受管字段依旧走正式规范路径。代码/引文/句中字面示例不误处理。只换阅读方案绝不顺带加粗写回。

## 文件归属与依赖

你拥有 Agent 通道/CLI 的适配、工作区协作上下文、共享指导、自然正文写回和普通 TODO 授权。目录观察核心由目录支维护；阅读方案算法/校验和高亮由阅读支维护；预览/窗口由预览支维护。消费真实公开能力，不在 router 中复制模块算法。

`workspace-agent.ts` 的必要命令演进归本支，保持闭合输入、真实权限和已有兼容性。新接口与共有装配由整合支协调。先用既有 `materials.read` / 关联结果里的 `reference`；仅在易用性需要时加薄的便捷调用，不另造链接协议。

## 三条端到端验收

### 边做边记录

Agent 读取真实现场 → 写出比较文件 → 取得稳定引用 → 写回现有任务附近 → 记录一条有意义的阶段进展 → 在明确许可和完成依据下更新一个普通 TODO。用户点引用能预览。原项目仍有未决定内容和未完成任务，不能被全部标完成。

### 讨论后少量沉淀

多轮合成讨论只沉淀必要想法、条件和权衡，续接同一主题；原来的“可能 / 目前偏向 / 尚未询问”保留。新材料可关联，只有用户确实要做的行动形成 TODO。两次读取同一请求不生成重复笔记。

### 零散记录再协作

用户留下重复句、半句话、问号和新条件 → Agent 先给两个阅读方案，原文不变 → 用户明确要求格式整理后才写回 `**[标记]**` 与允许的结构调整 → 用户同时加一句造成过期提议 → 重新读取继续，用户补充仍完整在场。

另需验证：两工作区读取同一共用指导，更新一处后按版本重新读取；未授权 TODO 被拒绝，授权后普通 TODO 可按证据维护，正式对象仍不能走自然替换；断连后的结果查询与幂等恢复。

演练使用真实本机 CLI/插件/Graph/文件与既有 Journal，不能只执行模拟 router。为权限、版本、落点、格式兼容、幂等、恢复和共享指导增加必要测试。
