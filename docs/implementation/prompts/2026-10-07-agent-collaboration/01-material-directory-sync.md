使用隔离 Graph、材料、profile、端口及进程，不复用用户正在体验的 Logseq Lab。按实际 package.json 使用工具链。允许本范围修改、验证和本地提交；不推送、创建 PR、发布或再委派 Agent。

## 用户要得到的行为

材料区天然对应当前工作关联的目录。用户或 Agent 直接在文件系统中增加材料，无需再次手动导入，即可在材料区找到它。目录浏览保持真实层级：根目录只显示这一层的文件与文件夹，点文件夹进入下一层，返回保持位置。

一个工作可以有多个材料根。根的名称、来源和默认保存位置可辨认；同名文件不能被合并或混成一行。既有关联材料和历史继续可达，不因目录视图改造被藏掉。

## 必须实现

1. 以关联目录的真实一级内容作为目录视图数据。文件和文件夹分别呈现；面包屑/返回足够清楚。进入子目录才列它的下一层，不把内部所有文件常驻到上层。
2. 材料区活跃时自动发现外部新增、删除和目录变化；回到材料区、宿主重新获得焦点和进入目录时核对。优先使用宿主可用能力；需要刷新作为降级时有界、可取消、去抖，不全盘扫描。正常验收目录中的新增文件约 2 秒内可见；实际大目录边界明确显示。
3. 未登记项可先直接浏览，预览或请求引用时通过同一材料服务惰性关联。只读关联保留原件与原位置，不复制、不自动授予写权限，不按文件名/hash 合并身份。
4. 提供预览支与协作支共用的“目录文件 → 真实材料身份/引用”入口，返回现有真实 `reference`、材料 ID、当前文件名、归属与可用性。同路径合法重试幂等，不重复登记；当前路径已经失联或身份不可靠时保留旧事实并说明需核验。
5. 默认引用显示当前真实文件名，使用已有 `longdoc://` 稳定链接。覆盖包含中文、空格、括号和 Markdown 特殊字符的文件名。可靠改名延续材料 ID；自动名称同步，手写别名保留。Agent 不需要自己拼链接或扫描 `.longdoc` 元数据。
6. 多个根的重叠范围、同名文件、一个文件已有多工作关联、解除关联、默认根切换、外部原地保存和同名副本均有清楚行为。目录不可用或读取部分失败时保留已经可靠的记录、引用、文件与历史。
7. 部分读取、分页、扫描上限和截断不能被当作删除。工作/Graph 切换撤销旧监听和结果；卸载后没有监听、计时器或重复材料行残留。
8. 列表继续沿用视觉刷新：名称优先、路径按需、行内改名、覆盖菜单、就地复制反馈、稳定阅读位置。目录同步不能清掉正在编辑的文件名草稿或抢焦点。

材料根之外仍有关联的历史/外部材料时，保留一个可发现的既有关联入口；主目录内容不被历史目录缓存冒充。目录设置不改变正式 Workspace 身份，也不迁移旧文件。

## 与其他分支的边界

你拥有目录服务、观察核心、材料列表与目录 UI、稳定身份和引用名称。预览支拥有预览 renderer/窗口及字节读取；通过共同基线的预览入口委托文件打开，不复制预览代码。协作支消费你的材料解析结果，不拥有另一套登记逻辑。

`materials/controller.ts` 只对列表/目录及最小委托进行必要改动。公共组合根、公共导出和跨模块大接线交给整合支。需要接口调整时给出明确的字段与适配说明，不自行改动其他分支核心。

新生成笔记或测试正文的语义标记写为 `**[标记]**`；本支不因同步目录而批量修改 Logseq 原文。

## 关键验证

- 在真实隔离材料根用文件系统加入 `路线.md`、Word、PDF、图片、Excel 和一个两层文件夹；材料区无需手动刷新即可出现一级项，进入/返回子目录正确。
- 两个根各有同名文件；各自来源明确、身份不串。额外根失联时其他根仍可用。
- 导入、外部加入、Agent 写出的同一文件通过同一解析入口获得同一真实引用；只读角色与原件保持。
- 改名与原地修改不会破坏可靠身份；删除、同名复制、缺少文件身份、截断扫描不会错误认领或删历史。
- 刷新期间保持改名输入、列表书签和焦点；快速工作/Graph 切换及卸载后没有旧结果回流。
- 不启动 Kernel/companion，仍能浏览目录与发现外部新增文件。

对实际持久状态、文件内容、权限、身份和生命周期增加必要回归测试。按仓库完成检查；Desktop 证据要体现真实文件变化，不用假 watcher 回执代替。
