# 实施 prompt · 多格式只读预览与独立窗口

请实际实现材料阅读能力，完成代码、必要测试、打包资源、真实隔离 Desktop 验证和交接。不要把只显示元信息或“用默认应用打开”算成对应格式的内置预览。

建议分支：`codex/material-readonly-preview`。你负责读取、预览、链接打开和预览窗口；目录发现/身份由目录支提供，Agent 写作由协作支提供。

## 起点与共同要求

本 prompt 与共同约定位于仓库的 `docs/implementation/prompts/2026-10-07-agent-collaboration/`。若主工作树尚无这些文件，可从本地 `codex/workbench-visual-refresh` 分支读取同路径；不要为了取文档切换或重置用户主工作树。

先读适用 AGENTS.md、package.json、本目录 [shared-contract.md](shared-contract.md) 和整合者公布的公共接口。独立工作树从共同 `BASE_SHA` 开始，必须包含已验收视觉刷新 `eb07013d119584dbd3c68012541f1355118d2b0b`。记录实际 SHA 与工作树状态，保留用户修改。

隔离 Graph、材料、应用 profile、端口和进程；不占用用户当前 Lab 或生产应用。按实际工具链实施。允许范围内修改、本地提交和验证；不发布、推送、创建其他聊天或委派 Agent。

## 用户要得到的行为

材料默认是只读预览。Markdown、Word、图片、PDF、Excel 都能在统一阅读路径里查看；点击 Logseq 中本地文件的引用链接，先到这个预览。用户可以“放大预览”到真正独立的窗口，移动和调整窗口后仍能在 Logseq 继续写作。

材料列表点击、正文内材料链接、Logseq 原生笔记链接和 Agent 写回的稳定引用使用同一个目标解析和预览服务。链接进入预览本身不编辑、转换覆盖或保存原文件。

## 先核对现状与宿主能力

阅读材料服务、`reading-ui.ts`、`controller.ts` 的 `openDoc/openExternal`、现有稳定链接安装、`host/file-io.ts`、宿主面板机制和打包脚本。

当前 Markdown 有只读阅读和明确编辑路径，非 Markdown 主要交给默认应用；`FileIO` 尚不是完整二进制读取接口。先在实际目标 Logseq 中验证真实二进制读取和独立窗口能力，再确定 renderer 与资源方案。不能把 Lab 专属 IPC、宿主应用补丁、跨安全边界注入或测试脚本当成插件安装后具备的能力。

## 格式范围

| 格式 | 必须看得到的内容与操作 |
| --- | --- |
| `.md` / `.markdown` | 完整 Markdown、表格、列表、代码、本地图片、材料引用；沿用可靠清洗与来源 |
| `.docx` | 段落、标题、列表、表格和内嵌图片的阅读型预览；不静默丢掉主要内容 |
| PNG / JPEG / WebP / GIF | 正确图像、原始比例、尺寸、适配与缩放；说明实际动画支持 |
| `.pdf` | 多页、页码/翻页、缩放；正常中文 PDF 能读，扫描 PDF 页面能显示 |
| `.xlsx` / `.xls` / `.csv` | 工作表切换、行列位置、已保存值、合并单元格等合理呈现；大表可有明确的分页/资源边界 |

Word 核心验收为 `.docx`；旧 `.doc` 必须被正确识别并说明真实能力，不能用 `.docx` 成功替它宣称已支持。Word 预览不是逐页像素复刻 Office；Excel 预览不承担编辑或重新计算公式。未完整渲染的内容、损坏/加密/超限文件要有准确、就地的结果和可继续动作。

## 必须实现

1. 统一只读预览目标和状态：工作/材料身份或可靠本地文件来源、格式、读取版本、加载/失败/不可用、返回位置。文件内容仍只有原文件一个权威来源。
2. 从可信宿主能力读取二进制。按需扩展现有 `FileIO` 或建立可复用宿主端口，保持原文本能力兼容；不得拿 UTF-8 字符串转码冒充原二进制。目录范围验证与材料身份继续使用现有边界。
3. 为上述核心格式实现可用 renderer。新依赖核对官方文档、许可证、运行时与 Logseq 打包兼容；预览资源、worker、字体需求和样式随安装包交付，基础阅读不依赖临时 CDN 或开发服务。
4. 本地文件引用默认预览：至少覆盖插件真实 `longdoc://` 链接以及可可靠解析的 Logseq 本地资产文件链接。Graph assets 只读解析不搬移其文件，也不破坏材料根在 Graph 外的既有规则；无法确认的路径给出真实原因。页面/wiki 链接不冒充材料链接。
5. 正文文件链接点击不能同时触发阅读行的来源定位；与阅读支约定事件和路由边界。打开预览保持原生草稿、选区、中文组合输入及正文/材料书签。
6. “放大预览”打开真正独立的窗口，拥有同一材料 ID 与读取版本。窗口可移动、调尺寸、关闭，返回 Logseq 仍在原工作。只扩大右侧面板或在同一 iframe 显示模态框不算独立窗口完成。
7. 独立窗口的生命周期可靠：文件改动与失联状态真实；窗口/工作/Graph 切换不会让旧异步结果指向另一份材料；关闭/卸载释放对象 URL、worker、事件和其他资源。使用实际许可的宿主能力，不要求修改用户 Logseq 应用安装。
8. 原有 Markdown 编辑保留为单独明确动作，进入已有 Vditor、权限、草稿、冲突和保存机制。预览页面和放大窗口默认不能直接编辑原文件。
9. UI 沿用当前工作台颜色、紧凑身份区和公共菜单。以内容为主体；格式控件只出现于有需要的预览。窄面板、独立窗口、明暗主题、长名称与大表都有可用布局。

## 与其他分支的边界

目录支提供单层浏览、文件解析、可靠 ID/引用；你不能复制材料目录或另造材料身份。你拥有新预览模块、格式 renderer、二进制宿主扩展、独立窗口、本地引用解析和所需构建资源/依赖。lockfile 的预览依赖由你集中维护。

现有材料列表通过共同基线的预览入口委托打开。公共组合根与跨模块根接线归整合支，提出最小接线补丁和使用说明。材料服务变更须保持目录支契约，避免重排整个 `controller.ts`。

新生成测试笔记的语义标记用 `**[标记]**`；预览材料正文不因为展示而自动写回加粗。

## 关键验证

- 在真实隔离 Desktop，用一套中文合成文件逐一验证五类预览。Word 包含标题/表格/图片；PDF 至少多页并含扫描页；Excel 有多个 sheet、合并单元格、中文和较长表。
- 分别从材料列表、Logseq 原生稳定链接、正文里的“详见文件”链接和可解析的本地资产链接进入。展示同一目标，而不是另存的转换副本。
- 打开、缩放、翻页/换 sheet、放大独立窗口、关闭、返回正文，验证原文件字节和编辑草稿没有被预览改动。
- 文件被外部修改、改名、删除、拒绝读取或损坏时，旧预览不冒充当前有效版本；提示不把列表和原生输入推乱。
- 安装包解压到仓库外，在没有开发服务器的隔离实例加载，验证资源/worker 真的可用。
- 为字节保真、目标解析、格式分派、作用域失效和资源释放增加必要回归；不要只测某个库能解析样例。

真实独立窗口、真实引用点击和离线安装包是核心验收。若宿主能力存在阻碍，先实现可审查的能力验证和实际替代方案，准确报告缺口，不将同面板放大或外部应用打开标成满足本要求。
