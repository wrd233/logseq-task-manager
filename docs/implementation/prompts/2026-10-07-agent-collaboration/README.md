## 并行和汇合

1. 在远端成功获取这次资料提交，记录完整 `BASE_SHA`。A、B 都从同一个提交开始；不能各自追随不同时间的 main。
2. 两支先读共同约定，再按自己的 prompt 实施。共同约定先固定操作语义和归属，不要求另一个 Agent 先实现公共框架。
3. A 负责材料服务、列表、预览、字节读取和相关依赖；B 负责阅读、Agent、写回及最终组合。两支都能增加必要的最小本地接线，避免大面积重排公共文件。
4. B 在 A 就绪前完成阅读、协作、共享指导、权限和合成验收资料；材料引用先复用已有真实 `reference` 能力。新材料能力经窄的适配入口消费，不复制实现、不把永久 mock 当成完成。
5. A 给出完整提交和 handoff，B 在自己的分支合入这个已核对的提交，接通所有入口，解决冲突并重新验收最终安装包。另一台电脑上的提交需先通过用户授权的远端或文件交付方式取得。

这批资料的推送不自动替未来实施授权再次推送、合入 main 或发布。两份 prompt 默认允许隔离实施、必要验证和本地提交；B 额外允许在自己的实施分支合并 A。人类后续指令覆盖这些默认范围。

## 必须共同保留的决定

- Logseq 原文、材料文件、阅读方案各有权威来源。阅读文字来自原句，Agent 调整排布和聚合；标题也不能把“可能”变成“已决定”。
- 点击正文高亮来源及后代；点击“目标”等标题高亮其全部相关来源及必要上下文。文件链接进入预览，文本选择保持可用。
- 材料根默认显示当前层的文件和文件夹；进入文件夹再读下一层。用户直接加入文件，材料区自然发现。
- 文件链接默认只读预览；放大进入独立窗口。原有 Markdown 编辑是单独动作。
- Agent 可以写实际文件、取得真实文件名链接，并按用户要求补充笔记和维护范围内获授权的普通 TODO。
- 记录围绕问题、主题、任务及有价值的阶段变化增长；详细材料放文件，避免每次对话都增加总结树。
- 保留用户的语气、思考过程、权衡、重复来源和不确定判断。
- 语义行首标记用 `**[目标]**`、`**[想法]**`、`**[注]**` 等。普通待办仍为 `TODO 核对住宿`；已有正式锚点才使用 `TODO **[任务]** ...`。只换读法不写回格式。
- 共用指导一处维护，项目只写差异。各 Agent 入口明确读取与版本，当前会话不会因为文件改了就自动重载。

## 最终交付口径

A 交付可用材料能力及真实验证，B 交付自己的能力并完成两支联调。最终必须走通“目录加入文件 → Agent 获取引用并写笔记 → 原生点击预览/独立窗口 → 读法切换/集合高亮 → 有依据的阶段记录与 TODO → 并发编辑恢复 → 两工作区加载同一指导版本”。

安装包、真实行为、格式矩阵、检查结果和未实测范围共同构成交付；交互演示和单个解析器成功不能替代实际插件验收。完整要求见两份 prompt 和共同约定。
