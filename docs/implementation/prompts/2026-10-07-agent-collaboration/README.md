## 怎样开始

1. 先执行整合 prompt 的“共同基线准备”。它核对现状、固定必要接口和扩展点，提交共同基础，公布完整 `BASE_SHA`。这一步只做小规模准备，不提前实现四支功能。
2. 四条功能分支从同一个 `BASE_SHA` 建立自己的工作树并行实施。每份 prompt 都要求读取[共同约定](shared-contract.md)，保持同一组来源、材料身份和版本含义。
3. 整合分支同时准备合成 Graph、验收资料和跨模块检查；功能分支完成后，再合并和验证完整路径。
4. 若一个接口确实需要调整，由整合分支组织一次共享修订。功能分支不各自创造第二套材料 ID、阅读方案或写回授权。

“并行”不要求各分支在接口未定时同时修改核心文件。先把共用的地基对齐，后面的并行才有价值。

## 共同采用的产品决定

- Logseq 原文是笔记权威；文件是材料正文权威；阅读方案仅描述读法。这三者可以协作，但不能互相冒充。
- 阅读方案从来源取文字。Agent 可以决定聚合、顺序、对照和布局，也可以生成明确属于阅读层的小标题；不能悄悄改写原句，或把“可能”包装成“已决定”。
- 点击一段正文，高亮该段及其下属内容；点击小标题，高亮该组实际引用的块及必要上下文。高亮不等于进入编辑，也不等于允许写回。
- 材料根目录直接显示一级文件和文件夹；进入文件夹再显示其下一层内容。多个关联目录保留可辨认的来源。
- 文件引用的默认动作是只读预览；“放大预览”进入真正独立的窗口。Markdown 的已有明确编辑能力仍通过单独编辑动作进入。
- Agent 记录围绕已有问题、主题、任务和有意义的阶段变化增长。详细产物放文件；不按每次对话、工具调用或搜索生成一条永久笔记。
- 保留用户的语气、思考过程、权衡、重复记录和不确定判断。没有决定的内容继续作为想法或问题。
- 语义行首标记统一写为 `**[目标]**`、`**[想法]**`、`**[注]**` 等。已有正式任务锚点采用 `TODO **[任务]** ...`；普通待办继续采用 `TODO 核对住宿`，不能为了统一外观新增正式对象标签。`TODO` / `DONE` 不包在星号里，旧裸标记仍可读取。

## 支持格式的验收口径

| 类别 | 本轮核心格式 | 必须说明的边界 |
| --- | --- | --- |
| Markdown | `.md`、`.markdown` | 正文、表格、代码、材料引用、本地图片 |
| Word | `.docx` | 保留段落、标题、列表、表格与内嵌图片；是阅读预览，不承诺 Office 的逐页像素复刻。旧 `.doc` 必须明确识别实际能力，不计作已支持 |
| 图片 | PNG、JPEG、WebP、GIF | 缩放、原始比例、尺寸；实际格式能力如实说明 |
| PDF | `.pdf` | 多页、缩放、页码；加密、损坏或资源超限有就地反馈 |
| Excel | `.xlsx`、`.xls`、`.csv` | 工作表切换、行列位置、已保存值及合理表格呈现；不承担编辑和公式计算 |

## 最终必须走通的闭环

1. 用户直接向关联目录加入文件，材料区自动出现；进入文件夹能看到内部文件，返回位置稳定。
2. Agent 在允许的工作目录写出文件，获取真实材料引用，将“详见 + 带文件名的链接”写回原有任务附近。
3. 用户点击 Logseq 中的这个链接，进入同一个只读预览；放大到独立窗口，关闭后继续原来的工作。
4. 用户原文仍保留“可能”“不过”“先不急着定”；Agent 的两种阅读编排都能展示完整文字，点击标题和正文能正确高亮来源。
5. 阶段记录和获授权的普通 TODO 围绕现有任务增长；没有完成证据的任务与尚未决定的项目继续保持原状态。
6. 用户同时补充笔记时，过时的写回不能覆盖新内容；重新读取后继续。切换工作或 Graph 后，旧结果不会串到新现场。
7. 修改一处共享约定，两个工作区通过各自入口重新读取后使用同一版本；项目补充各自保留。

## 交付与范围

各支交付代码、必要的针对性测试、真实能力证明和简明 handoff；整合支完成全量检查、插件安装包及完整 Desktop 证据。允许本地隔离工作树、修改、验证和清楚的本地提交。推送、PR、合入用户主分支或发布另按用户后续指令。

优先复用现有暖灰、纸面和青绿色工作台。新增界面继续像 Logseq 中的阅读与材料体验，避免为了展示内部接口把产品变成技术控制台。
