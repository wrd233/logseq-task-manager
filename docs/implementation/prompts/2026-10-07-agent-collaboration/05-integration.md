3. 固定必要的新类型、能力和扩展点：单层目录浏览/材料解析；统一只读预览目标与打开入口；版本化阅读方案/来源集合；Agent 协作现场及普通 TODO 许可的接入位置。新增名字标明属于本轮，不把旧 FocusPlan 直接冒充自由布局。
4. 给共享大文件约定清楚归属，准备最小非破坏性装配扩展点，使各支能接入并做真实局部演练。公共骨架不能改变现有默认行为，也不能用永久 mock 代替后续接线。
5. 在 `docs/implementation/agent-collaboration-common-baseline.md` 记录类型/操作、文件所有者、依赖、可执行起步方式及已确认宿主能力。提交后向用户汇报完整 `BASE_SHA`，四支从这一 SHA 开始。

这一步的完成不意味着总任务完成。其余功能还未就绪时，继续准备合成 Graph、格式样例、跨模块断言、隔离启动和交付流程；准确报告尚需哪些功能提交。

## 并行期间

- 目录支拥有材料目录服务、观察核心、列表和引用名称；预览支拥有 renderer/字节读取/独立窗口及预览依赖；阅读支拥有方案与高亮；协作支拥有 Agent 通道适配/指导/写回/普通 TODO。
- 你拥有公共组合根、导出、共享视觉和最终装配。不要与功能支同时大改其主要实现文件。
- 必要接口变更集中形成一次可追踪的公共修订，明确适配影响。读取各支本地提交和 handoff；协调信息通过共享文档/用户给出的提交收集，不擅自联系其他会话。
- 分支完成的真实模块应能通过共同扩展点验证。试验入口不残留到最终用户界面；最终包不允许依赖开发服务器、只在工作树存在的路径或 Lab 专属 IPC。

## 最终整合顺序

1. 整合目录支，核对一级浏览、自然同步、ID/引用和失联事实。
2. 整合预览支，接通材料列表、原生文件引用与独立窗口。
3. 整合阅读支，接通方案、正文点击/标题集合高亮、材料点击和书签。
4. 整合协作支，接通真实现场、共用指导、生成文件引用、笔记落点和获授权的普通 TODO。
5. 解决接口、依赖、命令、类型和 UI 冲突；按最终行为重写指南与交接。不要为冲突把某支新行为退回旧打开/旧平铺列表。

一个已存在模块可以提前整合；顺序表示最终接线依赖，不要求其他支在此期间停止独立工作。

## 最终产品必须成立

- Logseq 原生编辑仍是日常笔记入口；工作台提供完整原文的自由阅读编排。
- 点击正文高亮该来源及后代；点击小标题高亮整组实际来源。文件链接默认只读预览，不兼触发高亮或进入正文编辑。
- 材料区直接同步关联目录的一级内容，文件夹逐层进入；不启动 Agent/Kernel 也可使用目录和预览。
- Markdown、Word、图片、PDF、Excel 按已核实格式矩阵阅读。放大是真正独立窗口；关闭后仍保留笔记和阅读位置。
- Agent 可写实际文件、取得真实带文件名引用、按用户要求写回现有主题/任务附近；不会每轮创建一份总结。
- 用户语气、思考过程、不确定性、条件与重复来源保留。任务完成要有依据；未授权 TODO 和正式字段保持受保护。
- 共用指导一处维护，各工作区通过各自入口读取/标明版本，项目差异不被覆盖。
- 新写作的语义行首标记都是 `**[标记]**`；原生 TODO/DONE 语法保持。旧裸标记仍可读，只编排阅读不触发格式写回。
- 原文、文件、阅读方案、历史和阶段认可的身份/版本不混淆。并发编辑、断连、范围切换和迟到结果没有静默覆盖或串工作。

## 共同验收资料

准备一套所有支共用的合成资料：长原文不少于 80 块、约 4,000 个中文字符、三至四层关系、普通 TODO、正式对象边界、重复句、未知/裸/加粗标记、条件、反例、代码、引文和材料链接；两个材料根、同名文件、嵌套目录；五类中文文件。

另准备三个较短的工作过程样例：边做边记录、讨论后沉淀、零散记录再协作。内容应使用用户习惯，而不是替换成正式方案文风。样例均不含用户生产内容。

## 真实跨模块验收矩阵

| 路径 | 要核对的结果 |
| --- | --- |
| 文件系统加入文件 → 材料区 | 活跃界面自动出现一级项，文件夹进入/返回正确；同名不合并 |
| Agent 写文件 → 取引用 → 写笔记 | 同一个真实材料 ID，完整服务生成 reference，落在原有任务附近；重试不重复 |
| 原生 Logseq 链接 → 预览 → 独立窗口 | 五类文件能读；目标和版本一致；关闭后原生输入和书签保留 |
| 两阅读方案 ↔ 原结构 | 逐来源核对原句与上下文，Graph 原始内容/层级/版本不被读法修改 |
| 点段落 / 点标题 | 真实原生高亮集合准确，包含应有后代；链接点击不触发高亮 |
| 原文发生同时编辑 | 旧方案/写回失效；新补充、光标、草稿、条件仍在；重读后继续 |
| 普通 TODO 的许可与完成 | 未许可被拒绝；许可范围内有据维护；子项完成不推断整个工作完成 |
| 正式任务 / 阶段 | 自然正文路径不越权；Agent 不能代用户认可 |
| 共享指导修改 | 一处维护、两个入口读取同一新版；旧现场能显示/刷新版本，项目补充保留 |
| 改名、失联、根/Graph 切换 | 可靠 ID/旧引用保留；迟到结果不进入新工作，窗口和监听被正确清理 |
| 打包后的独立运行 | 解压包在仓库外运行，资源/worker/预览/通道可用，没有开发路径依赖 |

所有“通过”都提供对应事实；未知结果、只验证解析器、仅 HTML 截图和 Lab 注入不得记为通过。物理 IME、Finder 拖入、跨应用剪贴板和其他平台如未实测，明确列出，不借 UI 截图扩大证明范围。

## 检查与交付

整合后执行仓库所要求的完整检查，至少 `npm run check` 和 `npm run package:plugin`。在最终安装包解压实例重新跑核心闭环；记录包与实际运行文件的身份/hash，避免源码正确而安装包旧。

交付：

- 清楚的本地整合提交及四支完整 SHA/共同基线。
- 可加载的最终插件 ZIP、实际格式能力矩阵与真实 Desktop 证据。
- `docs/implementation/agent-collaboration-integration-handoff.md`：最终结果、接口归属、检查结果、完整验收矩阵、剩余限制。
- 更新用户指南：进入工作、带现场去协作、记录粒度、文件引用/只读预览/放大、切换读法/定位、维护普通 TODO、共用指导与恢复。

最终报告围绕用户能做成什么、如何验证及尚存的真实限制。不能以四支都报告完成代替你自己的端到端核验，也不能承诺所有格式、平台和竞态已经“完美”解决。
