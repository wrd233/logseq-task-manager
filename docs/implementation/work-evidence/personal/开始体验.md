# 个人真实体验

双击本 Worktree 的 `apps/dsh-plugin/scripts/work-evidence-experience.command`，选 **1 启动 / 继续**。终端自动找到本机 Node 24，缺少本地依赖时用已检查的 Node 20 安装；每次启动由原 playground 构建真实独立 bundle。未安装 Node 或官方 DSH 时会说明缺项，不改变全局运行时。

浏览器首次出现“预览版说明”点继续。“开始使用”可先关闭，不需要 Key 就能观察和整理交接。点击输入框上方 **工作变化**。菜单 **3 查看状态**给出本轮样例目录，复制到“明确选择 Git 根目录”，点“选择目录”。这不会选择 DSH 执行工作区；保留默认工作区即可。

## 按点击顺序体验

1. 点 **同步一下我刚才做的事**：首次是干净检查点、0 个新提交。回到菜单选 **2 生成样例变化**，再在页面同步。应看到 1 个新提交、5 个当前变化条目；`work.txt` 同时带提交与工作区来源，不重复堆成三份文件。
2. 展开 `work.txt` 的 **差异与依据**，依次点提交、暂存差异、未暂存差异。分别是 3 次重试、改为 5 次、再加 10 秒超时。另有重命名、删除、未跟踪文件和合成 `.env` 元数据。未跟踪正文不自动读取，敏感正文受限；这些全是本轮合成内容。
3. 需要真实分析时，在这个独立 DSH 中自行添加 API Key / 登录，并从原生模型选择器选模型。未配置时分析不可用，观察、Diff、交接和草稿引用仍可用。展开 **分析范围与相关上下文**：会将所选文件的有限提交/工作区 Diff、Git 元数据、已保存意图及用户回答发给当前模型的供应商。会参考同轮已有解释的主题；默认不读取 DSH 历史或 Logseq。确认接受后才勾选 **允许使用当前 DSH 模型分析本轮来源**，再点该文件 **分析此条**。应看到局部进度、解释和主题；解释不是测试通过证明。
4. 如果模型提出关键问题，回答“本例先尝试降低偶发失败，尚未运行测试，最终超时值未定”，点 **保存回答并局部更新**。只有该条重分析；可比较另一文件解释未变。用户说明独立保存。若没提问，可用 **补充或修订理解**完成同类操作。
5. 分析另一条，如果有问题，选 **跳过这个问题**。交接仍应保留未知。样例刻意缺少重试/删除目的与验证结果，但真实模型不保证提问；没有问题时如实记为本次未覆盖，不能伪造问题或结果。
6. 随时点 **整理交接草稿**，核对未知、编辑、保存。展开 **已保存交接 → 重新打开交接**；点 **修订这份交接**修改再保存，应新增一版而非覆盖原版。无需模型也能完成。
7. 先在 DSH 原生输入框写一句自己的前缀。历史交接点 **准备交接引用**，查看预览，再 **确认插入原生草稿**。应追加记录 ID/哈希引用，前缀保留，聊天不出现已发送消息。不要点击发送，除非你自己决定。
8. 切换 **结构关系**，选择 `work.txt` 应展开同一文件、同一 Diff 依据；再回 **条目列表**。结构是本轮文件/主题关系，不是结构历史回放。
9. 在“我的意图”留一句未保存文字后刷新页面，允许浏览器重载警告。应恢复文字、观察、交接历史和未发送原生草稿。菜单选 **4 停止**，再 **1 继续**，保持同一地址。回到原标签页刷新，若出现“开始使用”可关闭；核对同样内容仍在。

## 最少操作与恢复

- 菜单 1：启动/继续并打开浏览器；3：地址、目录、运行身份；4：仅停止当前自有运行，保留全部记录；5：停止当前自有运行并创建干净新样例、打开新 profile，旧记录和仓库全部保留。0 只退出菜单，不停服务。
- 样例变化只生成一次。重复选 2 会拒绝，保护当前体验现场；需要重做完整流程选 5，新页面先同步再生成变化。重置是新运行，不迁移浏览器未保存输入或模型配置。
- 终端也可运行 `apps/dsh-plugin/scripts/work-evidence-experience.command start|stop|status|change|reset`（一次选一个参数）。不需输入运行编号。不要用日常 web profile 的通用插件安装命令。
- 历史运行编号和路径在 `tmp/work-evidence-ux/run-*/owned.json`。高级恢复某个旧运行可使用原 playground 的 `start RUN_ID`；先确认该运行已停止。个人菜单只控制最新个人运行。
- 地址端口被占用：启动明确失败，不能接管别人的服务。保留旧运行记录，选 5 建立新地址；原浏览器临时输入不会迁移，应先复制。
- 分析失败：保留已保存说明和旧解释，检查模型配置/范围后主动重试。不要把“待更新”当作完成。旧 Diff 报来源变化时，重新同步查看当前来源，旧记录仍可查。

## 可选故障演练（另建运行）

默认个人体验运行不用故障 bundle。高级演练在本 Worktree 用已核实的 Node 24 运行原 `work-evidence-playground.mjs new --clean`，记录它返回的新编号，再 `start 新编号 --faults`。后续每条命令均使用同一个 `node --import tsx apps/dsh-plugin/scripts/work-evidence-playground.mjs` 前缀，例如 `node --import tsx apps/dsh-plugin/scripts/work-evidence-playground.mjs start 新编号 --faults`。在这个独立页面建立观察和输入，再用 `pause 新编号`、`lose-receipt 新编号`、`release 新编号`、`normal 新编号`演练回执丢失；原请求重试应核对记录而非双写。`corrupt 新编号`只破坏该自有仓库的一条观察，`repair 新编号`恢复备份；不要在真实项目或默认个人运行执行。最后 `stop 新编号`。不明进程或变更过的备份会拒绝操作。

最简单的受控失败是菜单停止宿主后在原页面操作保存：失败时保留输入；继续启动后重试核对回执。正式记录以保存回执为准。浏览器临时输入不跨运行、设备或浏览器迁移。

真实 Logseq 与已有 DSH 会话仅作进阶体验：没有精确目录匹配的已有可信连接/授权时不可用，不建立绑定，不写 Graph/Kernel。没有完整文件快照或按内容精确去重；历史 Diff 可能失效。模型配置只留在本轮 profile，不从日常配置复制密钥。
