# 项目工作区与 Agent 协作：阶段性需求整理

整理日期：2026-10-01。本文汇总本轮关于笔记、文件、Agent 对话、动态渲染与上层任务系统的讨论，作为阶段性需求基线；它描述目标形态，不代表现有实现已经覆盖，末尾保留尚待明确的设计选择。

我们最终要做的是一个**以笔记中的任务块为入口、以本地文件夹为成果工作区、由你和 agent 共同维护的项目协作系统**。一个中等规模任务可以关联页面、零散笔记块、参考文件、成果文件和多轮 agent 对话；这些材料保留各自的存放位置，同时共同指向同一件工作。你可以直接与 agent 交流，也可以在笔记中自由修改和补充，项目的连续性由这些关联和共享记录维持。

这个系统持续维护一份**准确、简洁、能够帮助重新进入项目的当前理解**：项目要解决什么、已经做到什么、哪些结果经过验证、哪些选择已经确定、还有什么问题，以及现在可以做什么。agent 自动建立文件与笔记的关联，并随着工作推进更新记录。记录采用你认可的写作和组织风格，保留必要的背景、理由、条件与依据，让你和新接入的 agent 都能据此继续工作。

渲染层与原始笔记使用同一组内容，**原始笔记本身保持可读、可编辑，渲染层帮助你安排注意力**。页面可以使用带标注的自然段，也可以适时使用分点；当你提出问题时，它在保留熟悉结构的前提下收紧内容，突出足以支持判断的依据、限制和未决问题。你能从笔记本身看懂 agent 的建议，并随时恢复完整上下文。

你与 agent 协作时，页面清晰呈现每次有意义的变化，你可以在对应位置直接修改、提出批注或接受新表述。**文件、想法、决策和成果不断进入项目，项目又持续向上层任务系统提供当前可执行的动作、等待条件和跨任务依赖**。技能负责稳定写作与维护规则，工具和界面负责可靠读写、定位、版本对应和交互；Git 等历史机制按工作区特点使用。

- **持续的项目身份与双向关联：工作需要跨笔记、文件和对话连续存在，并在更换会话或 agent 后仍能继续推进。**

  - 默认以一个笔记任务块和一个本地文件夹建立中等规模项目。
  - 项目可以关联页面、子块、日记中的零散记录及其他位置的相关材料。
  - 关联材料可以保留原有存放结构，通过引用共同归属于项目。
  - 项目身份应能承受任务改名、文件夹移动和对话更换。
  - 一个项目可以关联多轮对话和多个 agent 的工作记录。
  - 一次对话涉及多个项目时，应能区分内容的项目归属。
  - 从任务入口可以找到工作文件夹、具体成果及相关对话。
  - 从 agent 对话可以回到任务入口、需求来源和成果位置。
  - 关联应表达材料的角色，例如目标、参考、决策、产出和历史。
  - 在笔记软件支持的范围内，引用应能定位到具体块或有意义的内容片段。

- **可信的共享项目状态：你和 agent 需要依据同一份准确的当前理解开展工作，并能分清事实、意图、推断和未决事项。**

  - 状态应覆盖当前目标、范围、必要背景、成果、验证、决策、问题和依赖。
  - 状态维度可以随项目类型调整，例如研究重视证据，写作重视论点，开发重视实现与验证。
  - “已实现”“已运行”“已验证”和“满足要求”应分别表达。
  - 用户随想、agent 建议、已确认选择和已验证事实应保持清楚的身份。
  - 重要状态描述应能追溯到成果文件、验证结果、笔记或相关讨论。
  - 选型记录应保留当前选择、关键理由、适用条件及需要重新考虑的条件。
  - 对未来判断有影响的失败尝试应保留结论与来源。
  - 当前状态变化后，应更新现有表述，并把旧状态留入历史。
  - 会影响项目理解的新输入应被处理，或明确保留为待处理事项。
  - 信息不足时应明确指出缺口，并避免把推测写成确定结论。

- **低成本重入与高价值阅读：人的注意力有限，项目入口应帮助你迅速恢复理解并作出判断。**

  - 重入记录应回答在做什么、有什么可用成果、哪些选择已定、哪里受阻以及现在能做什么。
  - 首页内容应能够改变读者对当前状态、既有选择或下一步的判断。
  - 入口保持简短，完整背景、历史和依据通过引用或展开获得。
  - 常规操作过程可以留在对话或执行记录中。
  - 阅读形式根据内容关系选择，自然段用于因果与权衡，分点用于并列、步骤和比较。
  - 自然段可以用少量加粗或标注突出选择、条件和关键变化。
  - 表达应避免空泛总结、重复背景和缺乏依据的进展描述。
  - 模仿你的风格应同时学习信息选择、判断组织、措辞和标注习惯。
  - 写作规则应依据你认可的真实笔记样本建立。
  - 短记录仍需保留影响判断的条件和不确定性。

- **自由表达与持续整理共存：你需要随手记录想法，也需要项目正文持续清楚，两者应能共同存在。**

  - 允许直接在笔记中添加零散、暂不完整或尚未确定的想法。
  - 新想法可以挂在相关内容旁，也可以暂时放在轻量的补充位置。
  - agent 应先理解输入的含义、归属和潜在影响，再决定怎样整理。
  - “读到”“理解”和“采纳”一个想法应被分别处理。
  - 原始表达应能追溯，以便检查整理是否保留了你的意思。
  - 可以自动关联材料、合并重复信息和提出更清楚的表述。
  - 涉及目标改变、优先级调整或选择确认时，应依据明确意图更新项目。
  - 影响当前判断的内容进入正文，未确定的内容保留为问题，处理完的内容可以收起。
  - 重要输入的处理结果应可见，同时减少逐条管理随想的负担。

- **agent 持续维护上下文：共享记录需要随实际工作变化，并成为每轮协作的起点。**

  - 开始工作时读取当前项目状态，以及新增的想法、批注和材料。
  - 先读取足以理解当前任务的内容，再按需深入查看依据与历史。
  - 确认选择、验证成果、发现问题或依赖时，更新对应记录。
  - 写入围绕有意义的状态变化进行，并优先维护现有内容。
  - 每次回写前读取最新内容，避免覆盖你刚刚进行的修改。
  - 已经在对话中明确确认的内容，应准确接回项目记录。
  - 不同对话和 agent 可以利用共享记录承接前一轮工作。
  - 工作结束后应能找到最新成果、仍待处理的问题和可继续推进的动作。

- **原始笔记与渲染层保持一致：同一份内容应支持直接阅读、渲染阅读和可靠编辑。**

  - 原始笔记本身应达到直接打开仍能看懂项目的标准。
  - 当前状态、批注、原始想法和历史应有清楚的归属。
  - 同一项当前事实应有明确的维护来源，减少多个可编辑副本之间的漂移。
  - 渲染层可以重新安排呈现方式，但应保留内容来源和语义。
  - 渲染层中的修改必须能够准确定位并写回原始内容。
  - 原始笔记的修改应反映到渲染层和 agent 读取的上下文中。
  - 内部组织粒度、页面呈现粒度和修改粒度可以不同。
  - 一个自然段可以整体阅读，同时支持对其中具体句子提出意见。
  - 筛选、折叠和高亮属于视图变化，应与修改正文明确区分。

- **按问题聚焦判断：页面应根据当前问题减少阅读量，并保留足以支持判断的信息。**

  - 支持通过表达问题或明确操作进入聚焦视图。
  - 聚焦问题可以包括下一步、阻塞原因、选型依据和待定事项。
  - 页面可以隐藏无关结构和条目，同时保留相关内容的原有标题、顺序及位置关系。
  - 显示数量由问题和材料决定。
  - “紧缩”动画应帮助理解哪些内容被收起、哪些内容成为焦点。
  - 被隐藏内容应有轻量的恢复入口，允许返回完整上下文。
  - 最小呈现应保留关键依据、限制条件、反例和不确定性。
  - 应先识别影响判断的材料，再形成建议。
  - 信息不足时，应展示影响判断的缺口。
  - 剪枝应保留语义完整性，必要时保留整段并突出关键句。
  - 页面应区分原文内容、对原文的归纳和新增推断。
  - 必要时允许用简短连接语说明材料怎样支持建议。

- **可见、可纠正的共同编辑：agent 的更新应让你容易察觉、理解和反馈。**

  - 渲染层应突出新增或改变的状态、决策、问题和依赖。
  - 写入应围绕可理解、可评价的变化进行。
  - 局部变化应优先通过局部更新呈现。
  - 点击相关内容后，可以直接修改原文、提出批注或接受新表述。
  - 直接修改应改变当前内容，批注则保留为待讨论或待调整输入。
  - 修改重要选择后，应检查受到影响的计划、依赖和行动建议。
  - 常规事实更新可以直接记录并标示变化。
  - 已在对话中确认的选择无需重复决策，新提出的建议应保持建议身份。
  - “检查表述”“确认已阅”和“采纳建议”的含义应清楚。
  - 审阅期间应尽量保持布局稳定，其他变化通过提示呈现。
  - 隐藏区域发生重要变化时，应提供可发现的入口。
  - 批注和直接修改应成为 agent 下一轮工作的明确输入。

- **顺畅的文件进入与成果关联：你应能自然地把资料或自行完成的成果加入工作区，并让它们进入项目理解。**

  - 可以直接向工作文件夹添加文件。
  - 文件进入时不应强制要求先完成命名、分类和说明。
  - agent 应识别新文件并判断它与当前任务的关系。
  - 文件角色可以包括参考资料、草稿、可用成果和替换版本。
  - 能从内容和上下文判断用途时自动关联，有实质歧义时再确认。
  - agent 产生的成果也应自动关联回任务入口。
  - 新文件可能改变项目状态和下一步，系统应据此检查当前判断。
  - 判断成果是否可用应结合项目目标和实际检查结果。

- **可追溯的工作历史：后续重入需要知道成果怎样变化，以及当时为什么这样推进。**

  - 保留重要成果版本与关键决策历史，并建立两者的联系。
  - 保留相关对话入口和有长期价值的讨论片段。
  - 当前页面维护最新理解，历史内容可以按需追溯。
  - Git 是否启用应根据工作区内容特点选择。
  - 倾向于文本、代码和配置为主的工作区默认使用本地 Git。
  - 二进制大文件为主的工作区可以按需启用 Git，或主要跟踪说明、清单和决策。
  - 已有 Git 的工作区沿用现有历史。
  - 提交宜对应可解释的阶段，例如确认方案、形成可用稿或完成验证。
  - 笔记位于独立笔记库时，应关联当时的笔记状态或历史快照。

- **从状态推导可执行动作：任务系统应持续帮助你掌握当前可以动手的行为。**

  - 动作应由目标、成果、问题和依赖共同推导。
  - 每个动作应足以判断由谁执行、需要什么输入以及怎样算完成。
  - 动作可以是执行、确认选择、补充信息、验证成果或协调其他任务。
  - 区分当前可执行动作、正在处理的动作和仍在等待条件的事项。
  - 等待事项应说明等待什么，以及什么变化会使工作重新可推进。
  - 可以保留多个可执行动作，并给出一个优先建议。
  - 允许你根据时间、精力和外部条件选择其他可执行动作。
  - agent 可以继续执行的工作，与需要你参与的工作应分别呈现。
  - 工作状态变化后，应重新检查行动建议是否仍然成立。

- **跨项目协调与建议依据：上层任务系统需要结合多个项目的就绪状态，帮助你选择当前关注的工作。**

  - 项目应向上提供可执行动作、阻塞条件及可供其他任务使用的成果。
  - 支持表达一个项目对另一个项目的输入、输出和依赖关系。
  - 新成果出现或依赖解除时，应能识别其他项目新近可执行的动作。
  - 上层优先建议应结合整体安排、资源和外部条件。
  - 局部 agent 的候选建议应与跨项目综合判断清楚衔接。
  - 任务总览可以显示少量动作，并允许进入对应项目查看依据。
  - 建议背景优先通过项目面板的选择性渲染展示。
  - 新推导的建议应明确标识，并在必要时补充简短理由。

- **可复用的技能与可靠工具：稳定的协作方式需要明确规则，也需要工具保证规则能够落实。**

  - 建立写作与组织 skill，约束信息选择、段落与分点、理由表达、标注和不确定性处理。
  - 建立项目维护 skill，约束新输入处理、状态更新、过时内容整理和依据保留。
  - 建立判断与建议 skill，约束可行动作推导及相关材料选择。
  - skill 应包含你认可的真实样本，并根据实际反馈调整。
  - 工具负责可靠读写、内容定位、版本对应和精确回写。
  - 界面负责聚焦、动画、高亮、展开和反馈交互。
  - 明确区分 agent 的判断职责与工具必须保证的确定性行为。

- **以实际使用检验质量：整理质量应通过重入、判断和继续工作的效果验证。**

  - 离开项目一段时间后，应能仅凭入口迅速恢复关键理解。
  - 新接入的 agent 应能依据共享记录继续工作。
  - 重要判断应能找到依据，并检查记录是否准确。
  - 你应能在页面中发现误解，并用局部修改或批注纠正。
  - 聚焦视图应帮助作出判断，同时允许检查被隐藏的内容。
  - 每轮更新应容易检查，且不会持续扩大入口的阅读负担。
  - 先用真实项目验证记录、重入与行动建议，再逐步完善自动关联和动态交互。

- **仍需明确的设计选择：以下事项已有方向，但尚需结合真实使用确定。**

  - 自动整理随想的深度，以及什么情况下保留、归纳或转入正文。
  - 原始笔记中正文、批注、补充输入和历史的具体组织方式。
  - “接受”在不同内容类型下的含义，以及哪些更新需要确认。
  - 项目入口的默认内容、篇幅和标注方式。
  - 不同问题下的聚焦规则，以及新变化何时触发重新筛选。
  - Git 的适用范围、提交时机，以及笔记与成果历史的关联方式。
  - 多个可执行动作之间的优先建议规则，以及上层任务系统参与判断的范围。
