# Evidence and Skill Contract

Frozen Evidence is durable, target-bound, and auditable. The Plugin asks the Graph Adapter to read the selected block; the adapter returns graph identity, locator, canonical content, 8-hex source snapshot hash, and an HMAC proof made with the descriptor's separate Graph-snapshot capability. The Kernel verifies that proof before it accepts the identity or content, verifies the target Graph, and computes the strong digest itself. Possession of the HTTP bearer token alone is insufficient to forge Evidence. A durable record contains its own ID, WorkObject ID, `LOGSEQ_BLOCK` type, Graph ID, block UUID, canonical frozen content, SHA-256 content hash, freeze time, and locator; it never stores the proof capability. The 64-lowercase-hex Evidence hash is never interchangeable with the portable 8-hex managed projection hash.

Application requires another proof-bound fresh block read. Both freeze and apply canonicalize before SHA-256, so CRLF or removable Logseq `id::` representation differences do not make unchanged Evidence stale. Missing Evidence, invalid proof, locator mismatch, changed canonical content, or digest mismatch invalidates the Proposal before a Commit is inserted; the Ledger and current state remain unchanged.

The versioned Skill package lives at `skills/current-focus-maintenance/0.1.0/` and contains a manifest, policy, output schema, examples, and eval cases. Phase 3 pins the release-approved tuple, including exact content hash `ae5fec61a120cfe294f191e1ae37a61f008ac7868be232e6d814189211788813`; a modified package carrying the same ID/version is rejected even on a fresh database. SQLite also registers `(id, version, contentHash)` and refuses later in-place mutation. A Skill constrains output but cannot authorize itself: authorization also requires the exact operation and contract version, configured Agent identity, `LOW` risk, valid Proposal, target/projection/Evidence freshness, and no recovery item.
