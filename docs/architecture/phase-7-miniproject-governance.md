# Phase 7 MiniProject Governance

Phase 7 proves a light multi-round governance loop over one Formal MiniProject:

```text
bootstrap -> Skill + provisional Taste -> locate one target -> bounded reads/Evidence
-> one recommendation-first bottleneck -> one narrow reversible change -> verify
-> next-turn light notice -> stop when no question has enough value
```

The seven diagnostic dimensions are outcome clarity, completion boundary, current actionability, dependency reality, evidence/reference integrity, object-boundary coherence, and information economy. They are an ephemeral reasoning lens, not a checklist stored in the Kernel.

Persistent state is intentionally small: WorkObject/WorkIntent, normal Evidence and governed Formal Commit records, CurationReceipt, FeedbackEvent, and `governanceCorrelationId`. There is no GovernanceSession state machine, WorkingModel table, Claim DB, or QuestionQueue.

Authority is Option A from the Phase 7 Goal: stable WorkIntent changes are LOW-risk `AGENT` proposals bound to approved `work-intent-maintenance`, the originating read-only composite run, active provisional Taste, frozen Evidence, exact target version, and Graph projection. Current-focus changes use the existing `current-focus-maintenance` identity. A conversational answer is evidence available to the external Agent; it is not a trusted USER primitive and is never recorded as USER confirmation.

Continuous apply means the external Agent applies a stable local Proposal without a per-turn user Preview. Structural changes remain review-only. Final review is a short prose summary; audit identifiers stay available through CLI rather than appearing by default.

## Real Graph acceptance

The 2026-08-13 acceptance used Logseq Desktop 0.10.15, the real local Graph bridge, and one clearly synthetic Formal MiniProject. Raw Graph content, screenshots, descriptors, tokens, databases, and backups remain local and are not tracked.

The multi-round path was:

```text
title-only object
-> one completion-boundary question
-> free-form answer
-> UPDATE_WORK_INTENT Commit and Graph verification
-> fresh-context Agent SET_CURRENT_FOCUS Commit and Graph verification
-> typed ADD_REFERENCE with topology readback
-> SPLIT boundary candidate without execution
```

The first answer was treated as external Evidence, never as an authenticated USER command. The WorkIntent Proposal used `work-intent-maintenance`; the later focus Proposal used `current-focus-maintenance`; both retained the read-only composite run and Taste provenance. The natural reference created a `[资源]` heading and block reference only after a fresh root/topology check, then verified the resulting topology. Recovery was empty after all applies.

A separate existing natural MiniProject was read through the bounded Graph Gateway. Its sanitized shape already had one outcome, observable completion checks, and one actionable next step, so the correct result was no question, no Formalization, and no write. This proves the real-content trial can stop without turning historical Graph content into new Formal state.

The boundary case proposed keeping the current governance work and splitting an independently verifiable automation pipeline. It returned `BOUNDARY_REVIEW / SPLIT`, created no Proposal, and changed neither the object nor its history.

The final real-Graph run returned `NO_PROPOSAL / NO_CHANGE_NEEDED`: outcome, completion checks, and focus were coherent, and the already-raised boundary candidate had no new user decision. It created no Proposal or Commit. This is the healthy/no-question stop proof rather than another mutation.

The fresh-context Agent's actual light final review text was:

> 当前 MiniProject 已把“治理现有模板”确立为清晰、可推进的当前焦点，同时保留既有核心输出和完成标准；没有移动对象边界、归属、生命周期、历史或参考材料，也没有为了字段完整而增加承诺。现有证据已经足以支持这一步最小推进，因此当前阶段已足够好，无需继续追问或扩张治理范围。
