# Keep the Logseq SDK runtime pinned until an upgrade is materially safer

Task Copilot and the capability lab keep `@logseq/libs` 0.0.17 as a runtime dependency for the current Logseq 0.10.15 target. The registry-recommended 0.3.4 major is API-compatible after treating a nullable page Block tree as an explicit zero-write retry condition, but its published runtime still fixes DOMPurify 3.3.3 and lodash-es 4.17.23, both inside the current advisory ranges. A type-only dependency was rejected by a real Desktop reload: Logseq injects `__LSP__HOST__`, while the SDK runtime creates `window.logseq`; without that runtime the Plugin Frame does not load. We therefore do not claim the audit risk is fixed, do not add an SDK shim/fork, do not suppress npm audit, and do not force a major that preserves the reported risk. A future upgrade must pass the existing typecheck, 129-test plugin suite, build/bootstrap/dist checks and real Desktop load/API Gate, and must demonstrate materially safer published dependencies.
