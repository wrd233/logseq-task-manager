# Keep the Project current interface as one versioned object aggregate

Project Objectives, Deliverables, Work Stages, current summary, one to three current focuses, and optional primary-stage mappings are stored in one validated `objects.project_structure_json` aggregate. They change together through the existing Object version, Proposal review, Local Service Application command, SemanticCommit, and inverse Commit boundaries; stage edits never move child objects. Separate normalized tables were rejected because the current product queries read and replace this bounded Project-owned interface as a whole, while extra tables would add partial-update ordering and recovery surface without a proven query or E2E need.
