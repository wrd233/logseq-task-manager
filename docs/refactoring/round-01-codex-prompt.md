# 第一轮 Codex 提示词：行为保持的瘦身与边界整理

下面整段可以作为给另一位 Codex 的任务提示词。仓库为 `logseq-task-manager`；从该会话实际 checkout 开始，先检查 `AGENTS.md` 和工作区状态。

---

请直接完成本项目第一轮代码瘦身与重构，不要只提交审计报告或计划。本轮目标是：**减少有证据的重复和无效复杂度，解除明确耦合，澄清当前文档入口，同时保持现有用户行为与可靠性约束。** 暂不实现新的 Workspace、内容维护、问题聚焦、协作审阅或行动建议功能。

## 1. 阅读与事实基线

先阅读以下资料，并抽取与本轮有关的约束，不必通读全部历史材料：

1. 根 `README.md`、`package.json`、`docs/integration/README.md`、`docs/integration/VALIDATION.md`、`docs/architecture/target-package-map.md`。
2. `docs/requirements/2026-10-01-project-workspace-collaboration.md`：新需求方向。
3. `docs/architecture/2026-10-01-workspace-architecture-review.md`：源码分析与建议；可配合旁边的 PDF 阅读，MD 便于检索。
4. `docs/refactoring/README.md`：四轮边界、初步线索与删减标准。
5. `docs/vnext/README.md`，再针对性读取 05/06 的权限、正式事实和故障原则，以及 ADR 014、021、029、037、043。其他 ADR 只在判断具体行为时读取。
6. 阅读报告涉及的源码及调用方：Kernel、contracts、插件入口、任务控制器、工作视图、身份缓存、材料保存、边界检查和相关测试。

文档权威需要按范围理解：新需求决定演进方向，整合说明解释当前插件行为，正式治理规范约束现有正式状态与数据安全，历史阶段记录只在其适用范围内使用。报告中的“建议”不代表已实现；日期较新的文档也不自动覆盖所有旧约束。

检查当前 branch、未提交修改及 runtime。遵循仓库要求的 Node 20 与 npm，不通过升级依赖或重装全部工具解决无关问题；保留其他人的修改。在改动前运行必要基线检查，记录已存在的问题。

## 2. 必须落地的范围

**A. 收敛正式投影构造。** 核实 Kernel `projectionFor()` 与插件 `expectedProjection()` 的所有字段及 closure 转换。将同一份纯投影构造收敛到现有合适的共享模块，两端复用；不新建包，不引入 Node/SDK/数据库依赖到浏览器共享路径。保持 UUID、字段、空值/省略规则、canonicalization、hash 和公开协议完全兼容。特别注意无 closure 时不能因为新增 `closure: null` 改变旧 hash。异步读取 closure 的职责仍放在调用侧。通过真实协议样本与现有创建、更新、闭环、撤销路径验证兼容，不用只重复实现的测试证明实现。

**B. 解除工作视图对任务 UI 控制器的身份依赖。** 查清身份缓存的创建、更新、清空、失效和读取路径，把只读身份查询及其必要共享状态移到明确的共享模块，或通过窄接口注入；工作视图不再导入任务控制器。保持正式对象识别、Graph 切换及自然笔记 fallback 行为。本轮不提前重构整套 Graph Worker/Observer 生命周期，不改变 `tasksEnabled` 等功能开关的含义，不建立新的 DI 容器或全局事件总线。

**C. 执行经证明的冗余清理。** 扫描生产代码、构建脚本、导出声明、CLI/HTTP/全局入口、动态加载、测试及文档引用后，删除确无活跃用途的函数、类型、重复适配、过期兼容分支和对应孤立测试。重点核实 `agentContext`、`checkAgentPatch`、`continuingLayout`、`workspace/context.ts` 的孤立类型，以及重复纯逻辑；这些只是候选，不能因当前 grep 少就直接删除。若测试覆盖的是现有产品行为，要迁到实际入口；只有被明确移除的原型能力及其专属测试才一起删除。必要时保留并记录理由，不能为了代码量目标强行删减。

**D. 澄清文档状态并清理误导。** 修正 `docs/vnext/README.md` 中“01–04 已被替代”与后续“旧 01 是宪法”的矛盾。说明 `commit-state-machine.md` 的当前 formal 路径与 legacy 路径；在 ADR 003/042 等相关历史记录中标明替代关系或适用范围，不改写当时决定。使当前架构说明与本轮实际修改一致。重复解释尽量用链接收敛，历史验收证据保留。只在确认无唯一信息、无引用且不承担兼容/恢复说明时删除文档，并修复引用。

**E. 补上对应的边界约束。** 在现有检查工具中以 import 关系验证新增边界，至少覆盖 `.ts` 和 `.mjs`，使 work-view 再次依赖 task-center 控制器时会失败。采用小而明确的规则即可，不为这一轮搭建通用架构分析平台；已有负向边界检查继续有效。

## 3. 过度防御性编程如何处理

每一处拟删除的防御先回答：保护了什么失败场景？输入是否已在可信边界验证？中间是否有 `await`、外部写入或重入导致事实变化？是否承载兼容性、恢复或用户草稿保护？保留它的最低复杂度表达是什么？

可以删减或集中：可信内部对象被反复做 shape 检查；同一纯规则复制；无受支持调用方的兼容层；已验证不可达分支；静默吞掉必须反馈的业务失败；没有产品入口的原型 scaffolding。

**必须保留其行为：** HTTP/LLM/SDK/磁盘等外部边界校验，trusted user channel、证据 proof/hash、expected version 与拓扑校验，写前检查与读回核对，异步 epoch/generation、幂等、草稿/输入法保护、持久化作业恢复、事务、Undo、projection obligation、受支持数据库迁移。

不要批量删除 `if`、`catch`、optional chaining 或重复读取。一次 `await` 前后的检查可能保护不同瞬间；`PanelCoordinator` 把 tail 转回 resolved 可能是在保证失败后后续操作仍能执行；Graph 离线的 fallback 可能是在保护自然工作不被阻塞。先理解再改，允许提取清晰命名的规则，但不能让内部成功表象掩盖失败。

## 4. 本轮限制

- 不修改 schema，不改变既有数据格式，不重置真实 Graph/数据库/材料目录，不删除历史迁移、账本和证据。
- 不改变正式权限、任务状态语义、公开 API/CLI、视图布局到来源的边界和 feature enablement。
- 不整批删除 legacy 提交/恢复链。它与 formal 路径共享 `#prepare`；后续应在调用方、持久状态和恢复依赖迁移完成后再处理。
- 不替换数据库，不引入 Svelte/ProseMirror/CRDT/微服务，不为未来功能堆接口或空包，不做全仓格式化、机械改名和无关依赖升级。
- 不把 vendor JS、许可证、生成产物规则或 RC 故障证据误判成冗余；`requirements.html` 修改通过 JSON/template 和生成脚本完成。
- 没有重复数、行数下降或覆盖率的强制指标；评价依据是实际少了哪些重复职责和耦合，行为是否保持。

## 5. 验证、提交与交付

按阅读/基线、投影统一、身份解耦、冗余清理、文档与边界检查分步实施，每一步保持可审查，不停在等待我批准计划。使用现有相关测试；只对协议兼容、耦合边界、过期结果等重要行为补充必要测试。

结束前运行仓库完整 `npm run check`。根据受影响范围完成必要的 Graph/插件 smoke 验证；如果没有真实 Logseq 环境，明确哪些由自动化证明、哪些尚未验证，不伪造 UI 结论。失败要查明与基线的关系；不得删测试、关闭规则或修改预期来掩盖回归。

交付 `docs/refactoring/round-01-results.md`，保持简短可核查，包含：

1. 实际完成的改动和当前依赖图。
2. 删除/合并清单、生产调用证据、对应验证；少量检查保留的理由。
3. 文档状态和替代关系，剩余待核实项。
4. 真实检查结果、已存在失败和未验证的 UI 场景。
5. 第二轮建议及其明确边界；不自行开始第二轮。

为本轮生成独立、说明清楚的本地提交，检查最终 diff 不包含临时制品或个人状态。是否推送按该会话用户的指令执行。最终回复说明具体删掉/收敛了什么、为什么等价、验证结果和 commit。**不要把架构愿景的未来能力写成这轮已经实现，也不要只交付审计文档。**
